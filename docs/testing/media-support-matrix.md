## 1 已验证环境与范围

应用实际运行与安装基线为 Windows 11 x64 26100，笔记本和台式机已有记录；没有把 Windows 10、其他架构或未测试编码写成已兼容。Windows 屏幕/应用的采集范围另见对应记录，不由本媒体矩阵代替。

以下样本由已授权的私有 18 秒视频片段生成。开发用 FFmpeg 只负责准备输入；消费者使用正式 Application 导入任务、安装目录的 MediaTools::bundled、实际 FFmpeg/ffprobe 和本地 Whisper，PATH 只有 Windows 系统目录。样本不进入公开仓库。

## 2 视频与音频样本

| 文件后缀 | 实际容器 | 本轮视频/音频 | 结果 |
| --- | --- | --- | --- |
| MKV | Matroska | H.264 / AAC | 提取音频、本地转写 7 段 |
| MP4 | MP4 | H.264 / AAC | 提取音频、本地转写 7 段 |
| MOV | QuickTime | H.264 / AAC | 提取音频、本地转写 7 段 |
| M4V | MP4 型 M4V | H.264 / AAC | 提取音频、本地转写 7 段 |
| AVI | AVI | MPEG-4 Part 2 / PCM s16le | 转为应用音轨、本地转写 7 段 |
| WebM | WebM | VP9 / Opus | 转为应用音轨、本地转写 7 段 |

ffprobe 核对了实际容器与编码。M4V 这里是含音轨的 MP4 容器，不能据它宣称无音轨的原始视频码流可直接学习。六个文件均无文本字幕，自动进入本地转写；生成 20–23 个候选，实际时长 18.038–18.060 秒。编码、封装和识别差异导致文本/候选可能不同，需要确认纠错。

MP4 与 M4V 样本字节相同，正确复用一个来源，最终是 6 个文件、5 个唯一资料来源；这不属于漏导入。其他视频编码须按实际输入检测，不能把文件后缀当作全部编码的保证。

## 3 字幕与选择

已由[导入选择与查询](import-query-results.md)、[原型](prototype-results.md)和[桌面导入](desktop-import-results.md)实际覆盖：内嵌英语文本字幕、英语 PGS、空字幕回退、本地无字幕转写、多音轨/字幕显式选择，以及 UTF-8/带 BOM UTF-16 的外置 SRT、ASS、经典 SSA 和 WebVTT。错误选择明确失败，不静默切换；识别文字与时间可在收录前修订。

未验证的字幕格式或受保护素材不作兼容承诺。目录扫描支持的六个视频后缀不影响显式文件失败的单独报告。

## 4 目录扫描与路径去重

目录递归访问子目录，后缀大小写不敏感；不自动跟随目录符号链接。忽略普通 TXT 等非视频文件。用户显式指定的坏文件保留给逐文件处理，不让它从结果中消失。

本轮把 MOV/AVI/WebM 放入两层、含中文名称的子目录，将输入目录和同一 MP4 文件一起传入。原实现目录条目 canonicalize、显式文件不 canonicalize，在 Windows 下列出 7 个输入并返回重复资料。修正现有显式文件的路径身份后，正式扫描得到 6 个输入、导入完成项 6 个、失败 0 个，既有 5 个唯一来源没有增加。修正后的重放复用已解析资料，没有为了验证路径再运行无关识别。

新增回归覆盖绝对路径、含点路径、递归目录和同一文件合并；不存在的显式 MKV 仍单独保留。规范化失败的显式输入继续交由具体文件处理报告错误。

本轮 `cargo fmt --check` 与全目标 Clippy 通过；核心测试 64 项通过、0 失败、3 项显式忽略。实际目录重放结果单独记录，不以单元测试代替媒体处理证据。

私有 JSON 在 `.tools/format-matrix-validation/verification.json` 和 `verification-fixed.json`。`import_matrix_probe` 是正式任务的集成入口；输入准备与截图/模型权重均未作为代码提交。
