## 1 原因与实际证据

用户看到的当次任务有 6 项词义、2 项句子译文，最终处理 8/8，但 7 项无效；所谓成功的一项将 OCR 伪词 lalk 的“无此单词”存成了中文词义。任务会结束，之后再次启动仍会准备缺失项，因此呈现为反复处理同一批内容。不是单个 HTTP 一直不返回，也不是本机模型服务整体不可用。

本轮读取任务和 SQLite，重现实际请求，并从保留的原始 PGS 解码相关图像逐项核对。实际响应为 HTTP 200、合法 JSON、finish_reason=stop，排除本次响应截断或服务连接错误。

| 原因 | 核对结果 | 修复 |
| --- | --- | --- |
| OCR 错字／音符变成词 | tolot 实为 idiot，lalk 实为 talk，Yamos 实为 Vamos；歌词粘连、音符及其他错字也产生伪词 | 依据原图修订原句和候选，保留原始 SUP 及时间；不设黑名单、掌握或跳过 |
| 缩写结果缺中文 | how’d 返回 how did，what'd 返回 what would，不能作为中文词义；后者还与本次原句不符 | 已核对的补充词库保留 did／had／would 的常见展开及中文，通用词义不任选一种 |
| 字母歌无中文结果 | 两段字母序列被模型照抄，随后未通过中文校验 | 明确要求中文说明唱字母并保留正确字母序列，真实 Qwen 请求及保存通过 |
| 断词和外语 | 重音字符被截断，hi-larious 的后半部分被当作独立词 | 保留完整拉丁字母；底库确认合并拼写后整理为完整词键，原文和字符范围保留 |
| 缺失大小写和跨字幕线索 | 孤立小写词不足以判断姓氏、品牌、外语和临时构词；人名后的下一条字幕才交代人物类别 | 保留原始大小写，附一处出现和前后有限字幕，仍按词共享缓存 |
| 字段放错 | Elunga 的 meaning 为空，但 notes 明确说明其为人名 | 仅对明确无歧义的备注类别整理人名词义，保留原拼写，不编造标准音译 |
| 模型判断仍可能错误 | Woosnum 在原图确为姓氏，模型仍给疑似拼写判断；Sellecks 曾生成错误的语境解释 | 姓氏经原图核对加入补充词库；构词用法依据原字幕及视频画面人工订正并注明来源，不把含中文等同于语义正确 |
| 旧校验错误 | 旧缓存共有 17 个不同目标以“无此单词”类诊断充当释义，其中也包括可由底库解释的词 | 诊断不再命中有效缓存或阻止排队；有效结果仅修复无效自动缓存，不覆盖个人词义或学习记录 |

## 2 当前资料修复及正常流程

修改前使用 SQLite 在线备份 API 在资料目录的 backups 保存一致备份；原始诊断响应、字幕图、修订清单、旧自动缓存和任务结果只保存在本机私有证据中，不提交影视素材或个人数据库。

1. 通过既有带 revision 的 `update_source_example` 修订 14 处已核对文字，另对 1 处保持原文重新整理分音节候选，共 15 处；时间范围保持。
2. 修复或补存 6 项底库释义。余下实际准备项为 8 个词义、14 个句子译文，共 22 项。
3. 初次补齐产生 18 项结果，4 项仍无效；补上相邻字幕后，2 项继续取得结果，但剩下人名仍未全部解决。因此没有以第一次任务结束为通过，也没有隐藏失败。
4. 读取剩余模型原始响应后修正明确的人名字段整理；Woosnum 依据原图补充，不采纳模型的疑似拼写猜测。另对照原视频纠正 Sellecks 的错误语境义。
5. 最后实际任务完成 1/1，generated=1、failed=0、skipped=0；原生 `explanation_work(None)` 返回 **0 项**。累计补存 14 个句子译文及 7 个模型词义，其中上述构词语境由原素材人工订正；另一项由补充词库解决。
6. 数据核对确认当前候选没有引用“无此单词”类诊断。个人词义、收录关联、学习／测验／水平测试和原声资产表与备份逐行相同；15 处修订的文本、revision+1 和时间范围与清单一致。旧任务和不再被当前候选引用的诊断缓存保留追溯。

新代码仍保留未知项目的未完成原因和有限补试；本轮没有增加永久忽略、默认跳过或假定未知单词均为专名的规则。
