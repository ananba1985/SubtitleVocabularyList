## 1 范围与现有限制

本轮评估既有资料的实际大小，补充可重复执行的只读诊断及同步前的容量提示，不截断例句、原声、作答、修正或旧报告。差量传输和检查点减少网络、处理与存储重复，但完整逻辑资料仍有上限：

| 对象 | 当前预算 | 说明 |
| --- | --- | --- |
| 完整请求或分片传输内容 | 8,388,608 字节（8 MiB） | 分片为 500,000 字节，不因分片或差量编码而取消完整请求限制 |
| 完整业务快照 | 8,384,512 字节 | 从上述预算预留 4,096 字节给信封，与现有站点一致 |
| 单个原声音频 | 20,971,520 字节（20 MiB） | 原声独立传输、按摘要复用，不嵌入资料 JSON |
| 不支持分片的站点发送请求 | 996,000 字节 | 沿用原保守阈值，不能声明为 8 MiB |

桌面预算集中在 `src-tauri/src/sync_limits.rs`；脚本读取同一常量定义，不手工复制另一套数值。站点仍为已部署的版本 31，本轮不修改服务端协议或上限。

## 2 只读诊断用法与口径

退出应用后，使用已完成 SQLite 检查点的 Data 目录或其静态副本。需要 Python 3.9 及以上，仅使用标准库。输出应放在被检查目录之外的私有位置，例如：

```powershell
python -X utf8 scripts/sync-capacity-report.py --data-dir D:\Private\ClosedData --output .local\sync-capacity\report.json
```

数据库以 `mode=ro&immutable=1` 打开，不迁移、不冻结、不导出新的完整资料，不读凭据或请求网络，也不创建 WAL／SHM 访问文件。输入必须保持关闭、静态且已检查点；发现非空 WAL 时拒绝继续，不能用此工具检查正在写入的日常库。原声只读取受管文件的大小，不读取或计算音频内容摘要。

报告统计所有本地账号范围的已确认快照、已冻结待发请求、完整历史行数及持久原声文件的数量、总字节和最大单项字节。输出不含题目、回答、账号标识或路径正文。最大单项与其预算比较；总字节是本地合计，不受单包上限直接限制。80% 仅是提示进一步调查的工程参考，不是已经测出的性能拐点。

尚未冻结的修改不会重新投影，因此诊断不能证明全部当前业务资料均在上限内。某类没有记录时显示 `not_sampled`，不能解释为该类完整包大小为零。此工具不预测还可使用多少年，也不证明无限容量。

## 4 提前核对与最小验证

词条和测试会话在冻结时复用已有一次完整 JSON 编码的 UTF-8 长度，扣除少量信封元数据后同时核对完整快照预算；不为检查再编码整包，不增加事务。词条在写入冻结队列、开始该包原声传输之前发现超限；测试会话在保存冻结请求前发现超限，已按业务规则保存的报告仍保留。发送前也核对完整请求，避免差量很小却掩盖逻辑快照超限。音频及不支持分片的实际发送阈值均显示实际字节和对应上限。

超限时返回 `capacity_exceeded`，提示完整本地资料保留，不要求用户删除历史。入站差量还原后的完整快照与站点使用相同预算，保留原完整校验、游标及提交规则。schema、DTO 和网络字段不变。

## 5 评估结论与后续触发条件

OPT-12 的本轮容量评估、可执行诊断和提前检查完成。已知样本暂未显示接近上限，当前不增加新的历史分页协议；此结论不消除现有 8 MiB／20 MiB 限制，也不宣称已经实现传输历史分页或无限历史容量。

实际账号的代表性资料接近诊断参考值、出现容量错误，或出现明确的增长需求时，应再设计带版本协商的历史分页：不可变事件／页面、确认游标与回执、旧报告及原声引用均需完整保留，并明确旧设备恢复方式。这里是条件性后续设计方向，尚未实施或验收；不能以截断、删除历史或单纯调大常量代替。
