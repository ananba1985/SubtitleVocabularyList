## 2 桌面账号连接

桌面生成高熵同步令牌，把 SHA256 摘要与请求 UUID、设备显示名发送到 `/api/desktop/requests`。站点生成十分钟有效的连接请求和核对码；摘要只能建立待授权状态，不能自填用户身份。桌面持有原始令牌，以 Bearer 方式轮询同一请求。令牌不进入 URL、日志、词库、公开源码或前端响应。

用户在系统浏览器打开同一站点的 `/desktop-connect?request=...`，按平台流程真实登录 ChatGPT，核对设备名与桌面显示码，明确批准这台设备交换个人词库、例句、原声和学习记录。批准接口必须具有平台用户身份且同源 Origin；站点把请求绑定到该真实用户。未批准、过期、拒绝或撤销均不能访问个人数据。平台站点访问服务凭据不提供用户身份，不能替代该连接流程。

批准的设备令牌初始有效期为 90 天，可从同一站点撤销。桌面凭据使用 Windows 当前用户的受保护存储，与词库可同步内容分开。离线模式不发起连接、查询或同步，已保存内容继续学习。

当前实现使用 Windows 当前用户 DPAPI，密文按站点 origin 摘要保存到数据目录的独立 `credentials` 子目录，不进入词库或同步资料。Tauri 状态只返回请求标识、设备、连接码和账号范围，不返回令牌。HTTP 客户端不跟随重定向，凭据不发送到不同 origin。失去响应后可用已保存的同一请求重试；较旧的异步结果不能覆盖新连接请求。真实用户尚未批准的连接只能显示 pending，不能据平台所有者权限自动构造身份。

已实现路由为 `/api/desktop/requests`、`/api/desktop/requests/:id`、`/api/desktop/requests/:id/approve`、`/api/desktop/status`、`/api/desktop/connections` 及撤销入口。本站的真实匿名检查确认首页和连接页为 200，个人词库和连接管理为 401；这些证据不代表批准后的真实用户数据交换已经通过。

## 3 数据协议

采用版本化 JSON 词条资料包，保留关联实体的稳定标识。一个资料包包含该词条的完整相关记录，原声字节单独传输。资料包覆盖以下实体，与 SQLite 相同的关系规则对齐：

| 部分 | 数据与约束 |
| --- | --- |
| entry | 类型、原文、匹配键、修订与创建时间；不同类型和显式分开的含义不盲目合并 |
| meanings | 所有释义与原始标识、来源及修订 |
| sources / examples / entryExamples | 已收录例句所需来源、原句、位置、时间、语境释义及关联；不包含素材路径或未收录对白 |
| media / exampleMedia | 原声摘要、格式、时长、资料标识及对应例句；无本机路径 |
| collectionActions | 原明确收录事件与发生时间；拉取或重放不产生新的主动行为 |
| units / attempts / corrections | 独立维度、范围、原回答、提示、答案依据、原判分、修正及策略版本；历史不可静默覆写 |
| states | 当前安排与策略状态；应用学习事件后重算核对，不能靠远端状态清空本地历史 |

当前共享契约位于 `protocol/svl-sync-1.json`：外层为 schemaVersion、deleted、entry、tables，关联字段沿用 SQLite 的 snake_case，覆盖 12 类实体。两端逐项检查字段和关系，禁止漏段或带入运行时路径。资料包与媒体容量见第 5 节；超限返回失败而不删字段，接近边界的实际样本仍需验证。

## 4 变更、幂等与冲突

以下队列、应用与冲突流程已由桌面和站点实现，服务端基准版本、回执、事务及历史保留通过本地契约检查。真实通过范围与余项见第 6 节。

本地业务修改和待同步事件在同一事务保存。每次待推送资料包有稳定 changeId、摘要、远端基准版本；回执丢失后保持同一内容重试。站点按真实用户、changeId 去重，同一标识的不同内容返回冲突。远端资料包修订使用基准版本条件更新，变更与回执通过 D1 batch 原子提交，不依赖先读后写的客户端时间覆盖。

`/api/svl/v1/changes` 按账号范围的稳定游标返回增量和实体版本。桌面只有在内容、原声和映射已持久化后推进游标；中途失败仍可重放。站点已有词库逐用户建立稳定映射和完整资料包，既有词条不会在每次拉取时生成新标识。旧接口的新收录、修改与移除也需要进入变更流。

两端修改同一资料包时，保存远端和本地版本并显示差异。追加的不同例句、原声和学习事件按稳定标识、来源位置及摘要合并；同一字段的不同修改、身份映射歧义或同一不可变事件的不同内容要求明确处理。合并结果作为新的修改提交，保留判分和修正历史。原声不可用不伪称完整同步成功。

网站移除保存完整 tombstone，不能静默删除桌面的例句、原声或学习记录。桌面保留待确认版本，由用户选择归档或恢复；此规则不引入新的备份导出功能。

### 4.1 笔记本同步实现

schema 5 新增业务变更标记、按站点 origin 与真实账号组合键隔离的资料包基准、冻结发送队列和冲突。收录、编辑、作答、人工修正及已收录来源归档与变更标记在同一事务提交；准备发送时按账号基准产生稳定 changeId 与完整快照。已发送请求失去回执时，先重试同一内容，再发送期间新增的修改。

拉取使用实体别名映射，覆盖关联外键、含 `:ctx:` 的语境键、题目及收录结果内的实体引用。来源、同句、同释义、学习范围和相同原声复用已有实体；不调用收录命令来导入历史，因此不产生额外主动收录。原声摘要通过后持久化，结构与映射通过事务保存，之后推进游标。失败保留原游标；已保存资料再次重放不会增加计数。

按最近共同资料包执行字段与新增实体合并。原收录、回答与修正不可覆盖；独立新增内容保留，两端同时改写的文字要求选择。复习状态按原事件重算；未发生本地业务修改时，不把重算导致的投影版本变化再回推成新学习事件。同形词匹配要求用户选择合并或独立保存，未选择前不自动发布重复词条。

网站移除采用保留完整资料的 tombstone。桌面收到移除后必须明确选择归档或恢复；归档仅从词库与复习列表隐藏，不删除释义、例句、原声或学习历史。网络失败、取消和冲突不宣称完整同步成功。

桌面增加 sync_start、sync_status、sync_conflicts、sync_resolve。处理请求含展示时的远端版本、当前本地版本及目标版本，变化时要求刷新。凭据不进入状态或前端；网络不跟随重定向，连接或离线设置变化时停止继续交换。站点同 changeId 的并发请求需在 D1 同一事务内占用回执，再按请求摘要和词条标识写入，避免“末端返回冲突但已产生另一条记录”的竞态。

网页旧词库接口改为读取完整资料包；旧表保留作迁移来源。新收录、追加语境、释义纠正、移除、原声关联和人工学习结果修正均进入同一资料包变更流。界面显示全部释义、例句、原声和历史；版本冲突保留输入并要求重新打开。

## 5 原声与授权隔离

使用 Sites 托管 R2 保存原声，D1 保存媒体归属和元数据。上传与下载均核对已批准的账号或真实浏览器登录，对象键按账号范围及内容摘要构建。上传校验字节摘要、长度和类型；重复上传复用同一资料，未完成媒体不能作为资料包成功引用。下载保存到应用管理媒体目录，再按既有摘要与文件规则核对。

单个账号的游标、映射、回执和媒体不得跨账号复用。切换连接不会把已知游标当作新账号已经处理；每个账号保留其同步状态，本地核心不要求在线身份。

服务端单请求上限为 1,000,000 字节，单个资料包预留响应封装空间后为 996,904 字节；桌面发送使用 996,000 字节的保守上限。原声单文件上限 20 MiB，超过边界时显式失败并保留完整本地资料，不截断历史。JSON 快照字符串长度按 JavaScript UTF-16 单元限制对齐。一次拉取达到批次上限时保存游标并返回尚未完成，不能显示全部成功。大词条长期历史的分页传输仍是容量余项。
