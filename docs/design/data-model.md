本模型将词条、语境、原声、主动收录和测验历史分别保存，支持多来源追加与重试去重。以下实体和约束是详细设计提案，实际表结构、索引和迁移在实施阶段形成并验证。

## 1 基础约定

| 内容 | 提议规则 |
| --- | --- |
| 标识 | 持久化实体采用应用生成的稳定 UUID；同步保留原标识或建立明确映射 |
| 文本 | 保留用户确认的原始文本；辅助规范键只用于查找候选匹配 |
| 类型 | 词条类型为 `word`、`phrase`、`sentence` |
| 时间 | 记录时间使用 UTC；对白位置用整数毫秒，采用起点包含、终点不包含的区间 |
| 版本 | 可编辑实体具有递增 `revision`，用于检测读后修改期间的冲突 |
| 去重 | 操作去重与内容去重分别处理；词条规范键不作为无条件唯一键 |

规范化提议包括 Unicode 规范化、边界空白清理和辅助大小写匹配。词形归并、缩写和同形异义判断属于候选匹配策略，保留原文且允许用户选定已有词条或另建词条。

## 2 词条与素材实体

| 实体 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `entries` 词条 | `id`、`kind`、`text`、`match_key`、`revision`、创建与更新时间 | 主键为 `id`；按类型和匹配键查找，允许用户保留不同含义或大小写对应的独立词条 |
| `meanings` 释义 | `id`、`entry_id`、释义文本、来源类型、`revision` | 属于一个词条；新增语境不能自动覆写已有释义 |
| `sources` 来源 | `id`、来源类型、显示名称、素材识别信息、可选原路径与时长 | 原路径为定位提示，移动原文件不使已收录资料失效 |
| `examples` 例句 | `id`、可空来源、位置键、原句、可选起止毫秒、修订信息 | 同一来源片段可被多个词条引用；没有自动来源时仍可保存用户补充句子 |
| `entry_examples` 词条例句关系 | `entry_id`、`example_id`、可选 `meaning_id`、本次语境释义 | 词条与例句组合唯一；引用释义时必须属于同一词条 |
| `occurrences` 来源出现 | `id`、`source_id`、位置键、候选匹配键、原始词形、可空 `entry_id` | 按来源、词或短语跨度及候选键去重；确认匹配后关联词条 |
| `candidate_decisions` 预习判断 | 来源、候选键、当前语境范围键、判断状态、更新时间 | 保存用户确认的出现位置或语境范围，不代表其他语境或全局掌握状态 |

例句重复判断以来源与片段位置为主，并核对原句。相同句子来自另一集时仍保留另一条来源；同一来源的两个不同出现位置也保留。对来源不完整的输入，重复判断结果供用户确认。

字幕修订会更新已有片段或显式建立新版本，不能因为文本变化就把同一片段当成一次新的主动收录。一个片段内同一词多次出现时，用词或短语跨度区分出现记录，避免用例句数量代替出现次数。

## 3 原声实体与文件

| 实体 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `media_assets` 音频资料 | `id`、来源片段与处理配置键、内容摘要、相对路径、音频类型、格式、时长、状态 | 已保存原声的状态为 `ready`；文件不可用时明确标记异常，不返回可播放的成功结果 |
| `example_media` 例句音频关系 | `example_id`、`asset_id`、来源位置 | 组合唯一；同一音频可被多个词条例句引用 |

系统语音兜底使用已安装的 Windows 英语语音即时朗读，并标识为 `system_tts`。0.1 不要求把每次合成结果保存为文件；已经保存的来源对白标识为 `original`。

音频目录由应用管理，数据库仅存相对定位和元数据。素材路径、来源和内容摘要具有不同用途：路径用于查找原文件，来源用于追溯，音频摘要用于重复文件识别。

准备音频前按来源片段及处理配置查找已保存且可用的资料，再核对内容；找到时直接复用，避免同一片段被反复编码产生重复副本。输入来源不同的相同音频也可按实际内容摘要复用，来源关系仍分别保留。

### 3.1 保存与中断恢复

1. 在本次操作的临时位置生成音频，核对可解码性与目标片段。
2. 将完整文件放入正式媒体目录；目标重复文件经核对后复用。
3. 在数据库事务中写入词条关系、例句、媒体引用及主动收录记录。
4. 事务提交后返回完整结果，并清理本次临时文件。

文件系统与数据库不组成一个原子事务。数据库回滚后留下的未引用文件按来源和引用情况清理；清理不能删除被其他例句引用的音频。重试使用同一操作标识查找已提交结果，恢复过程不重复计数。

存在来源音频但保存失败时，保留收录草稿供重试。若用户明确选择先收录文字，则记录无已保存原声的事实，之后补齐音频；不得静默把失败降为完整成功。

## 4 主动收录与幂等记录

`collection_actions` 记录 `operation_id`、请求摘要、词条、来源、行为类型、已提交结果和发生时间。`operation_id` 唯一，结果可用于同一操作的重试返回。

| 输入行为 | 处理规则 |
| --- | --- |
| 第一次明确确认收录 | 产生一次主动收录记录，保存或追加相关内容 |
| 同一确认操作重复提交 | 相同操作标识与请求摘要返回原结果，不增加次数 |
| 同一操作标识对应不同请求 | 返回冲突，要求新的操作标识或重新确认 |
| 用户之后再次明确收录 | 生成新操作标识；内容可能复用，但新增主动收录记录 |
| 导入解析或任务重试 | 更新来源与候选，不能冒充用户主动收录 |
| 同步拉取或重放 | 合并内容，保留既有行为来源；不能产生新的本地主动收录记录 |

影片来源出现次数从 `occurrences` 取得；划词与 OCR 的已知位置按已确认的来源和位置关联去重计算，不推断原窗口全文的词频。主动收录次数从已提交的用户行为取得。累计次数作为查询结果计算，避免把两个概念合并成一个计数字段。

采集片段再次确认时，如果原句相同则复用；用户修订原句时保留不同文字版本。当前使用位置键的 quote 后缀保存修订文字标识，出现计数归并回原位置，不因纠错虚增。系统语音是可重建缓存，不进入 original 类型的 media_assets 或原声同步关联。

## 5 学习与测验实体

| 实体 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `learning_units` 学习单元 | `id`、`entry_id`、释义范围键、能力维度 | 按词条、明确范围键和维度唯一；范围键非空，避免可空字段破坏唯一约束 |
| `review_attempts` 作答记录 | `id`、唯一提交操作标识、单元、题目快照、回答、提示、结果、判分来源、策略版本、调度前状态、时间 | 作答后保留题目与答案依据；播放次数不能自动变成正确结果 |
| `review_corrections` 判分修正 | `id`、原作答标识、前次结果版本、新结果、理由、时间 | 保留修正关系，重试同一修正不再次影响复习状态 |
| `review_states` 复习状态 | 单元标识、状态版本、算法标识与版本、算法状态、下一次时间 | 是有效测验结果的当前投影；与影响它的作答或修正一并提交 |

维度提议为词义 `meaning` 和听力 `listening`。短语用法困难可记录为专项原因及题目类型；是否单独形成调度维度属于 OPEN-03，本文不新增第三种必需复习维度。

自由浏览和预习熟悉判断不写入测验正确记录。已掌握词条再次主动收录时保留历史，并给相关学习单元设置重新复习的优先状态；具体下一次日期由复习策略决定。

判分修正后，应重新计算受影响单元的当前状态。如果后面已有新的测验，则从受影响作答前的状态边界，按有序记录及各次适用策略版本重算，不能只覆盖最后一次日期或静默改用当前参数。未改变的其他单元不受影响。

## 6 任务与同步实体

| 实体 | 主要字段 | 设计边界 |
| --- | --- | --- |
| `tasks` 任务 | `id`、启动操作标识、输入来源、类型、阶段、状态、进度、结果引用、错误、取消请求 | 导入按素材保存阶段；恢复策略与引擎配合验证 |
| `sync_outbox` 待同步修改 | 变更标识、实体类型与标识、基准版本、变更内容、状态 | 与对应本地数据提交关联；字段范围必须受最终同步契约限制 |
| `sync_links` 远端映射 | 站点账号范围、远端标识、本地实体标识 | 将旧站点词键映射到本地稳定标识，避免重复拉取建立新词条 |
| `sync_state` 同步状态 | 账号范围、已确认游标、成功时间、冲突与失败概要 | 未应用的远端修改不能被当作游标已处理 |

账号范围是已有站点认证与数据隔离所需的信息，不引入多用户协作功能。原声和学习记录已确认纳入 0.1 同步，必须保留实体标识与关联；实际传输协议、首次对齐及删除传播规则仍需按 OPEN-04 对齐。

任务执行标识与业务操作标识分别保存。同一业务操作失败后可建立新的执行尝试，但同一时刻只允许一个有效执行；已提交结果仍按业务操作标识去重，不能因重试任务换了标识而再次收录。

## 7 数据库实现约束

- 在数据库连接初始化时明确启用并检查外键；关系约束不能仅依靠界面校验。[SQLite 外键说明](https://www.sqlite.org/foreignkeys.html)
- 对唯一约束使用非空业务键；可空字段不能直接承担需要全局唯一的组合身份。[SQLite 建表说明](https://www.sqlite.org/lang_createtable.html)
- 按词条匹配、来源片段、到期学习单元、任务状态和待同步状态建立必要索引，先验证实际查询再扩展。
- 原声与关联写入、收录记录与次数、作答与复习状态分别采用一致的事务边界。
- 凭据与访问令牌不进入可同步的词库内容，具体本地凭据管理由同步适配设计确定。
- 数据迁移按版本执行并验证。0.1 不以新增用户可见备份导出功能替代迁移完整性要求。

## 8 数据验证与待完善内容

模型验证应覆盖重复提交、新来源追加、无来源收录、多词共用对白、图片或音频失败、判分修正以及同步重放，执行依据见 [测试计划](../testing/test-plan.md)。

迁移已保存于 `src-tauri/migrations`，当前 schema 为 2。002 增加导入语料与音频缓存位置、候选类型、例句归档标识，以及同业务操作只允许一个有效执行的任务约束。已验证从 schema 1 升级保留词库，拒绝较新数据库降级打开。

词条匹配提供候选与显式新建或合并，重试按操作标识去重。修订已收录的来源对白时，先归档旧文字、时间和原声引用，再修改预习对白并重建候选；已收录资料保持原始关联。媒体使用内容摘要命名和配方键复用，保存与播放检查状态和文件摘要。实际验证见[桌面记录](../testing/desktop-import-results.md)。调度状态与同步队列的业务写入仍待后续实施。
