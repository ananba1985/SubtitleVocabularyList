## 1 目标与范围

用户希望用 SubtitleVocabularyList 替代本机 Pot。此增量补齐独立翻译小窗、划词／OCR 自动翻译、剪贴板监听、多服务查询和插件扩展。查词可以独立完成，只有用户明确收录时才进入原有词条、例句、原声合并流程。

现有取词、OCR、Qwen 解释、Windows 英语语音、词库、原声和托盘继续复用。默认快捷键沿用 Alt+C、Alt+E、Alt+D；自定义键和全局已掌握筛选保持。本设计不改变主窗口默认完全退出的规则，用户选择常驻时才在关闭主窗口后保持服务。

用户已授权执行本计划。独立窗口、监听、服务配置和声明式插件首版已实现；下文保留初始设计说明，实际参数与已覆盖边界以本节补充及验证记录为准。Pot 的 [使用指南](https://pot-app.com/docs/) 和 [快捷键说明](https://pot-app.com/docs/config/hotkey.html) 用于使用方式对照；不承诺现有 Pot 插件直接兼容。

## 2 功能与交互设计

### 2.1 FR-14 独立翻译小窗

小窗与主窗口、收录确认窗口分别管理。只查词时不打开主窗口，也不增加词条或学习记录。

| 元素 | 默认行为 |
| --- | --- |
| 原文输入 | Alt+D 打开后获得焦点；已有查询时可修改，Enter 查询，Shift+Enter 换行；输入法组合中的 Enter 不提交 |
| 查询方式 | 默认自动识别中英方向及词语／段落，亦可显式选择英文词义解释／整段翻译；手动、划词、截图和剪贴板共用核心判断 |
| 结果区 | 英文词语显示中文词义、原句译文与用法，英文句子显示中文译文；中文词语和句子显示英文译文；原文始终可核对 |
| 主要操作 | 查询／取消、朗读／停止、复制译文、收录；收录前继续核对类型、例句和合并目标 |
| 服务与选项 | 默认服务的结果优先显示，其他服务按需展开；服务配置与剪贴板开关收起，避免占据主要阅读区域 |
| 窗口关闭 | Esc 或关闭按钮隐藏小窗并取消本窗查询、停止播放；不等同于完全退出应用 |
| 窗口固定 | 提供固定开关；未固定时允许失焦隐藏，正在编辑或确认收录时不擅自丢弃草稿 |

首版尺寸采用 420×320 逻辑像素，允许调整；实际尺寸和位置受当前显示器工作区限制，靠近取词位置且不超出可见区域。已核对本机默认窗口，不表示各屏幕均已验证。多屏移除后重新计算可见位置。

复制译文是显式操作，不自动改写剪贴板。选择“收录”时以当前选择的完整服务结果准备草稿；取消收录不产生词条。已存在未保存的收录草稿时，沿用现有排队和确认规则，不覆盖旧草稿。

### 2.2 FR-15 划词／截图自动翻译

| 入口 | 处理顺序 |
| --- | --- |
| Alt+C | 保持原应用前台，读取并核对本次选区和可取得语境，再显示小窗、读缓存并查询缺失解释 |
| Alt+E | 先截取原桌面、显示选区，完成 OCR 后显示可编辑原文并自动查询；取消选区不查询 |
| Alt+D | 打开小窗输入原文；Enter 发起查询，不把每个键入字符都送往服务 |
| 托盘菜单 | 输入翻译与截图翻译进入同一会话流程，左键恢复主窗口、右键菜单习惯保持 |

自动查询默认只调用本机模型。模型不可用时小窗仍展示原文、已保存结果和重试操作，不自动转向外网。显式启用某个外部服务的自动查询后，才允许按其已声明的数据范围发送请求。

单词使用 explain 模式，包含目标与完整原句；OCR 的整段文字使用 translate 模式，不把第一行或第一个词冒充完整输入。修订 OCR 文字后由用户再次查询。沿用现有 4,000 字符目标和 20,000 字符语境上限；超限要求缩短或明确拆分，不静默截断。

自动采集沿用全局已掌握跳过规则；整句含有熟词不等于整句已掌握。用户主动在输入窗口查询已掌握词仍可得到结果，不改变掌握、主动收录次数或测验成绩。

### 2.3 FR-16 剪贴板监听

监听默认为关闭，由小窗或托盘中的“监听剪贴板”开关显式开启。状态在小窗和托盘可查看，不在词库、测验等页面展示全局横幅。应用重启后恢复为关闭，避免悄悄延续监听。

原生监听只读取新的纯文本变化；不在启动时翻译旧剪贴板，不读取文件、图像或富文本附件。暂定 300 ms 合并间隔，将连续复制合并为最新一次查询，空白、超限和相同规范化文本不重复发送。本间隔是可调整的初始参数。

默认每次替换小窗的当前查询，不自动拼接成长篇翻译。自己执行“复制译文”时标记相应剪贴板序号，避免把译文再次作为新输入。关闭监听立即停止接受新复制，取消该监听来源的待发及在途查询；关闭小窗只取消当前查询，显式开启的监听可在常驻期间继续，托盘保持开启标识。

查询成功结果默认可保存为本机查询缓存，不创建剪贴板流水历史、词条或同步变更；设置中允许关闭监听结果的持久化。开启监听时说明纯文本会被用于所选自动服务及本地缓存。被占用而读取失败时不使用旧文本冒充本次结果。

### 2.4 FR-17 多服务查询

先把现有 Qwen、词典查询和在线翻译整理成内置适配器，再增加用户配置的服务。用户可设置启用、默认、顺序和是否允许自动查询。

| 服务属性 | 初始设计 |
| --- | --- |
| capability | translation、dictionary；现有 OCR／speech 继续通过各自适配器工作 |
| networkScope | loopback 或 external；本地模式保持可离线，外部服务由明确查询或启用设置触发 |
| 查询输入 | 目标文字、源／目标语言；只有声明需要语境且用户允许的服务才收到原句；不发送截图、词库或历史 |
| 查询结果 | 服务标识、词义／译文、可选用法／读音、缓存来源、状态与错误；每个服务独立完成并显示 |
| 并发 | 本机模型遵守已保存的并发上限；外部服务按各自配置限制，不套用模型合批量 |

快的服务先显示，不等待所有结果；一个服务失败不清空其他有效结果。用户选择某个完整结果再收录；多个服务产生不同释义时不静默覆盖已确认词义。已有解释直接可用，模型或服务离线不使窗口重开后空白。

配置外部服务时展示地址及发送范围，凭据在本机受保护保存，不进入公开文件、日志或查询事件。外部自动查询默认关闭；手动离线设置优先禁止全部外网服务，不禁止回环模型。服务不可用时不自动新增提供商或上传更多资料。

### 2.5 FR-18 插件扩展

插件采用版本化能力接口，内置服务也遵循相同输入／输出模型。首批实现翻译和词典扩展；OCR、语音扩展沿用能力分类，另行安排，不以声明能力替代实际实现。

首版插件使用单个 JSON 配置文件，包含 manifest、HTTP 请求模板及 JSON Pointer 响应字段映射。主程序负责执行请求、凭据引用、响应校验、超时和取消，不在首批运行任意 JavaScript、DLL 或外部程序。

manifest 至少包含 id、name、version、protocolVersion、minHostVersion、license、capabilities、allowedHosts 和配置字段定义。安装前显示提供者、能力和访问地址；启用、禁用、升级与卸载都通过服务设置执行。导入只允许规定的包内相对路径，配置不携带真实凭据。首版使用项目 JSON 规范，不执行 .potext，也不解析包内图标或脚本。

禁用或卸载后不再分派新请求，在途请求取消或按已定义收尾结束；已有词条、原声和有效查询缓存保留，结果仍标记原服务。无法支持的协议版本或能力明确显示为不可用，不伪装成安装成功即可使用。

现有 Pot 插件的迁移先核对接口、许可和运行依赖，再选择重写适配器或薄兼容层。是否支持某个具体插件属于后续决策，不承诺完整兼容，也不建设插件市场。

## 3 运行结构与职责

| 模块 | 后续职责 | 复用基础 |
| --- | --- | --- |
| ARC-01 | 独立查询小窗、服务结果、显式收录和偏好入口 | React／Tauri 多窗口、现有收录确认 |
| ARC-02 | 保留原窗口取词，截图和剪贴板文本输入 | NativeDesktop、UI Automation、现有 OCR |
| ARC-09 | 查询会话、请求版本、交互优先调度、服务注册和插件配置解析 | 现有 Application、ModelGate、取消机制 |
| ARC-06 | 模型、查询、语音适配器 | model_content、OnlineLookup、Windows TTS |
| ARC-07 | 查询缓存、服务偏好和凭据引用 | SQLite、settings、现有解释持久化 |
| ARC-04 | 用户确认后统一收录及合并 | collection_prepare／commit、来源例句与原声关联 |

拟按 native capture → QuerySession → 缓存／ProviderRegistry → QueryResult → 小窗展示组织执行；点击收录后再进入 ARC-04。首版由 queries.rs、providers.rs、desktop_query.rs 和 QueryView 实现；窗口创建在独立线程完成，避免 Windows 同步命令／事件处理中的 WebView 挂起。

主窗口未打开也能查词。窗口事件只用于通知，窗口重新显示后查询会话快照，不依赖曾收到的事件恢复结果。小窗关闭后仍保存有效缓存；未确认的查询不产生已收录词条。

## 4 会话、取消与进度

QuerySession 记录 sessionId、inputRevision、origin、target、context、mode 和语言；每次开始查询生成 queryId，各服务响应带 sessionId、inputRevision、queryId 和 providerId。只有全部匹配当前输入的结果进入当前窗口；迟到的旧结果可以按其原身份缓存，但不能覆盖新词。

0.8.30 在上述入口默认使用 mode=auto，查询开始时由 QueryInput::resolved_mode 统一解析为 explain 或 translate，UI 会话仍保留 auto，编辑后再次识别；显式模式保持用户选择。简单规则为超过 6 个空白分隔词、段内换行／中文句末标点，或多词文字含句末／句间标点、分号时整段翻译，其余查词。它不是语法解析器，短句、专名或长短语可能需要手动调整；不改变收录类型或共享 OCR 类型判断。

解析后的模式决定服务能力筛选、底库／解释复用、模型提示、输出长度、流式译文处理和缓存身份。translate 仅使用支持翻译的服务，不以词典释义替代段落译文；保留原完整 target，不抽取某个词。缓存继续使用既有 explain／translate 身份，自动翻译可复用有效的显式翻译结果，旧 explain 缓存、释义、例句、原声及学习历史不删除。没有数据库迁移、DTO 字段或解析版本变化，模型输出的事实／缩写含义仍需上下文核对。

0.16.2 补齐 FR-14 的中英方向识别。手动输入、划词、截图与剪贴板入口统一传入 sourceLanguage=auto、targetLanguage=auto；QueryInput 省略语言字段时也默认 auto。每次 query_start 先解析方向，再确定查询模式、服务及缓存身份：原文包含 U+3400 至 U+9FFF 汉字时识别为 zh-CN，否则按 en 处理；目标语言自动选对侧的 en 或 zh-CN。中英混合文本含汉字时同样译英文，这是中英快捷规则，不是多语言检测。会话保留 auto，编辑后重新判断；调用方显式指定语言时保持其选择，观剧与选区替换的固定英译中入口不变。

只有英译中可使用 explain 的中文词义提示、底库及已有解释；中译英即使选了英文词义解释也解析为 translate，短词“最终”与中文整句均使用目标语言翻译提示并显示 translation。实际语言对进入所有服务的请求和缓存键，旧的中文解释结果不作为本次英译结果，也不清空旧资料；无需迁移数据库或新增 DTO 字段。真实模型的具体用词准确性与本次方向判断分别验证。

状态按服务分别为 idle、queued、running、ready、failed、cancelled。编辑原文使旧查询失效，保留新输入；重新查询、切词或取消不会提交收录。相同完整输入／服务请求在途时合并订阅，窗口关闭解除其订阅，不取消其他窗口仍在使用的同一请求。

交互查询在下一可用模型许可中优先于后台中文准备；不终止已经执行的后台批次，不绕过用户并发配置。自动监听只保留最新未分派输入，避免大量旧复制排队。切换输入或关闭监听应解除等待，不能被等待中的后台任务长期锁住界面。

查词进度和错误留在小窗的相应服务内。正常查询、取消以及自动监听的重复失败不逐次写入后台任务历史；自动失败保留当前会话的最新原因及次数。剧集导入、整集中文准备和同步的任务规则保持。

0.8.7 将内置本地模型的 explain／translate 交互查询改为 `stream:true`，逐段读取 SSE 的 content 增量；服务返回完整 JSON 时仍沿用原解析入口。模型许可尚未取得时显示“排队等待”，开始请求后显示“等待回复”，收到可展示字段后显示“正在生成”。底库和缓存继续直接返回，不为了展示流式效果延迟命中结果；后台批量准备沿用原批处理协议。

`query_stream` 保留跨网络包的 UTF-8／SSE 行，只向会话提供增量 JSON 中已经解码的 meaning、translation、notes 文字，不展示 JSON 结构或未完成的转义。首次有效片段立即通知，后续通知间隔至少 80 ms。无实际原句的解释仍不展示 translation。片段通过已有 sessionId／inputRevision／queryId 核对后更新内存快照，不逐片写库或记任务历史。

生成过程中 QueryProviderResult 为 running，value 可以含临时预览；复制和收录只在 ready 时出现。只有流完整结束、完整 JSON 解析与原有中文字段校验通过后，才保存有效结果并置 ready；失败清除临时值。取消继续使用现有订阅取消及请求中止机制，修改输入后迟到片段不进入新会话。

## 5 数据设计与兼容

| 数据 | 存放与规则 |
| --- | --- |
| QuerySession | Rust 进程内；窗口快照包含当前状态、生成中的临时文字或完整有效结果，退出后释放，不保存剪贴板复制流水 |
| query_results（schema 7） | SQLite；身份包含精确目标、完整语境、mode、语言、providerId 和非敏感配置指纹；保存完整有效结果及服务来源 |
| 服务／插件配置 | settings 的独立键，记录非敏感选项、顺序、自动查询和 credentialRef；不混入已确认词义 |
| 服务凭据 | 主程序受保护存储，沿用 Windows DPAPI 方案；SQLite 只存引用，读取接口不返回完整凭据 |
| 监听状态 | 运行期；启动关闭，合并间隔等非敏感偏好可保存 |
| 用户词库 | 沿用现有表、合并与同步规则；查词缓存和完整插件配置不参与词库同步 |

现有 explanations 的目标／完整语境身份和已有资料保持；默认本地解释可直接复用并标记为已有资料。多服务结果写入新的缓存，不把不同服务强塞入旧唯一键，也不覆盖原解释。界面区分“当前服务缓存”和“已保存的本地解释”，不冒称旧记录由新服务生成。

插件升级或配置改变生成新配置指纹；旧缓存保持可读，不因达到固定数量阈值自动清空。只有格式完整且符合该能力校验的结果进入持久化，流式片段和失败结果不冒充有效译文。用户清理查询缓存时不删除词条例句、原声和学习历史。

已新增 007_query_results.sql 并升至 schema 7，旧词库按原迁移链升级。查询缓存键包含精确输入、语言、服务非敏感配置和解析版本；本地 explain 的有效结果同时沿用 explanations 持久化，已有结果不覆盖。无 context 时不展示虚构原句译文。监听不保存缓存时仍可复用已有缓存，新结果仅驻留当前会话，确认收录后沿用正常持久化。

0.8.1 修正 FR-14／FR-15 的无句划词：若 explain 输入的 context 去掉首尾空白后与 target 完全相同，则它只重复选中文字，不构成额外原句。本地解释的读取、请求、校验与保存统一按空语境处理，使用无句词典提示并保存通用中文词义；会话、来源及后续收录仍保留原始 context。真实不同原句仍要求有效中文词义及句子译文，整段翻译模式保持原规则。本地 explain 查询解析版本递增至 3，其他服务和整段翻译缓存身份保持，既有解释与个人词库不清空。本地基础词库已命中时继续直接返回，不调用模型。

0.8.6 修正专名解释的字段错放：手动查询、单项准备及批量准备统一调用 `normalize_model_fields`。在已有明确人名类别整理之后，仅当 meaning 缺少有效中文且归一化后与查询目标相同、notes 已有可用中文时，将 notes 原文移至 meaning，并清空已转移的 notes，避免重复展示；不修改已有有效中文词义，不凭名称拼出新释义。交互词典提示明确要求专名保留原拼写，在 meaning 说明类别及用途。查询 JSON 解析或解释校验失败时，错误中保留具体原因和模型 content 原文（最多 16,000 字符），不再统一要求核对拼写或图片字幕。本地 explain 查询解析版本为 4，其他服务与翻译模式身份保持。中文、句子译文与字段长度的保存条件仍用于检查结果结构，不代表已核对模型的知识准确性。实际返回及验证见 [查询字段整理记录](../testing/pot-replacement-results.md#6-专名中文说明字段整理086)。

## 6 命令与事件提案

编号登记在 [接口契约](interfaces.md)，以下命令已接通，实际字段以接口契约及实现类型为准。

| 命令 | 关键输入／输出与约束 |
| --- | --- |
| translation_session_open | origin、target、context、mode；返回 QuerySession，仅创建查询会话，不收录 |
| translation_query_start | sessionId、expectedInputRevision、providerIds；返回 queryId 与各服务状态；自动入口限于已启用的自动服务 |
| translation_session_get | sessionId；返回当前输入版本、状态、有效结果，不含凭据 |
| translation_query_cancel | sessionId、queryId；只取消相应查询订阅，不取消收录或其他窗口的请求 |
| clipboard_listener_set/get | 设置 enabled 或读取当前状态，返回运行期 enabled 和最近输入状态；关闭时取消监听来源请求 |
| providers_list/update | 返回非敏感配置；更新服务与自动范围，凭据提交后只返回引用／是否已配置 |
| plugin_install/remove | 用户选定包或 pluginId；返回版本、能力与启用状态，卸载保持业务资料 |

query_updated 事件只携带会话、输入版本、查询和服务标识以及状态；流式进度也使用此通知，当前预览或完整结果由 translation_session_get 读取。窗口间显式收录继续使用现有 collection_* 命令，不引入第二套收藏数据库。
