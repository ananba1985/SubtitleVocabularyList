## 1 已确认方案

安装位置由用户在安装器中选择，不固定 D 盘。本机用户决定安装到 `D:\SubtitleVocabularyList`，安装目录保存程序和 tools，资料保存到其 `Data` 子目录。本轮按用户后续缩小的要求调整资料路径和测试入口，不执行发行打包或安装，也不改安装器的路径选择流程。

| 运行方式 | 未显式指定资料目录时 |
| --- | --- |
| 本地调试脚本／debug 程序 | `D:\SubtitleVocabularyList\Data` |
| 本地打包 exe／生成的 run-local.ps1 | `D:\SubtitleVocabularyList\Data` |
| 安装版／发行 standalone exe | 当前可执行程序所在目录下的 `Data` |

因此安装到本机选定的 D 盘位置后，三者默认共用一份资料。正式程序选择其他安装位置时仍跟随该位置；本机测试默认值不自动跟随以后更换的安装位置。隔离测试可显式用 `-DataDirectory` 或 `SVL_DATA_DIR`，环境变量优先于程序默认值，不修改系统级环境变量。

0.8.31 的开机启动登记会携带 `--data-dir "<开启时当前绝对资料目录>"`，该显式参数优先于 SVL_DATA_DIR 和上述默认值，避免登录时进程工作目录／环境变化导致读到另一份词库。没有该参数时沿用原规则；资料文件不移动、不复制、不迁移。登记属于当前 Windows 用户，不写入可迁移的词库配置；移动程序或资料目录后需关闭开关再开启，更新登记到实际路径。

## 2 内容与缓存

Data 根目录保存 `vocabulary.sqlite3`，以及 media、corpora、jobs、credentials 等资料目录；例句、中文解释、学习状态、设置和同步元数据沿用数据库。`corpora` 保存长期语料和整集音轨，`jobs` 管理任务中间产物，0.26.6 的兼容迁移及引用回收见第 5 节。`cache/webview` 为主窗口及查询小窗共同使用的 WebView2 资料，`cache/temp` 为本进程及子工具的 TEMP／TMP，`cache/speech` 为可复用系统语音。启动前明确创建并使用这些目录，不通过 AppData 选择业务库或 WebView 缓存位置；无法访问选定位置时显示启动错误，不退回其他空词库。

0.7.3 安装配置将 Google 和 ECDICT 基础词库作为独立资源写入 `Data/dictionaries`，随包带两份 SQLite、清单和来源说明；升级只替换列明资源，不打包或覆盖 `vocabulary.sqlite3`。发行准备不读取本机日常 Data；standalone 复用同一映射，保留已存在的个人资料。实际 NSIS 包本轮按用户要求未生成，资源流程结果见[记录](../testing/dictionary-packaging-results.md)。

主窗口通过绝对路径 WebviewWindowBuilder 创建，小窗使用同一目录，避免 WindowConfig 的相对目录处理。开发配置与发行配置采用同一应用标识，复用现有单实例机制；关闭或从托盘完全退出上一种运行方式后再切换。数据库结构升级沿用 Store 的迁移规则，旧程序不能读取更高版本结构。

源剧集是用户导入时选取的文件，不复制所有外部剧集到 Data；已经准备的音轨和已保存音频随资料目录迁移。Windows 自身的运行时安装、系统声音和操作系统记录不作为本程序业务资料。

## 3 迁移方式

迁移前退出客户端，选定一份实际使用的源目录；不把各类验收用的隔离词库合并到日常资料。执行：

```powershell
.\scripts\migrate-data.ps1 -SourceDirectory '旧资料目录' -DataDirectory 'D:\SubtitleVocabularyList\Data'
```

脚本要求目标不存在，核对绝对路径、源目录链接和进程状态，先用 SQLite backup 保存包含 WAL 提交内容的一致性快照，再移动整个源目录。仅改写 sources 的 corpus_path／audio_path 和 tasks 的 snapshot_json 中的旧根路径；逐表比较所有记录并检查数据库完整性。旧库快照保存到 Data/backups，用户词条与释义不作文本替换。

新脚本只在上述逐表比较及 integrity_check 成功后，在迁移快照目录写入 `migration-verified.json`，记录目标资料根目录和通过结果。启动清理读取回执时要求目标目录与当前选定 Data 一致；没有回执的旧格式按下一节列明的严格命名／内容范围处理。0.26.4 起，迁移和首次正常启动通过后直接清除这些临时恢复材料，不再转存一份准备长期保留的快照；失败或未通过正常启动时保留原副本。

本机原开发库已移到 D 盘选定位置；旧安装库为空，单独存档到 `backups/legacy-installed-data`。最新开发 WebView 缓存移到 cache/webview，旧安装缓存独立存档到 `backups/legacy-installed-cache`。其他隔离测试目录保持独立。实际行数、路径和启动证据见验证记录。

## 4 成功启动后的自动清理

对应 NFR-02、NFR-06。安装器覆盖结束不触发删除；桌面宿主全部 setup 成功，主界面成功取得 `app_info` 和 `settings_get` 后调用既有 `app_ready`，每次启动仅安排一次后台维护。`Store::open` 已完成 schema 迁移，维护再次对当前库执行 `quick_check` 及 `foreign_key_check`；任一步未通过均不开始清理。校验后释放数据库锁，再处理文件，不阻塞首屏等待文件回收。

0.26.4 取代此前“最近两份”的策略：自动快照是升级过程的临时恢复副本。需要数据库 schema 升级时先保存包含 WAL 已提交内容的一致性副本；无 schema 变化时不重复复制数据库。升级／迁移验证及首次正常启动均通过后清除全部程序拥有的自动快照，包括此前两份策略留下的副本；失败或尚未完成正常启动时不执行清除，不按数量提前丢弃恢复点。

| 路径／内容 | 保留和回收规则 |
| --- | --- |
| `backups/automatic/snapshot-<毫秒时间>-<UUID>.sqlite3` | 程序管理的升级前临时快照；通过完整性验证后才发布。升级、迁移校验及首次正常启动均通过后清除全部已识别快照及其 SQLite sidecar，不再保留固定份数；自动目录为空时也移除空目录，未知名称仍保留 |
| 同一自动目录内的上述 `.partial` 临时文件和已无对应主快照的 sidecar | 当前资料启动及校验成功后回收程序拥有的未发布残留；其他名称不参与 |
| `backups/migration-<UUID>` | 只认迁移脚本使用的 `before.sqlite3`、其 sidecar 和可选验证回执；当前升级／校验／首次正常启动通过，且快照自身完整性正常、回执匹配当前资料目录后，直接清除临时快照和包装目录，不再重复转存。旧格式无回执时仍限定上述命名与内容；包含额外未知文件时整目录保留 |
| `backups/legacy-installed-cache` | 回收本项目此前保存的旧安装 WebView 缓存；当前 `cache/webview` 和 `cache/temp` 不参与 |
| `backups/legacy-installed-data` | 仅在目录只含旧词库及其 sidecar、库内全部业务表为空且完整性检查通过时回收；含记录、额外文件或凭据则保留，不假定它已合并 |
| 手工备份及其他旧文件 | 自动命名空间之外的文件／目录原样保留；不依据 `.sqlite3` 后缀或大小猜测。此前人工修复生成且未登记为自动快照的 `before-chinese-repair-…` 也保留 |

当前 `vocabulary.sqlite3`、完整例句／词义／学习历史、`media` 原声、`corpora` 长期资料、`subtitles`、`credentials`、`dictionaries` 和正在使用的缓存均不属于备份清理的删除候选；`jobs` 在第 5 节按引用独立管理。用户手工备份请放在 `backups` 下自定文件名／目录，不放入程序保留的 `automatic/snapshot-…` 命名空间。

所有删除目标均检查解析后的绝对路径仍位于选定 Data 内，拒绝目录链接／重解析点；删除目录前还检查其后代链接。清理错误只记录 `[data-maintenance]` 并延后至下次启动，既有业务资料不受影响。清理不联网、不启动定时轮询，也不每次升级复制完整原声；此规则当前接入 Windows 桌面，Android 仍沿用其独立沙盒缓存规则。

代码更新本身不会执行日常 Data 清理；需要运行含此实现的新桌面版本并达到上述成功门槛。开发验证只使用合成资料目录，不自动构建、安装或启动新版操作日常资料。最新临时恢复方案证据见[验证记录第 6 节](../testing/data-directory-results.md#6-0264-临时恢复备份最小验证)，第 5 节保留被替代策略的历史验证记录。

## 5 jobs 分层与按引用回收（0.26.6）

| 目录 | 作用和生命周期 |
| --- | --- |
| `corpora/source-<来源标识摘要>/corpus-<内容摘要>.json` | 完整语料正文与元数据；新导入在原来源安装事务提交路径，旧语料迁移保留全部 JSON 字段，仅修正 audioPath |
| 同一来源目录的 `audio-<内容摘要>.<原扩展名>` | 完整整集音轨，按字节摘要发布和复用；从 jobs 复制并核对完成前不改来源路径，不覆盖已有不同内容 |
| `media` | 已收录例句的完整原声片段，沿用原资产及例句关联，不参加本轮回收 |
| `jobs/task-<任务 UUID>/video-<导入指纹>` | 新导入的字幕提取、OCR 图片、转写输入和临时音轨／语料；发布为长期资料后，任务终态且无引用时回收整个任务工作目录 |
| `cache/speech` | 系统朗读和复习生成的可复用语音；生成过程临时文件进入任务工作目录，不再与长期音轨混放。缓存本身不参与本轮 jobs 删除 |
| 旧 `jobs/video-<64 位摘要>` | 先迁移来源仍指向的语料／音轨，再按最新引用判断；仅当文件均为已识别的语料、音轨、字幕、OCR 或转写产物且无引用时回收 |
| 其他 jobs 文件／目录 | 未识别名称或旧目录中含额外未知文件时保留；原截图会话等仍沿用原关闭／取消清理流程，不一概按时间或大小删除 |

兼容维护读取所有来源（包含仍服务于历史的来源），在数据库锁外复制和核对长期文件；语料正文、额外元数据、音频字节不删减。所有准备好的旧路径更新合并为一个短事务，并核对来源仍使用旧路径才更新。事务成功后重新读取引用；复制、验证或数据库提交失败时原文件和原引用保持，不靠移动原文件后再尝试提交。

引用来自来源的 corpus_path／audio_path／path_hint、全部 media_assets、持久任务快照、内存前台任务回执，以及设置中包含 jobs 路径的 JSON。非终态任务保护 `jobs/task-<其任务编号>` 全目录；即使任务终态，结果仍引用的路径也保护。学习历史、任务历史和任务结果本身不因回收而删除。

TaskManager 工作线程持有共享文件租约直到终态和回执保存完成；维护以非等待的独占租约避开全部工作线程，防止读取旧音轨路径后恰逢删除。桌面首次成功读取资料后在后台安排一次；使用工作目录的任务会设置待维护标记，任务结束时再尝试。仍有任务执行或文件错误时延后，后续完成事件／下次启动重试，不新增常驻轮询。只遍历 jobs 候选并读取来源／引用元数据，不比较或重算全部学习历史。

删除仅限选定 Data 内程序拥有且无引用的 `task-<UUID>` 工作目录、上述旧 video 目录、旧 `system-<摘要或 UUID>.wav` 和 `android-corpus-<摘要>.json`；引用任一子文件就保留对应工作目录。目录／文件操作复用路径与后代链接检查。`corpora`、`media`、当前字幕、缓存、手工备份及未知目录不参加回收。新语料发布入口是共用 Rust 核心，桌面／移动端资产访问范围已适配；启动批量维护由 Windows app_ready 接入，本轮未重验 Android 原生导入／播放。

实际最小正常证据见[验证记录第 7 节](../testing/data-directory-results.md#7-0266-jobs-分层与引用回收最小验证)。本轮只用合成目录验证，不直接迁移或清理日常 Data，不生成或安装新包。

## 6 使用与交付边界

三个中文入口仍按原职责使用。运行调试／本地构建不需要再传资料路径；生成安装包仍为手动入口。用户后续明确授权后，已通过同一脚本生成[0.6.1 安装测试包](../release/0.6.1-release-notes.md)，等待用户选择 D 盘安装并验证。历史 0.1 安装包不包含新规则，不能拿旧包验证本次行为。
