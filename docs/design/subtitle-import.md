## 1 目标与现状

导入剧集时尽量取得同一版本的英文、中文字幕，已有中文优先用于暂停翻译，减少本地模型整句翻译负担。导入只建立学习资料，不将整集对白加入个人单词本；译文显示后 5 秒的收录规则不变。

0.10.0 在原英文导入路径外增加 `subtitles.rs`：取得全部可转换的内置文本轨及同名分语言外置字幕，保存原资产，按时间读取当前中文并补齐缺失句缓存。已有来源、例句、个人词库、学习记录及自动回执保持。实际证据见[本地字幕验证](../testing/subtitle-import-results.md)。在线检索、图片轨独立资产和人工时间校正尚未接入，以下涉及这些部分的内容仍是设计。

## 2 取得流程

1. 探测视频全部字幕轨及本地同名外置字幕，分别识别英语、中文、双语与未知语言；保留轨道语言、标题、格式和原文件。
2. 解析文件名中的剧名、年份、季／集（S01E02、1x02、中文季集），结合容器标题形成可编辑的检索条件。多集文件、名称冲突或季集缺失时由用户核对，不将首个搜索结果直接视为匹配。
3. 本地已具备可靠中英字幕时直接使用；缺少语言且用户已启用、配置在线字幕服务时，按文件名／剧集信息补查缺失语言。服务未配置时提供一次入口，不阻塞本地导入与观看。
4. 展示候选的语言、季集、发行版本、帧率和来源。媒体摘要、同一发行版本、时长与字幕时间共同参与匹配；名称相同不代表时间轴相同。冲突保留候选，确认后再导入。
5. 建立独立字幕资产和对齐映射，准备可复用的当前句中文资料；未匹配部分才进入原后台本地模型队列。

## 3 轨道、对齐与译文优先级

英文学习对白为规范时间轴；原始 ASS／SSA 样式和定位、PGS 图片轨独立保留供播放器显示。解析后的标准 cue 与原字幕资产关联，不用转出的纯 SRT 覆盖原字幕。

按实际时间重叠形成一对一、一对多或多对一映射，不能按行号直接拼接。内嵌双语的同一 cue 可拆分中英文，同时保留原始内容。时间偏移、不同剪辑版或帧率变换必须有明确依据；无法可靠对应的中文不作为已匹配译文。图片字幕需要识别后核对，不因存在中文轨就声称已获得可用文字。

暂停当前句的使用顺序为：用户修正内容 → 已核对对齐的中文原字幕 → 原有有效缓存译文 → 对缺项进行后台本地模型补充。不同来源保留原出处、版本和修订关系；不将下载字幕假标为模型生成，也不覆盖用户修改。暂停读取已准备资料，不默认重新请求模型。

给已导入剧集补中文字幕时保留英文来源及 cue 标识、个人例句、音频、学习历史和自动收录回执。仅更新字幕资产、对齐结果及缺失译文，避免整集重建造成重复收录。

## 4 数据与任务

| 对象 | 需要保留的信息 |
| --- | --- |
| 字幕资产 | 媒体／来源 ID、语言与双语标识、原格式、轨道号或服务文件 ID、来源 URL、文件摘要、发行版本、帧率、相对 Data 路径、取得时间 |
| 标准 cue | 资产与原 cue 标识、起止时间、原始文本、规范文本、原字幕定位引用 |
| 对齐映射 | 英文 cue ID 集合、中文 cue ID 集合、有效偏移、对齐依据／状态及版本 |
| 当前句中文 | 原句、完整中文、来源类型／引用、用户修订标记及关联版本；复用现有译文读取接口 |

本地实现保存在 `Data/subtitles/<媒体 SHA256>/`。原轨按 ASS／SRT／VTT 保存，标准 cue 与语言、来源、轨号、摘要及中文选择写入 `bundle-<来源摘要>.json`；`settings` 的 `subtitles:<sourceId>` 只保存相对路径，schema 仍为 10。原 ASS 样式与定位不改写，学习文本去除 FFmpeg 转出时保留的 ASS 控制标记。0.12.0 增加 PGS 原 SUP、DVD／DVB 原 MKS 资产复制，cue 为空且不可选为直接中文来源，明确提示需播放暂停后 OCR 核对；该图片轨导出分支尚待实际样本确认。

本轮时间匹配允许分句不同：计算中文 cue 对英文区间的覆盖并合并中文；总覆盖至少 65%，单个重叠至少为 `min(较短区间时长, max(80ms, 较短区间时长/5))`，排除容器轻微时间偏移造成的下一句边缘重叠。参数是初始实现值，未进行准确率校准，不代表所有发行版本均可靠对齐。不同剪辑版、人工偏移修正与在线匹配仍待后续。

已选择的原字幕中文优先于旧句缓存；保存字幕只为缺失句缓存新增记录，不覆盖旧值。沿用缓存字段时以 `model_url=subtitle://<资产ID>`、`model_name=中文字幕` 明示出处，不假称模型生成。用户可在“学习设置”选中文来源或继续用旧缓存，选择持久保存，切换后旧暂停计时失效并重新确认显示。CMD-72 至 CMD-74 分别读取资产、启动聚合取得任务和保存中文选择。未来字段表中服务 URL／发行版／人工修订等尚未实现。

每次剧集导入／补字幕显示一个聚合任务，包含探测、检索、取得、对齐和缺项准备进度。取消保留已完成资产，继续时复用摘要一致的结果，不产生每行字幕一条历史。未找到、配额不足、认证失败和版本不符分别显示真实原因；本地原字幕和观看始终保留。

## 5 在线服务边界

拟采用服务适配器，先完成本地双轨，再选择一个有官方 API 的服务接入。服务密钥由用户配置，不写入公共仓库；仅发送用户授权检索所需的名称、季集或服务支持的媒体摘要，不上传视频、音频或个人单词本。下载字幕保留来源及适用条款，不将未经许可的字幕打入公开安装包。

2026-10-21 已核对的候选资料：

- [SubDL 官方 API 文档](https://subdl.com/api-doc)：提供名称／文件名、季集和语言条件，需 API key。尚未配置账号、请求真实候选或验证下载；实施时复核当时版本与限额。
- [OpenSubtitles 官方 API 使用说明](https://blog.opensubtitles.com/opensubtitles/how-to-build-a-movie-subtitle-finder-cli-with-python-and-the-opensubtitles-api)：提供文件名／媒体摘要检索等能力；需按官方要求配置认证和下载权限。采用现代 `.com` API，不采用已公告终止的旧 `.org` XML-RPC 接口。

未配置服务不影响核心离线功能。在线取得失败不能改为未经授权的云端翻译，也不冒充取得成功。

## 6 最小验收与开放项

M-25 本地文本部分：一份中英轨正常样本通过，包含原 ASS 定位和持久化；M-27 本地部分：对应中文用于暂停上下文，未请求模型，旧个人词条保持，见 TC-65／67 记录。M-26 尚未执行：用户配置服务后，对一集明确名称／季集的视频完成缺失语言检索、确认与下载。图片字幕、在线来源和时间校正不在本轮通过范围内。

尚待实施时确定：首个在线服务、所需账号与配额、自动接受匹配的阈值、图片字幕中文的核对方式。原暂停学习闭环与播放器常规功能继续沿用 mpv，不因字幕取得扩展重做播放器。
