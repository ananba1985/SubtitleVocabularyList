## 1 目标与执行边界

交付完整“准备合格题库 → 配置并分层抽样 → 离线作答 → 分频段报告 → 确认收录 → 复测及完整历史同步”流程。阶段先交付可用的本地闭环，再接通新增站点资料交换；本地可用不代替 FR-23 完整同步或组合题库已完成。

用户已授权按本计划开发和测试。按实际变化增量提交当前分支，不新建分支/PR，不为每个功能重做发行包；0.8.0 标明开发中，不表示完整功能完成。验证使用隔离资料，不迁移日常安装版词库，不预设未经测算的工时。

## 3 每阶段具体任务

### M-15：资料与题目

1. 核对固定来源、原排名及缺项，取得组合来源的实际文件/许可/版本结论；不擅自换成无关词典短语排行榜。
2. 扩展底库生成器，完整词频目录与中文词典分别计数；建立 assessment 领域基础迁移，保持现有查词及个人资料，后续阶段按该基础接逻辑，不无变化重复迁移验证。
3. 建立目标/题型去重键、背景准备检查点、核对记录/发布接口及不可变版本，管理面板在 M-17 接入；命中底库的释义复用，不为每词×剧集对白重复生成。
4. 采用并记录 assessment-policy-1 的初始参数，允许用户修改 N、题数、内容和题型；不把设计参数标为已验证的测量标准。

### M-16 至 M-18：本地完整流程

1. 迁移只新增水平测试领域表，不改旧 review 状态；会话、作答、修正和确认收录关联按设计事务保存。
2. 先完成可验证的核心，再接桌面。前端不保存权威答案或评分事实，答题不依赖模型；保留原声/系统语音标识。
3. 配额、题目和评分版本冻结；报告分母、无提示/确定表现及样本不足清楚；历史比较说明配置差异。
4. 收录接入现有准备/合并/提交，不另建词库；取消不保存，批量逐项结果真实可见。复测不批量标记 Top N 已掌握。

### M-19：完整同步与交付说明

1. 在实际站点源码中确认能力路由和 D1/R2 资料限制，再落地协议与本机迁移的同步记录表；不把现行 svl-sync-1 改成不兼容新包。
2. 交换完整会话快照、作答、提示、修正、报告及收录引用，沿用原账号批准和媒体摘要；下载历史不触发收录或复习重排。
3. 核对真实两端保存内容；旧站点未支持时明确待同步，不让现有词条同步误报为全部学习资料同步。
4. 更新设计、字段契约、测试结果和使用说明，按用户后续发布需求再安排随包题库、安装和升级验收。没有发布请求时不打包。

## 4 最小正常验证与执行规则

只执行阶段表对应的最低必要正常流程及变更需要的类型/编译检查，通过后提交并推进。纯脚本或站点工具使用语法检查和一次基本正常运行即可，不自建扩展测试环境。已通过检查不因进入下一阶段无变化重跑。

TC-53 至 TC-58 具体输入/预期维护在总测试计划；TC-53、TC-54 已执行；TC-55 桌面流程通过但真人听感延期，TC-56／57 核心通过，TC-58 真实完整往返已通过（同机隔离端，不冒充第二物理设备）。恢复、冲突、缺项等设计要求不自动授权故障注入、负载/性能、兼容矩阵、长期实验或心理测量校准；需额外执行时先说明目的及预计时间/token成本，并取得用户明确同意。真实站点和实际声音证据与合成数据分开记录。
