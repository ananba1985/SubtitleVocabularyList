## 1 边界和流程

电脑在现有剧集入口发布选定剧集的已有准备资料，手机打开自己选择的本地视频后，检查同账号资料并明确下载使用。两端经现有服务器独立工作，电脑退出后仍可下载。只匹配视频内容 SHA-256，不按文件名猜版本，不传视频、原声大文件、路径、模型地址、凭据或个人学习事实。

共享字幕、译文和词语解释使用独立 `svl-prepared-1` 契约，不混入词条／测验同步包。复用同一真人批准连接及账号隔离；本地离线可使用已下载资料，新网络动作需用户明确触发。字幕缺译文保留空值及已译／总数，不虚构完整准备结果。

## 2 数据契约

| 字段 | 内容 |
| --- | --- |
| protocol／preparationVersion | 固定 `svl-prepared-1`／`svl-preparation-1`，与词库 schema 分开 |
| mediaSha256／durationMs／title | 已准备视频摘要、时长和显示标题，排除本机位置 |
| preparedAt／subtitleRevision | 原准备数据时间和字幕内容版本摘要 |
| subtitleDelayMs／chineseOffsetMs | 原观看整体延迟、原中文字幕对齐偏移；中文时间对齐已作用于逐句译文，接收端不重复叠加 |
| cues | 当前准备版本的英文原句、原始开始／结束时间及可用中文译文 |
| explanations | 属于这些原句／候选词的已准备词义、语境、译文和备注；不含模型配置 |
| 服务器 metadata | 视频摘要、单调递增 revision、完整内容 digest、字节数、标题、句数／已译数／解释数、准备和上传时间 |

完整内容摘要按对象键排序后的 UTF-8 JSON 计算，列表顺序保留。每份完整资料沿用现有 8 MiB 请求预算并预留封装空间，超限保留本机资料并说明，不截断字幕／解释换取成功。服务器 D1 保存账号隔离的当前版本元数据，R2 按账号和内容摘要保存不可变准备版本，未上传视频或个人词库。旧版本是追溯资料，不覆盖已收录快照。

## 3 接口与并发

`/api/svl/v1/account` 宣告 `preparedEpisodes: svl-prepared-1`，旧客户端继续原协议。

| 接口 | 行为 |
| --- | --- |
| GET `/api/svl/v1/prepared-episodes/{mediaSha256}/info` | 当前账号该视频的元数据；不存在返回 404 |
| GET `/api/svl/v1/prepared-episodes/{mediaSha256}` | 取得完整 metadata／package，不依赖电脑在线 |
| PUT `/api/svl/v1/prepared-episodes/{mediaSha256}` | `{baseRevision, package}`，仅接收完整已校验内容；相同 digest 幂等确认，不同版本按基准条件更新，基准过期返回 409 |

客户端复用 HttpRemote 的连接、能力检查、手动离线、账号变化及 TaskManager；下载核对完整摘要和视频身份后才绑定。桌面发布时展示已知服务器版本，遇到变化先刷新核对；不按最后在线时间静默覆盖。检查、发布、下载均是显式动作，不加入常驻后台轮询。

## 4 手机应用与共享核心

保留原词库、例句、原声、作答及修正。共享解释进入现有只补缺的缓存，字幕使用本机私有文本资产和原 Store／字幕对齐；Media3 继续渲染，不新写字幕时钟或合并算法。当前 URI 保存对应指纹和准备版本，换视频后的旧网络结果不能改写新视频；已下载版本可在该视频下次打开时复用。

手机生成应用私有 VTT 并沿用现有英文选轨／整体偏移，学习对白和原声区间使用同一时间线。准备版本更新保留旧来源／字幕资产及既有收录的原始文字、时间和媒体。原视频仍由用户经系统选择器授权；包内不包含电脑路径，也不把同名文件当成已匹配。

## 5 最少完成证据

一次真实正常链路覆盖：隔离桌面准备具名合成视频并发布 → 退出电脑 → 已批准手机下载并匹配同版本地视频 → 暂停显示原句与共享中文、离线点词复用准备解释 → 旧词条／原声／历史保持。随后同一正常更新流程核对版本与快照保持，不扩大网络故障、跨账号攻击或兼容矩阵。正式发布打包仍按项目人工入口。
