## 1 实现与环境

Windows 11、单屏 2560×1600、200% 缩放，实际 Tauri WebView2 与本地英语 Tesseract。按截图按钮或默认 `Ctrl+Alt+Shift+S`，先以 Windows GDI 保存本次桌面快照，再打开无边框选区窗口。拖选后按原始图像尺寸换算物理像素，裁剪并离线识别，成功结果进入现有收录确认窗口。

每次快照和窗口使用独立会话标识。矩形在核心再次检查，显示器配置变化时要求重新截图；取消、失败与完成均释放此次临时图像。截图准备任务完成只表示等待拖选，OCR 任务成功才表示文字识别成功，均不表示已收录。

## 2 实际结果

| 场景 | 结果与边界 |
| --- | --- |
| 200% 的窗口与快照对齐 | 最初出现窗口客户区高度多 56 个物理像素；使用原生客户区校正后，实测客户区为 2560×1600、原点 (0,0)，页面 1280×800、DPR=2 |
| WPF 英语文字拖选 | 实际拖选进入确认窗口，识别 `I was reluctant to ask for help.` 中的首字母为竖线；确认前可人工纠正 |
| 合并与语境 | 修正后收录 reluctant，合并到既有词条，形成 3 次主动收录、3 个来源例句；没有原声的截图来源不伪造音频 |
| 空白区域 | OCR 返回 empty_recognition，结果为空，不显示旧识别内容、不自动收录 |
| 无效与过小矩形 | 核心拒绝空矩形并保留当前会话；页面点击过小选区显示错误，可重新拖选或取消 |
| 重复采集 | 已有会话时返回 capture_busy，不并行替换快照 |
| 过期会话 | 返回 not_found，不取得后续会话图像、不生成新识别任务 |
| 引擎缺失 | 临时使用不存在的 Tesseract 路径，返回 provider_unavailable、结果为空；恢复后两个快捷键仍有效，词条与例句计数未改变 |
| 快捷键冲突 | 划词和截图配置为同一快捷键时拒绝，保留旧设置与注册结果 |
| 清理 | 完成与取消后未残留本轮 screen 快照；用户未确认的文字不会自动进入词库 |

WPF 测试窗口默认渲染曾造成 GDI 快照中文字空白。测试夹具明确使用软件渲染后可复现识别；这只处理夹具，不宣称所有硬件加速或受保护内容都能截图。
