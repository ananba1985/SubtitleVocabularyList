## 1 本轮交付与实施边界

用户确认文档后要求开始开发，先打通内嵌播放器、暂停显示已有译文及显示后 5 秒自动收录整句。本轮以此为交付范围，开发版为 0.9.0，schema 保持 10；已接入范围、实际检查和未完成项见[结果记录](../testing/watch-and-learn-results.md)。不把整个 M-20 至 M-24 或 FR-25 至 FR-29 标为交付，不生成安装包。

用户随后补充：暂停自动显示导入时已生成并保存的句译文，**译文实际显示后**持续暂停 5 秒自动收录整句，提前继续则不收录；等待翻译不计入。5 秒为用户确认的默认值，可配置及关闭。此规则已进入本轮核心实现，替换首稿“只允许手动确认收录”的边看边学约束，其他采集入口不变。

完整模块的原计划顺序为“真实内嵌播放 → 暂停展示已保存译文 → OCR 保底 → 译文显示后定时整句收录与手动收录 → 入口整合与位置恢复”。按用户最新指示，本轮先打通已导入视频的保存译文闭环，OCR 和查询补充随后实施。全屏与译文靠近原字幕位置已纳入本轮；听感检查须提前说明，不直接外放测试音。外部 mpv 进程或 PotPlayer 联动不能替代已确认的内嵌播放器交付。

## 3 各阶段完成门槛

### M-20 内嵌播放基础

- 核对并锁定 libmpv 构建、架构、依赖、许可和摘要，记录资源来源；不把用户本机播放器作为必要依赖。
- 新建单一播放会话与宿主视频区域，接通加载、播放／暂停、定位、音量、音轨／字幕、外置字幕、字幕延迟和全屏的最小控制。
- 优先验证原生子 HWND；在一个真实 Tauri 窗口完成本地视频播放、暂停、原生 OSD 译文叠加、调整视图区及打开／关闭面板。记录实际渲染选择、显示确认、焦点与字幕时间规则。
- 完成证据：TC-59 的真实窗口和可听播放记录、资源清单、实际采用的窗口与时钟约定。若 HWND 方案不适用，只调整 libmpv 内嵌实现，不撤销内嵌产品要求。

### M-21 字幕与已保存译文展示

- 建立带版本的暂停快照，区分用户暂停与内部暂停；取得同一文件、轨道、时间位置的文本，已有索引只在身份匹配时复用。
- 从导入保存的同源对白读取译文并显示在视频画面上，不默认重发模型请求；没有已保存译文时提示补充，用户需要时复用流式 translate／explain 及 ModelGate。
- 记录完整有效译文实际显示的确认时间，读取／OCR／模型等待及流式未完成时间不算；不是收到查询响应就直接开始计时。
- 继续播放即移除译文、收起面板并使旧订阅失效；不创建整集准备任务。
- 完成证据：TC-60 一条已知文本字幕“观看→空格暂停→画面显示数据库原译文→点词→继续”，核对没有重生成句译文、来源和实际呈现；定时保存留到 M-23。

### M-22 OCR 保底闭环

- 只在没有可靠文字且画面有字幕时使用暂停视频帧 OCR；异步等待含字幕截图完成后再识别。
- 复用已有 OCR，提供帧内重新框选、编辑原文和重查；标识 OCR 与采集时间，释放临时图像。
- 完成证据：TC-61 的一个图片字幕或硬字幕正常样本，从暂停识别到编辑后翻译。没有全文字幕／起止时不伪造；不以识别失败回退掩盖模型响应问题。

### M-23 统一收录与原声

- 从已冻结的暂停上下文复用同一收录服务，手动路径保留草稿确认；自动路径在完整译文显示后持续暂停 5 秒时保存整句、译文和来源，不弹确认框。
- 增加默认开启／5 秒设置、取消本次、单调计时与上下文核对；恢复播放、离页及手动草稿取消原计时。缺少完整译文或 OCR 未核对时不计时，补齐后实际显示再从零开始。
- 自动操作稳定标识持久去重，不将自动保存重放当作新的主动重复学习；保存仅当前功能反馈，不制造逐次后台历史。
- 复用来源绑定、现有合并、操作标识及媒体保存；有真实字幕边界用原声，只有 OCR 帧位置则由用户调整试听区间或仅存文字。
- 完成证据：TC-62 在隔离资料中从同一素材收录一个新词、向已有词确认追加一个例句，试听保存的原声，并确认旧释义／学习记录保持。沿用既有完整同步数据结构，不新增观看进度同步功能；不重复执行全套站点测试。
- TC-64 再以同一片段完成显示后快速播放及持续 5 秒两种正常用法，核对等待翻译不算、到时自动保存整句和再次暂停不重复；不扩展故障或压力测试。

### M-24 入口与日常使用收尾

- 增加侧栏“边看边学”及相关托盘导航，旧预习仍可独立使用；原收录按钮、全局快捷键和其他页面职责保持。
- 恢复已保存位置、轨道和字幕设置；切页／最小化暂停并隐藏视频，返回后手动继续。播放器与既有学习音频互斥。
- 完成证据：TC-63 正常关闭、重开并继续一次，进入既有单词本读取本轮收录，确认预习和听读会话未被替换。更新文档为实际实现状态，未覆盖的兼容／异常条件如实列出。
- 将 libmpv 资源、版本和许可纳入现有打包资源清单及预检设计；实际安装包、源码资料打包和实装验收仍等用户明确要求，不在本阶段自动执行。

## 4 最小验证与证据规则

TC-59 至 TC-64 对应上述正常路径，同一条已通过的流程不因收尾无变化重做。采用一份合法可用、带已知字幕时间的本地片段及一个图片／硬字幕样本，测试个人库隔离；不把隔离库作为用户的默认空词库，不停止用户正在使用的其他服务。

实施时每阶段只做必要的编译／类型检查及对应正常检查。听感、快捷键和窗口操作优先由可用的实际窗口工具核对，需要用户听感时一次说明操作和预期；保留素材标识、程序版本、文本来源、实际时间及保存结果，不记录无关日常播放日志。

本轮最小正常检查见结果记录；其余阶段保持未执行。本计划不自动授权故障注入、压力／长期运行、性能专项、全格式／多屏兼容矩阵或安装验证；需要这些额外检查时先说明范围、目的和预计时间／token 成本，并等待明确同意。产品要求的错误处理在设计中保留，不把“未测试”写成“可忽略”。

## 5 风险与处理次序

| 风险／依赖 | 优先处理 |
| --- | --- |
| 原生视频覆盖 WebView 浮层或焦点不一致 | M-20 先验证一个真实嵌入布局；模态框时隐藏视频，必要时切换 libmpv render API |
| 字幕轨、延迟或暂停时间关联错误 | 先锁定当前轨和展示时间规则，所有异步结果关联上下文版本 |
| 图片／硬字幕只有采集位置 | OCR 标识来源；原声区间由用户试听确认，不伪造字幕时间 |
| 本地模型延迟／失败 | 默认用导入时保存的译文；手动补充才调用模型，等待不计时，完整译文显示后从零等满 5 秒 |
| 计时起点或重复保存错误 | M-23 使用实际显示时间、上下文及译文版本、核心条件判定和持久幂等，不因旧回调或再次暂停多存 |
| 新来源与旧导入重复或覆盖历史 | M-23 先接现有合并事务与来源绑定，不创建平行词库或改旧来源 ID |
| 播放引擎资源与升级 | 锁定实际 DLL 及许可，保持 Data／个人记录；打包及安装另行授权 |
