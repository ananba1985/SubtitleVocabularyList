## 2 桌面账号连接

桌面生成高熵同步令牌，把 SHA256 摘要与请求 UUID、设备显示名发送到 `/api/desktop/requests`。站点生成十分钟有效的连接请求和核对码；摘要只能建立待授权状态，不能自填用户身份。桌面持有原始令牌，以 Bearer 方式轮询同一请求。令牌不进入 URL、日志、词库、公开源码或前端响应。

用户在系统浏览器打开同一站点的 `/desktop-connect?request=...`，按平台流程真实登录 ChatGPT，核对设备名与桌面显示码，明确批准这台设备交换个人词库、例句、原声和学习记录。批准接口必须具有平台用户身份且同源 Origin；站点把请求绑定到该真实用户。未批准、过期、拒绝或撤销均不能访问个人数据。平台站点访问服务凭据不提供用户身份，不能替代该连接流程。

批准的设备令牌初始有效期为 90 天，可从同一站点撤销。桌面凭据使用 Windows 当前用户的受保护存储，与词库可同步内容分开。离线模式不发起连接、查询或同步，已保存内容继续学习。

当前实现使用 Windows 当前用户 DPAPI，密文按站点 origin 摘要保存到数据目录的独立 `credentials` 子目录，不进入词库或同步资料。Tauri 状态只返回请求标识、设备、连接码和账号范围，不返回令牌。HTTP 客户端不跟随重定向，凭据不发送到不同 origin。失去响应后可用已保存的同一请求重试；较旧的异步结果不能覆盖新连接请求。真实用户尚未批准的连接只能显示 pending，不能据平台所有者权限自动构造身份。

已实现路由为 `/api/desktop/requests`、`/api/desktop/requests/:id`、`/api/desktop/requests/:id/approve`、`/api/desktop/status`、`/api/desktop/connections` 及撤销入口。本站的真实匿名检查确认首页和连接页为 200，个人词库和连接管理为 401；这些证据不代表批准后的真实用户数据交换已经通过。

## 3 数据协议

采用版本化 JSON 词条资料包，保留关联实体的稳定标识。一个资料包包含该词条的完整相关记录，原声字节单独传输。资料包覆盖以下实体，与 SQLite 相同的关系规则对齐：

| 部分 | 数据与约束 |
| --- | --- |
| entry | 类型、原文、匹配键、修订与创建时间；不同类型和显式分开的含义不盲目合并 |
| meanings | 所有释义与原始标识、来源及修订 |
| sources / examples / entryExamples | 已收录例句所需来源、原句、位置、时间、语境释义及关联；不包含素材路径或未收录对白 |
| media / exampleMedia | 原声摘要、格式、时长、资料标识及对应例句；无本机路径 |
| collectionActions | 原明确收录事件与发生时间；拉取或重放不产生新的主动行为 |
| units / attempts / corrections | 独立维度、范围、原回答、提示、答案依据、原判分、修正及策略版本；历史不可静默覆写 |
| states | 当前安排与策略状态；应用学习事件后重算核对，不能靠远端状态清空本地历史 |

当前共享契约位于 `protocol/svl-sync-1.json`：外层为 schemaVersion、deleted、entry、tables，关联字段沿用 SQLite 的 snake_case，覆盖 12 类实体。分段传输不修改这个完整业务包；它只改变 HTTP 传输和站点内部的快照存放方式。两端逐项检查字段和关系，禁止漏段或带入运行时路径。

## 4 变更、幂等与冲突

以下队列、应用与冲突流程已由桌面和站点实现，服务端基准版本、回执、事务及历史保留通过本地契约检查。真实通过范围与余项见第 6 节。

本地业务修改和待同步事件在同一事务保存。每次待推送资料包有稳定 changeId、摘要、远端基准版本；回执丢失后保持同一内容重试。站点按真实用户、changeId 去重，同一标识的不同内容返回冲突。远端资料包修订使用基准版本条件更新，变更与回执通过 D1 batch 原子提交，不依赖先读后写的客户端时间覆盖。

`/api/svl/v1/changes` 按账号范围的稳定游标返回增量和实体版本。桌面只有在内容、原声和映射已持久化后推进游标；中途失败仍可重放。站点已有词库逐用户建立稳定映射和完整资料包，既有词条不会在每次拉取时生成新标识。旧接口的新收录、修改与移除也需要进入变更流。

两端修改同一资料包时，保存远端和本地版本并显示差异。追加的不同例句、原声和学习事件按稳定标识、来源位置及摘要合并；同一字段的不同修改、身份映射歧义或同一不可变事件的不同内容要求明确处理。合并结果作为新的修改提交，保留判分和修正历史。原声不可用不伪称完整同步成功。

网站移除保存完整 tombstone，不能静默删除桌面的例句、原声或学习记录。桌面保留待确认版本，由用户选择归档或恢复；此规则不引入新的备份导出功能。

### 4.1 笔记本同步实现

schema 5 新增业务变更标记、按站点 origin 与真实账号组合键隔离的资料包基准、冻结发送队列和冲突。收录、编辑、作答、人工修正及已收录来源归档与变更标记在同一事务提交；准备发送时按账号基准产生稳定 changeId 与完整快照。已发送请求失去回执时，先重试同一内容，再发送期间新增的修改。

0.8.10 在短读取阶段仅收集待映射／冻结的标识，随后每个词条分别建立映射并冻结资料包；词条之间释放业务数据库连接并检查取消。每份包的当前 epoch、基准版本、完整内容和 changeId 在该词条事务内确定；已提交的包不因后续本地编辑改写。发送队列按原创建顺序一次读取一份 pending 包，网络收发在数据库锁外执行。保持完整资料协议与原回执／冲突处理，不宣称并行同步或固定响应时间。

拉取使用实体别名映射，覆盖关联外键、含 `:ctx:` 的语境键、题目及收录结果内的实体引用。来源、同句、同释义、学习范围和相同原声复用已有实体；不调用收录命令来导入历史，因此不产生额外主动收录。原声摘要通过后持久化，结构与映射通过事务保存，之后推进游标。失败保留原游标；已保存资料再次重放不会增加计数。

按最近共同资料包执行字段与新增实体合并。原收录、回答与修正不可覆盖；独立新增内容保留，两端同时改写的文字要求选择。复习状态按原事件重算；未发生本地业务修改时，不把重算导致的投影版本变化再回推成新学习事件。同形词匹配要求用户选择合并或独立保存，未选择前不自动发布重复词条。

网站移除采用保留完整资料的 tombstone。桌面收到移除后必须明确选择归档或恢复；归档仅从词库与复习列表隐藏，不删除释义、例句、原声或学习历史。网络失败、取消和冲突不宣称完整同步成功。

桌面增加 sync_start、sync_status、sync_conflicts、sync_resolve。处理请求含展示时的远端版本、当前本地版本及目标版本，变化时要求刷新。凭据不进入状态或前端；网络不跟随重定向，连接或离线设置变化时停止继续交换。站点同 changeId 的并发请求需在 D1 同一事务内占用回执，再按请求摘要和词条标识写入，避免“末端返回冲突但已产生另一条记录”的竞态。

网页旧词库接口改为读取完整资料包；旧表保留作迁移来源。新收录、追加语境、释义纠正、移除、原声关联和人工学习结果修正均进入同一资料包变更流。界面显示全部释义、例句、原声和历史；版本冲突保留输入并要求重新打开。

### 4.2 同步增长控制（0.8.14）

0.8.14 阶段的 svl-sync-1／assessment-1 继续发送完整业务资料；0.8.15 差量上传扩展见 4.3。桌面先按账号、实体和已确认远端版本核对变更元数据；相同或更早版本已持久化时直接推进该条通知的游标，不再次下载、反序列化和应用整包。未知或更新版本仍完成原声核对、完整保存与冲突流程后推进。SyncResult.pulled 继续表示处理过的变更通知数，包含这些已确认版本，不能作为实际下载包数。

sync_outbox 的 pending／conflict 内容保持原样；成功回执已更新 sync_documents 基准后，在同一事务将 sent 的 payload_json 释放为 {}。用户明确处理冲突后，superseded 的旧包同样释放。每次同步按当前账号、每批最多 50 条清理历史 sent／superseded 的冗余副本，批间释放连接并检查取消。changeId、实体、原基准版本、epoch、状态和时间继续保留；词条、例句、原声、作答、修正、报告及当前完整同步基准不在清理范围内。释放空间由 SQLite 后续复用，不自动执行 VACUUM，也不保证现有数据库文件立即缩小。

水平测试使用 schema 10 的会话变更计数和账号摘要缓存，具体字段与触发范围唯一维护在[数据模型第 12 节](data-model.md#12-同步增长元数据schema-10)。状态读取仅刷新变更计数不匹配的会话，缓存来自完整包的原摘要和待解析引用数；未变化会话只读取元数据。旧库升级后首次按原完整资料核对摘要，后续不再随每次状态读取重建全部历史。数据库中的事实及关联变化使缓存失效，缓存命中不等同网络确认。

HTTP 发送先读取待核对会话标识，再逐会话冻结／发送，一次持有一份完整测试包；待确认的冻结包优先复用，不因期间的新修改替换原 changeId 或内容。词条历史行按主键建立查找索引，测试报告按本机槽位建立索引，保持原实体别名与旧报告内容，避免逐条扫描整个基准。

同一次同步中，相同摘要／格式的原声只准备和提交一次；HTTP 对已经 HEAD 核实或获得有效上传回执的媒体，在本次连接对象内复用确认结果，覆盖词条与测试会话。新的一次同步仍核对服务器状态，不用永久本地缓存假定远端文件存在。所有业务历史继续完整保留，真实变更的完整包仍会包含此前历史；8 MiB 完整包与 20 MiB 原声限制保持，超限保留资料并报告，尚未实现无限历史容量或跨版本差量传输。

本轮最小本地证据见[性能与隔离记录第 14 节](../testing/performance-results.md#14-0814-同步资料包与历史增长控制)，不替代真实站点网络验收。

### 4.3 实际变更差量上传（0.8.15）

FR-12／FR-23、NFR-02／NFR-03。共享 [json-delta-1 契约](../../protocol/svl-delta-1.json) 是可选传输编码，完整 svl-sync-1／assessment-1 仍是冻结请求、基准、业务校验和站点存储依据。站点 account 声明 bundleDelta=json-delta-1 后，桌面按当前账号、实体标识及 push.baseRevision 读取已确认完整基准。无能力、首次发送、基准不匹配或差量不比完整请求小时，沿用完整传输。

差量包含 changeId、baseRevision、entryId／sessionId 与 delta={protocol,ops}。JSON Pointer 路径指向 bundle；set 更新值或增加对象成员，remove 删除对象成员，splice 按顺序替换数组片段。未变化行作为锚点，UUID 排序的历史中间新增也不会使后续历史全部重发；等长变化片段继续比较字段。未提及的例句、原声描述、题目、作答和旧报告全部保留。新生成报告仍作为完整新成果发送，原报告文本及其摘要不改写。

站点从同账号、同实体、同版本的当前或历史快照补回完整包，再进入原 writeSnapshot／writeAssessment：完整字段关系、原声存在、旧历史保持、条件版本更新、回执和游标的原规则继续适用。回执摘要仍根据还原后的完整逻辑请求计算，不根据线上编码计算。同一冻结变更可在响应未知后重新编码重试，历史基准可用于原回执核对；明确返回 412／delta_base_missing 时，桌面用原 changeId、baseRevision 和完整内容重试。

大差量复用 chunks-1；完整逻辑请求仍受原容量限制，差量不用于绕过容量或删除历史。读取基准后释放数据库连接再执行网络，业务库无新增迁移，仍为 schema 10。首次接收与更新下载继续使用完整快照；本次减少桌面实际变更上传量，没有改变远端历史快照增长或完整包导出成本。

本地正常链路及站点发布身份记录在[性能与隔离记录第 15 节](../testing/performance-results.md#15-0815-实际变更差量上传)。本地合成身份与隔离 SQLite 不代替真实账号同步验收。

### 4.4 已有确认基准的差量下载（0.8.16）

FR-12／FR-23、NFR-02／NFR-03。站点在 account 中增加 bundleDeltaDownload=json-delta-1 能力。桌面同时核对既有 chunks-1 参数后，按当前账号和变更实体读取最新已确认的 remote_revision／完整 base_json；有基准时对变更详情 GET 发送 x-svl-delta=json-delta-1 与 x-svl-base-revision。站点词条、会话详情 GET 也支持相同请求头；未主动协商的网页和旧设备保持原完整响应。

站点按账号、实体和基准版本读取当前或历史完整快照，比较目标版本，返回保留原元数据的 {baseRevision,delta}；目标始终是该游标对应的版本，不替换为最新版本。差量不比完整响应小、无有效基准或未协商时，返回原 bundle／packetRef。差量只包含变更字段、新行及数组片段，旧例句、题目、作答、修正和报告在基准中保留；新报告仍作为完整新成果发送。

内联上限沿用 996,904 字节。大差量保存为账号隔离、按摘要寻址的派生传输对象，返回 deltaRef={digest,size,parts}；沿用已有 500,000 字节分片端点和 8 MiB 容量。桌面先完整下载并核对分片和总摘要，再把差量应用到读取时固定的确认基准，核对 baseRevision、实体和目标版本、完整大小，生成原 RemoteDocument／AssessmentDocument。差量不会直接应用到本地当前业务行，也不替换冻结的本地待发送请求。

还原后的完整资料继续执行原字段关系校验、原声核对／保存、三方合并或冲突保留，成功持久化基准后才推进对应游标。sync_documents 与 assessment_sync_state 仍存完整基准，业务表、原声和历史不裁剪，schema 仍为 10。下载阶段数据库连接在网络请求前释放；服务端仍需读取和比较完整快照，本次减少传输量，不声明消除了完整导出／比较或远端快照增长。

### 4.5 服务端检查点与已校验差量复用（0.8.17）

### 4.6 本地完整会话复用与短事务（0.8.19）

FR-12、FR-23、NFR-02／NFR-03。状态刷新与冻结发送共用完整会话准备流程。读取当前事实及报告后结束读取事务并释放业务连接，在锁外计算完整摘要，再用短事务核对 epoch 并发布缓存元数据；期间资料已变化则重新准备。完成会话先按 0.8.18 规则复用或生成业务报告，确保状态与发送使用相同资料依据。

### 4.7 减少派生写提交与接收重复处理（0.8.20）

FR-12、FR-23、NFR-02／NFR-03。针对 0.8.19 正常样本中总耗时未下降，保留锁外完整摘要与编码，减少两类额外工作：

1. 最近完整快照命中时只读取并核对 epoch，不创建空读取事务。需要构建时，报告当前位置、摘要到本地报告槽位的映射及首次设备标识先暂存，与摘要发布共用一个写事务；相同设置值不重写。读取阶段若确实产生新业务报告，仍必须提交该报告，不把真实历史当作可丢缓存。
2. 回执按原 changeId 保存完整基准；只有当前 epoch 与缓存匹配、缓存摘要又等于冻结 pending 摘要时，才在同一事务推进缓存计数。若发送后本地已经变化，不将后续事实误认为已确认。内存快照仍受原 epoch 核对约束。
3. 接收先完整校验远端包，并在锁外编码基准。已确认且本地未变时无需导出本地资料或解码旧完整基准；需要比较／合并时，旧基准只解码一次供导出和合并共用。经过完整校验的输入／合并／保留副本不再在应用入口重复校验同一包。
4. 应用、原声文件核对、不可变历史保存、报告内容判定和完整投影重建仍在同一接收事务。重建直接复用已解码的远端文档作为新基准，不再读取并解析刚保存的 JSON；最终缓存摘要根据实际保存的本地完整资料计算，不用远端摘要冒充本地结果。合并了本地追加事实时仍待上传，冲突仍保存双方完整资料。

增加 assessment.write_commit 记录上述会话操作中实际进入写提交范围的次数及耗时；读取提交仅在有行变化时记录，缓存命中无提交。该标记既不包含全应用所有事务，也不等于磁盘 fsync 次数。assessment.receive_encode 与 assessment.base_decode 分离编码及基准读取／解码范围。原有固定标签、默认关闭与隐私边界保持。

单条正常往返及与上次同范围样本的比较见[性能记录第 21 节](../testing/performance-results.md#21-0820-额外写提交与接收重复处理)。保留完整例句、原声、原回答、修正及全部旧报告；没有站点、协议、IPC 或 schema 变更，也不以一次本地样本声明长期或真实网络性能达标。

## 5 原声与授权隔离

使用 Sites 托管 R2 保存原声，D1 保存媒体归属和元数据。上传与下载均核对已批准的账号或真实浏览器登录，对象键按账号范围及内容摘要构建。上传校验字节摘要、长度和类型；重复上传复用同一资料，未完成媒体不能作为资料包成功引用。下载保存到应用管理媒体目录，再按既有摘要与文件规则核对。

单个账号的游标、映射、回执和媒体不得跨账号复用。切换连接不会把已知游标当作新账号已经处理；每个账号保留其同步状态，本地核心不要求在线身份。

原有单请求上限 1,000,000 字节、内联资料包上限 996,904 字节保持兼容；桌面发送小请求使用 996,000 字节的保守上限。更大的冻结请求支持最多 8 MiB，业务快照预留 4096 字节封装空间，按 500,000 字节分片传输。超限仍明确失败并保留完整本地资料，不截断历史。原声单文件上限仍为 20 MiB；JSON 快照字符串长度仍按 JavaScript UTF-16 单元校验。一次拉取达到批次上限时保存游标并返回尚未完成，不能显示全部成功。

### 5.1 大资料包传输与存储

`GET /api/svl/v1/account` 声明 `packetTransport=chunks-1`、`packetChunkBytes=500000` 和 `maxPacketBytes=8388608`。新桌面先核对能力；较旧站点不支持时保留超限请求，不盲目改写字段或切换协议。

| 路由与资料 | 约束 |
| --- | --- |
| `HEAD/PUT /api/svl/v1/packets/:digest/:index` | 已批准账号隔离的上传暂存；PUT 为 octet-stream，提供分片 SHA256。HEAD 返回既有分片摘要与长度，断线重试复用同一冻结请求的已上传分片 |
| `PUT /api/svl/v1/entries/:id` | 小包继续直接发送；大包发送 `{packetRef:{digest,size,parts}}`。服务端组装完整请求、验证总摘要及字段关系后才提交版本、回执和变更；不完整分片不创建成功词条 |
| `GET /api/svl/v1/changes/:cursor`、`GET /api/svl/v1/entries/:id` | 设备的大快照响应返回 packetRef，桌面取得全部页并核对长度、摘要和词条标识后再应用；浏览器获取完整 bundle |
| `GET /api/svl/v1/packets/:digest/:index` | 账号隔离的已提交快照页；传输中断、坏页和摘要错误不推进游标 |

原有小快照继续存于 D1。大快照按内容摘要存入 R2；D1 保存 entry、deleted、摘要引用和词库列表摘要，保留原先查询、版本、回执与游标的事务规则。先写不可变完整快照，再提交 D1 引用；存储失败不提交半份资料。列表文字是预览，详情与同步保持全部记录。已完成传输删除上传分片；未完成的分片可供冻结请求重试。旧版本快照和 tombstone 继续保留历史。

此分工避免完整长历史触及 D1 的单字符串/行 2,000,000 字节限制，依据[官方限额](https://developers.cloudflare.com/d1/platform/limits/)；使用已有 R2 绑定与其[分段读取接口](https://developers.cloudflare.com/r2/api/workers/workers-api-reference/)，没有新增身份、存储服务或数据库迁移。桌面的 `sync_transport.rs` 管理 HTTP 边界和分片；`sync_http.rs` 保持连接校验、取消与应用编排职责。

网页历史按时间倒序，每页渲染 20 条；翻页和判分修正保留全部事件，修正后留在当前页。新请求替换旧详情或关闭窗口后，过时的异步加载不追加到其他词条的界面。
