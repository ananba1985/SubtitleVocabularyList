## 1 目标与范围

用户在其他应用的输入框中写好英文，选中一个句子，按专用快捷键。系统翻译为简体中文，并直接替换原应用中的这段英文，保留未选中的内容。正常流程无需切到单词本、复制译文或再次点击确认。

例如输入框包含 `Hi, Tom. I will arrive tomorrow. See you soon.`，用户只选中 `I will arrive tomorrow.`，完成后为 `Hi, Tom. 我明天到。 See you soon.`。不会发送消息、提交表单或保存原应用文档；这些动作继续由用户完成。

首版只处理可核对选区和可编辑状态的文本控件、英语到简体中文、一次连续选区。只读网页、PDF 阅读选区、截图文字、多处不连续选区不自动回填。中文转英文、自动润色、全篇改写、OCR 回填和通用应用兼容另行规划。

这是主动写作动作，已掌握词筛选不阻止翻译。翻译、替换均不自动收录生词，不增加复习成绩，不发起站点同步。

## 2 用户流程与入口

1. 用户在原应用选中英文句子。
2. 按“翻译并替换”快捷键；系统在原应用仍为前台时取得选区、控件身份和可编辑状态。
3. 从对应翻译缓存读取，缺失时调用本地模型；原应用继续保持焦点。
4. 取得完整中文译文后，再核对原窗口、控件、选区位置及选中文字。
5. 目标未变化时，只替换该选区，光标留在译文之后。用户需要恢复时使用原应用的撤销操作。
6. 用户切换输入框、移动光标、更改选区或输入内容时，不再自动回填；保留原文，提供译文供手动复制。

### 2.1 快捷键与设置

| 项目 | 首版设计 |
| --- | --- |
| 独立入口 | 新增“翻译并替换”，与 Alt+C 划词查询、Alt+E 截图、Alt+D 输入查询分别处理 |
| 建议默认值 | Ctrl+Alt+R；这是本项目提案，不宣称是 Pot 默认键，也不宣称已在本机注册成功 |
| 用户配置 | 主窗口“本地设置 → 快捷键”可修改或留空禁用；与现有三键不得相同 |
| 冲突 | 注册失败明确显示不可用；保留原设置，不退出或终止占用快捷键的其他程序 |
| 运行中再次触发 | 再按同一快捷键取消本次操作；按住产生的重复 keydown 不启动或取消多次；取消后可重新选句再触发 |
| 服务选择 | “翻译并替换 → 翻译服务”默认本地模型，可明确选择已启用且支持整段翻译的单个服务；词典结果不能回填 |

本次需求没有指定按键组合，Ctrl+Alt+R 是可调整的建议。该入口只在应用运行或用户选择常驻时可用；不会修改原有关闭主窗口的退出设置。

### 2.2 反馈与窗口

正常过程只提供不抢焦点的轻量状态：“正在翻译，再按快捷键取消”；成功后短暂显示“已替换，可在原应用撤销”。提示不固定占用主窗口页面，也不逐项写入后台任务历史。

替换被取消或目标不可核对时显示简短原因。已有译文可通过提示中的“查看译文”打开现有查询小窗，用户自行复制；该入口不延迟执行之前的自动写入。等待期间不主动显示查询小窗，以免改变焦点和选区。

## 3 业务规则

| 编号 | 规则 |
| --- | --- |
| REP-01 | 快捷键表示授权替换当前选区，正常流程不重复请求确认；不代表授权修改整篇内容 |
| REP-02 | 选区必须非空、连续且来自可编辑的非密码控件；不能确认目标时停止自动替换 |
| REP-03 | 替换身份包含原窗口、焦点控件和选区范围，不能只按“选中文字相同”判断，避免替换另一处同名句子 |
| REP-04 | 校验失败、翻译失败或用户取消发生在写入前时，原文不变；进入写入阶段后不得自动再次粘贴 |
| REP-05 | 只使用一次请求的完整、有效译文；流式片段、模型说明、空结果或错误响应不能替换原文 |
| REP-06 | 只替换选中内容；不采用全选、重设整个输入框、搜索替换所有相同句子或发送 Enter 的方式 |
| REP-07 | 原文边界空白保留；译文不附加标题、引号、解释、词典说明或未经请求的例句 |
| REP-08 | 用户继续输入、改变选区或切换前台目标后，本次自动写入失效；不抢回原窗口或重新选择旧文字 |
| REP-09 | 复用本地翻译及共享模型并发许可；本地失败不自动转发外部服务。明确选择外部服务时，沿用联网与手动离线规则 |
| REP-10 | 不自动收录、同步或持久化原应用编辑流水；原文恢复依赖目标应用撤销，不能假设所有编辑器均支持一次 Ctrl+Z 恢复 |

## 4 技术设计

### 4.1 当前代码与新增分工

0.5.0 的 `windows_native.rs` 已有前台来源及选中文字读取，`desktop_capture.rs` 处理三组快捷键，`queries.rs` 提供整段翻译、缓存和服务适配，`model_gate.rs` 提供共享许可。现有划词流程还会建立学习来源、套用熟词筛选并显示查询小窗，不能直接把它当作替换流程。

拟新增 `native_replacement.rs` 管理原生替换操作，在 ARC-02 内负责采集与回填；ARC-09 复用翻译执行和缓存，ARC-06 保持本地模型调用。无需新增桌面框架或另一套翻译服务注册表。

| 分工 | 职责 |
| --- | --- |
| NativeDesktop | 注册第四个快捷键、读取即时前台来源、分派开始／取消 |
| NativeReplacement | UI Automation 目标核对、单操作生命周期、回填与结果核对 |
| QueryRuntime／模型许可 | 单服务、translate 模式、精确缓存、取消及交互优先；不改变查询小窗或监听的当前会话 |
| ClipboardWatcher | 排除本程序为回填临时写入及恢复的剪贴板变化，避免自触发翻译 |
| 本地设置／状态提示 | 快捷键和单服务选择；不激活的状态提示及手动查看结果 |

替换请求使用独立 owner，原生目标对象仅由 Rust 工作线程管理，不向网页传递可任意使用的窗口句柄或写入地址。

### 4.2 原生目标采集

取得 UI Automation 焦点元素、所属 HWND／进程、RuntimeId、一个非空 TextRange，以及原始文本。通过只读属性、文本属性和控件能力确认可编辑；密码控件、属性未知或范围不可比较时不自动写入。保存原始范围克隆，并使用端点比较核对位置；原文保留原样，不以清洗后的词条文本作为写入依据。

UI Automation 的 Text／TextRange 能读取选区及位置，但不是通用的“替换选区”接口；TextPattern 同样可出现在只读内容中。因此获取文字成功不等于可编辑，也不采用 ValuePattern.SetValue 重写整个控件。[Microsoft Text and TextRange](https://learn.microsoft.com/en-us/windows/win32/winauto/uiauto-implementingtextandtextrange)、[CompareEndpoints](https://learn.microsoft.com/en-us/windows/win32/api/uiautomationclient/nf-uiautomationclient-iuiautomationtextrange-compareendpoints)

初版目标为能完成上述核对的普通桌面编辑控件。浏览器 textarea／contenteditable、富文本编辑器和其他输入框是否支持，需要真实样本后登记；本设计不预填兼容结论。现有 Alt+C 的读取支持范围不自动等于回填支持范围。

### 4.3 翻译执行

固定 `mode=translate`、`sourceLanguage=en`、`targetLanguage=zh-CN`，使用选中的单个提供商。将完整选中句子作为翻译输入，不读取或发送整篇文档、窗口标题或其他输入框内容。输入上限沿用查询核心的 4000 字符，超限说明原因，不截断后覆盖原选区。

复用按文本、模式、语言、服务配置区分的 `query_results`；不拿单词解释 meaning 代替句子 translation，不因仅命中旧 explain 缓存就跳过整段翻译。保留首尾空白用于回填；模型只翻译句子正文，缓存仍按实际规范化输入区分。已有有效缓存可离线使用。

完整响应有效且含中文译文时才准备写入；英文人名、缩写及数字可保留，不能用“每个字符必须中文”作为判断。无法取得有效译文时给出原因，不用提示文本覆盖原句。首版不增加静默外网兜底或无限重试，显式重新触发必须重新采集当前选区。

建议操作总期限 60 秒，包含排队和请求等待；这是实现参数提案，沿用现有网络请求量级，不作为已测性能承诺。取消或到期释放查询订阅，完成之后的旧结果不能再次取得回填权。

### 4.4 回填与剪贴板

首选受控的一次粘贴：保留当前剪贴板数据对象，在原目标仍为前台且快捷键修饰键已释放时，临时写入 Unicode 译文，再核对选区，发送一次 Ctrl+V。只粘贴纯文本，不发送 Enter／Ctrl+Enter，不操作发送、提交或保存按钮。等待修饰键释放时不强制释放用户按住的其他按键。

剪贴板对象的保留及恢复需在原生原型中验证，可采用 Windows OLE 数据对象能力；若不能保留原有数据格式，则不声称可以无损恢复，不先清空剪贴板。通过剪贴板序号判断是否仍由本操作持有：粘贴已被目标读取且核对完成后才恢复；用户期间复制了新内容时不覆盖它。临时写入和恢复都加入 ClipboardWatcher 的自身操作排除。

不以固定睡眠时间代表目标已读取剪贴板。无法核对读取／回填完成时保留译文和原始剪贴板对象供本次收尾，显示“回填结果待核对”，不提前恢复导致目标粘贴旧内容，也不自动重试。原型如不能完成可靠的读取、写入与恢复闭环，应先缩小支持控件范围，再明确调整设计。[Microsoft Using the Clipboard](https://learn.microsoft.com/en-us/windows/win32/dataxchg/using-the-clipboard)

回填使用目标应用自身的编辑路径以便保留撤销能力，但一次 Ctrl+Z 是否完整恢复、选区内样式如何变化需按目标样本核对；首版提供纯文本替换，不承诺富文本样式逐项保持。

Windows SendInput 受 UIPI 权限限制，且返回值仅说明输入事件是否插入，不证明目标文本已替换。普通权限下不能据此保证写入管理员程序；不自动请求提升权限，也不把事件发送成功写成替换成功。[Microsoft SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput)

Windows 跨应用的目标核对与键盘输入不是一个原子事务。实施时在写入前紧邻核对窗口、焦点、选区端点和原文，并监听目标变化；不能据此宣传零竞态或全应用安全回填。UI Automation 或编辑器无法提供可验证目标时，走手动查看译文。

### 4.5 生命周期与重复触发

| 状态 | 条件与动作 |
| --- | --- |
| capturing | 从当前原应用读取可编辑选区；失败时结束，不打开其他窗口改变采集目标 |
| translating | 读缓存或调用服务；可取消；目标变化后永久失去本次自动回填资格 |
| validating | 完整译文返回后重新核对原目标；不重新选择已丢失的选区 |
| applying | 一次性取得回填权，最多发送一次编辑动作；此阶段不接受可导致二次写入的重试 |
| replaced | 从目标读取并核对选区对应位置的译文后才标记成功 |
| result_only | 有译文但目标已变化或不支持；仅供用户手动查看／复制 |
| unverified | 编辑动作已发送，无法确认最终内容；提示用户核对，不自动撤销或再次粘贴 |
| cancelled／failed | 无回填或已在写入前中止，保留必要原因；迟到结果不能变更终态或写入 |

同一时刻仅一个替换操作。operationId 和完成状态由原生侧持有；热键取消、窗口变化、退出和迟到回调都核对该标识。进入 applying 后取消只能停止后续动作，不能承诺撤销已经发生的编辑，也不能把实际已替换记录成“原文未变”。

退出应用取消尚未回填的请求，清理本次剪贴板资源；重启不恢复或自动执行旧操作。不安装长期键盘记录，不保存逐键输入。

## 6 开发安排与验收

本次仅设计和文档。后续获得实施指令后，按 M-14 顺序完成：

1. 在一个普通可编辑控件核对原生读取、范围定位、一次纯文本编辑、剪贴板收尾及原应用撤销；确定首个支持目标。
2. 接入现有 translate 服务、缓存、模型许可和取消；建立独立替换生命周期，不改变查询小窗会话或后台任务页面。
3. 接入可配置的第四快捷键、单服务选择及轻量提示；更新接口实际字段和支持范围。
4. 执行 TC-48 的一个真实正常流程，记录源文、选区、实际译文、未选内容及撤销结果，再交付源码和文档。

TC-48 最小正常样本使用一处已支持输入框中的 `Hi, Tom. I will arrive tomorrow. See you soon.`：只选中中间句并触发，确认中文只替换该句、两侧文本保持、无需切换窗口、不会自动发送；使用目标应用标准撤销恢复原句。非目标业务数据库不增加词条或同步记录。

焦点竞态、用户期间复制、只读／密码／管理员窗口、服务失败及浏览器／富文本兼容等是需要遵守的实现规则和待核对边界；本次没有运行这些测试。扩大兼容矩阵、故障注入、压力或持续监听检查需提前取得用户明确授权，不能根据此计划自动执行。
