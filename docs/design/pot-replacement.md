## 1 目标与范围

用户希望用 SubtitleVocabularyList 替代本机 Pot。此增量补齐独立翻译小窗、划词／OCR 自动翻译、剪贴板监听、多服务查询和插件扩展。查词可以独立完成，只有用户明确收录时才进入原有词条、例句、原声合并流程。

现有取词、OCR、Qwen 解释、Windows 英语语音、词库、原声和托盘继续复用。默认快捷键沿用 Alt+C、Alt+E、Alt+D；自定义键和全局已掌握筛选保持。本设计不改变主窗口默认完全退出的规则，用户选择常驻时才在关闭主窗口后保持服务。

这里定义后续方案，不表示已实现新窗口、监听器、服务配置或插件运行。Pot 的 [使用指南](https://pot-app.com/docs/) 和 [快捷键说明](https://pot-app.com/docs/config/hotkey.html) 用于使用方式对照；不承诺现有 Pot 插件直接兼容。

## 2 功能与交互设计

### 2.1 FR-14 独立翻译小窗

小窗与主窗口、收录确认窗口分别管理。只查词时不打开主窗口，也不增加词条或学习记录。

| 元素 | 默认行为 |
| --- | --- |
| 原文输入 | Alt+D 打开后获得焦点；已有查询时可修改，Enter 查询，Shift+Enter 换行；输入法组合中的 Enter 不提交 |
| 结果区 | 单词显示中文词义、原句译文与用法，句子显示译文；原文始终可核对 |
| 主要操作 | 查询／取消、朗读／停止、复制译文、收录；收录前继续核对类型、例句和合并目标 |
| 服务与选项 | 默认服务的结果优先显示，其他服务按需展开；服务配置与剪贴板开关收起，避免占据主要阅读区域 |
| 窗口关闭 | Esc 或关闭按钮隐藏小窗并取消本窗查询、停止播放；不等同于完全退出应用 |
| 窗口固定 | 提供固定开关；未固定时允许失焦隐藏，正在编辑或确认收录时不擅自丢弃草稿 |

初始尺寸建议 420×320 逻辑像素，允许调整；实际尺寸和位置受当前显示器工作区限制，靠近取词位置且不超出可见区域。该数值是初始布局提案，不是各屏幕均已验证的结果。多屏移除后重新计算可见位置。

复制译文是显式操作，不自动改写剪贴板。选择“收录”时以当前选择的完整服务结果准备草稿；取消收录不产生词条。已存在未保存的收录草稿时，沿用现有排队和确认规则，不覆盖旧草稿。

### 2.2 FR-15 划词／截图自动翻译

| 入口 | 处理顺序 |
| --- | --- |
| Alt+C | 保持原应用前台，读取并核对本次选区和可取得语境，再显示小窗、读缓存并查询缺失解释 |
| Alt+E | 先截取原桌面、显示选区，完成 OCR 后显示可编辑原文并自动查询；取消选区不查询 |
| Alt+D | 打开小窗输入原文；Enter 发起查询，不把每个键入字符都送往服务 |
| 托盘菜单 | 输入翻译与截图翻译进入同一会话流程，左键恢复主窗口、右键菜单习惯保持 |

自动查询默认只调用本机模型。模型不可用时小窗仍展示原文、已保存结果和重试操作，不自动转向外网。显式启用某个外部服务的自动查询后，才允许按其已声明的数据范围发送请求。

单词使用 explain 模式，包含目标与完整原句；OCR 的整段文字使用 translate 模式，不把第一行或第一个词冒充完整输入。修订 OCR 文字后由用户再次查询。沿用现有 4,000 字符目标和 20,000 字符语境上限；超限要求缩短或明确拆分，不静默截断。

自动采集沿用全局已掌握跳过规则；整句含有熟词不等于整句已掌握。用户主动在输入窗口查询已掌握词仍可得到结果，不改变掌握、主动收录次数或测验成绩。

### 2.3 FR-16 剪贴板监听

监听默认为关闭，由小窗或托盘中的“监听剪贴板”开关显式开启。状态在小窗和托盘可查看，不在词库、测验等页面展示全局横幅。应用重启后恢复为关闭，避免悄悄延续监听。

原生监听只读取新的纯文本变化；不在启动时翻译旧剪贴板，不读取文件、图像或富文本附件。暂定 300 ms 合并间隔，将连续复制合并为最新一次查询，空白、超限和相同规范化文本不重复发送。本间隔是可调整的初始参数。

默认每次替换小窗的当前查询，不自动拼接成长篇翻译。自己执行“复制译文”时标记相应剪贴板序号，避免把译文再次作为新输入。关闭监听立即停止接受新复制，取消该监听来源的待发及在途查询；关闭小窗只取消当前查询，显式开启的监听可在常驻期间继续，托盘保持开启标识。

查询成功结果默认可保存为本机查询缓存，不创建剪贴板流水历史、词条或同步变更；设置中允许关闭监听结果的持久化。开启监听时说明纯文本会被用于所选自动服务及本地缓存。被占用而读取失败时不使用旧文本冒充本次结果。

### 2.4 FR-17 多服务查询

先把现有 Qwen、词典查询和在线翻译整理成内置适配器，再增加用户配置的服务。用户可设置启用、默认、顺序和是否允许自动查询。

| 服务属性 | 初始设计 |
| --- | --- |
| capability | translation、dictionary；现有 OCR／speech 继续通过各自适配器工作 |
| networkScope | loopback 或 external；本地模式保持可离线，外部服务由明确查询或启用设置触发 |
| 查询输入 | 目标文字、源／目标语言；只有声明需要语境且用户允许的服务才收到原句；不发送截图、词库或历史 |
| 查询结果 | 服务标识、词义／译文、可选用法／读音、缓存来源、状态与错误；每个服务独立完成并显示 |
| 并发 | 本机模型遵守已保存的并发上限；外部服务按各自配置限制，不套用模型合批量 |

快的服务先显示，不等待所有结果；一个服务失败不清空其他有效结果。用户选择某个完整结果再收录；多个服务产生不同释义时不静默覆盖已确认词义。已有解释直接可用，模型或服务离线不使窗口重开后空白。

配置外部服务时展示地址及发送范围，凭据在本机受保护保存，不进入公开文件、日志或查询事件。外部自动查询默认关闭；手动离线设置优先禁止全部外网服务，不禁止回环模型。服务不可用时不自动新增提供商或上传更多资料。

### 2.5 FR-18 插件扩展

插件采用版本化能力接口，内置服务也遵循相同输入／输出模型。首批实现翻译和词典扩展；OCR、语音扩展沿用能力分类，另行安排，不以声明能力替代实际实现。

首批插件包采用声明式配置：manifest、可选图标、HTTP 请求模板及 JSON 响应字段映射。主程序负责执行请求、凭据引用、响应校验、超时和取消，不在首批运行任意 JavaScript、DLL 或外部程序。

manifest 至少包含 id、name、version、protocolVersion、minHostVersion、license、capabilities、allowedHosts 和配置字段定义。安装前显示提供者、能力和访问地址；启用、禁用、升级与卸载都通过服务设置执行。导入只允许规定的包内相对路径，配置不携带真实凭据。暂定使用项目独立的包规范，不直接执行 .potext。

禁用或卸载后不再分派新请求，在途请求取消或按已定义收尾结束；已有词条、原声和有效查询缓存保留，结果仍标记原服务。无法支持的协议版本或能力明确显示为不可用，不伪装成安装成功即可使用。

现有 Pot 插件的迁移先核对接口、许可和运行依赖，再选择重写适配器或薄兼容层。是否支持某个具体插件属于后续决策，不承诺完整兼容，也不建设插件市场。

## 3 运行结构与职责

| 模块 | 后续职责 | 复用基础 |
| --- | --- | --- |
| ARC-01 | 独立查询小窗、服务结果、显式收录和偏好入口 | React／Tauri 多窗口、现有收录确认 |
| ARC-02 | 保留原窗口取词，截图和剪贴板文本输入 | NativeDesktop、UI Automation、现有 OCR |
| 拟增 ARC-09 | 查询会话、请求版本、交互优先调度、服务注册和插件配置解析 | 现有 Application、ModelGate、取消机制 |
| ARC-06 | 模型、查询、语音适配器 | model_content、OnlineLookup、Windows TTS |

拟按 native capture → QuerySession → 缓存／ProviderRegistry → QueryResult → 小窗展示组织执行；点击收录后再进入 ARC-04。这里的模块和类型是提案，不是已经存在的代码。

主窗口未打开也能查词。窗口事件只用于通知，窗口重新显示后查询会话快照，不依赖曾收到的事件恢复结果。小窗关闭后仍保存有效缓存；未确认的查询不产生已收录词条。

## 4 会话、取消与进度

QuerySession 记录 sessionId、inputRevision、origin、target、context、mode 和语言；每次开始查询生成 queryId，各服务响应带 sessionId、inputRevision、queryId 和 providerId。只有全部匹配当前输入的结果进入当前窗口；迟到的旧结果可以按其原身份缓存，但不能覆盖新词。

状态按服务分别为 idle、queued、running、ready、failed、cancelled。编辑原文使旧查询失效，保留新输入；重新查询、切词或取消不会提交收录。相同完整输入／服务请求在途时合并订阅，窗口关闭解除其订阅，不取消其他窗口仍在使用的同一请求。

交互查询在下一可用模型许可中优先于后台中文准备；不终止已经执行的后台批次，不绕过用户并发配置。自动监听只保留最新未分派输入，避免大量旧复制排队。切换输入或关闭监听应解除等待，不能被等待中的后台任务长期锁住界面。

查词进度和错误留在小窗的相应服务内。正常查询、取消以及自动监听的重复失败不逐次写入后台任务历史；自动失败保留当前会话的最新原因及次数。剧集导入、整集中文准备和同步的任务规则保持。

## 5 数据设计与兼容

| 数据 | 存放与规则 |
| --- | --- |
| QuerySession | Rust 进程内；窗口快照包含当前完整有效结果，退出后释放，不保存剪贴板复制流水 |
| query_results（拟新增） | SQLite；身份包含精确目标、完整语境、mode、语言、providerId 和非敏感配置指纹；保存完整有效结果及服务来源 |
| 服务／插件配置 | settings 的独立键，记录非敏感选项、顺序、自动查询和 credentialRef；不混入已确认词义 |
| 服务凭据 | 主程序受保护存储，沿用 Windows DPAPI 方案；SQLite 只存引用，读取接口不返回完整凭据 |
| 监听状态 | 运行期；启动关闭，合并间隔等非敏感偏好可保存 |
| 用户词库 | 沿用现有表、合并与同步规则；查词缓存和完整插件配置不参与词库同步 |

现有 explanations 的目标／完整语境身份和已有资料保持；默认本地解释可直接复用并标记为已有资料。多服务结果写入新的缓存，不把不同服务强塞入旧唯一键，也不覆盖原解释。界面区分“当前服务缓存”和“已保存的本地解释”，不冒称旧记录由新服务生成。

插件升级或配置改变生成新配置指纹；旧缓存保持可读，不因达到固定数量阈值自动清空。只有格式完整且符合该能力校验的结果进入持久化，流式片段和失败结果不冒充有效译文。用户清理查询缓存时不删除词条例句、原声和学习历史。

新增表的 schema 版本在实施时递增并提交迁移；当前仍为 schema 6。本次文档不执行迁移。监听不保存缓存时仍可复用已有缓存，新结果仅驻留当前会话，确认收录后沿用正常持久化。

## 6 命令与事件提案

编号登记在 [接口契约](interfaces.md)，以下字段是设计提案，实施时由类型定义与必要验证落实。

| 命令 | 关键输入／输出与约束 |
| --- | --- |
| translation_session_open | origin、target、context、mode；返回 QuerySession，仅创建查询会话，不收录 |
| translation_query_start | sessionId、expectedInputRevision、providerIds；返回 queryId 与各服务状态；自动入口限于已启用的自动服务 |
| translation_session_get | sessionId；返回当前输入版本、状态、有效结果，不含凭据 |
| translation_query_cancel | sessionId、queryId；只取消相应查询订阅，不取消收录或其他窗口的请求 |
| clipboard_listener_set/get | 设置 enabled 或读取当前状态，返回运行期 enabled 和最近输入状态；关闭时取消监听来源请求 |
| providers_list/update | 返回非敏感配置；更新服务与自动范围，凭据提交后只返回引用／是否已配置 |
| plugin_install/remove | 用户选定包或 pluginId；返回版本、能力与启用状态，卸载保持业务资料 |

query_updated 事件只携带会话、输入版本、查询和服务标识以及状态，完整结果由 translation_session_get 读取。窗口间显式收录继续使用现有 collection_* 命令，不引入第二套收藏数据库。
