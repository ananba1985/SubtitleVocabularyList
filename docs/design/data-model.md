本模型将词条、语境、原声、主动收录和测验历史分别保存，支持多来源追加与重试去重。以下实体和约束是详细设计提案，实际表结构、索引和迁移在实施阶段形成并验证。

## 1 基础约定

| 内容 | 提议规则 |
| --- | --- |
| 标识 | 持久化实体采用应用生成的稳定 UUID；同步保留原标识或建立明确映射 |
| 文本 | 保留用户确认的原始文本；辅助规范键只用于查找候选匹配 |
| 类型 | 词条类型为 `word`、`phrase`、`sentence` |
| 时间 | 记录时间使用 UTC；对白位置用整数毫秒，采用起点包含、终点不包含的区间 |
| 版本 | 可编辑实体具有递增 `revision`，用于检测读后修改期间的冲突 |
| 去重 | 操作去重与内容去重分别处理；词条规范键不作为无条件唯一键 |

规范化提议包括 Unicode 规范化、边界空白清理和辅助大小写匹配。词形归并、缩写和同形异义判断属于候选匹配策略，保留原文且允许用户选定已有词条或另建词条。

## 2 词条与素材实体

| 实体 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `entries` 词条 | `id`、`kind`、`text`、`match_key`、`revision`、创建与更新时间 | 主键为 `id`；按类型和匹配键查找，允许用户保留不同含义或大小写对应的独立词条 |
| `meanings` 释义 | `id`、`entry_id`、释义文本、来源类型、`revision` | 属于一个词条；新增语境不能自动覆写已有释义 |
| `sources` 来源 | `id`、来源类型、显示名称、素材识别信息、可选原路径与时长 | 原路径为定位提示，移动原文件不使已收录资料失效 |
| `examples` 例句 | `id`、可空来源、位置键、原句、可选起止毫秒、修订信息 | 同一来源片段可被多个词条引用；没有自动来源时仍可保存用户补充句子 |
| `entry_examples` 词条例句关系 | `entry_id`、`example_id`、关联范围键、可选 `meaning_id`、本次语境释义、关联时间 | 按词条、例句、关联范围键唯一；同原句可有多条释义或解释，引用释义必须属于同一词条 |
| `occurrences` 来源出现 | `id`、`source_id`、位置键、候选匹配键、原始词形、可空 `entry_id` | 按来源、词或短语跨度及候选键去重；确认匹配后关联词条 |
| `candidate_decisions` 预习判断 | 来源、候选键、当前语境范围键、判断状态、更新时间 | 保存用户确认的出现位置或语境范围，不代表其他语境或全局掌握状态 |
| `explanations` 本地解释资料 | `target` 英文目标、`context` 完整原句、`meaning` 中文词义、`translation` 原句中文译文、`notes` 用法说明、模型地址与名称、生成时间 | schema 6；目标去除边界空白，与完整语境构成主键；模型是来源信息，更换模型不影响已有读取；保存无条数淘汰，不覆盖已有结果或人工词条资料 |

例句重复判断以来源与片段位置为主，并核对原句。相同句子来自另一集时仍保留另一条来源；同一来源的两个不同出现位置也保留。对来源不完整的输入，重复判断结果供用户确认。

字幕修订会更新已有片段或显式建立新版本，不能因为文本变化就把同一片段当成一次新的主动收录。一个片段内同一词多次出现时，用词或短语跨度区分出现记录，避免用例句数量代替出现次数。

schema 4 的关联范围键首先使用 meaning_id 或 entry；同一释义的不同解释按内容摘要追加范围后缀。它区分保存的语境，不增加新的调度维度；测验仍按 meaning_id 选择对应例句及原声。旧关联迁移时保留解释，关联排序时间使用原例句创建时间，不据此重建此前没有记录的精确确认时间。读取词条时原句去重，`contexts` 返回全部关联；旧 `contextMeaning` 兼容字段保留最早一条。

## 3 原声实体与文件

| 实体 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `media_assets` 音频资料 | `id`、来源片段与处理配置键、内容摘要、相对路径、音频类型、格式、时长、状态 | 已保存原声的状态为 `ready`；文件不可用时明确标记异常，不返回可播放的成功结果 |
| `example_media` 例句音频关系 | `example_id`、`asset_id`、来源位置 | 组合唯一；同一音频可被多个词条例句引用 |

系统语音兜底使用已安装的 Windows 英语语音即时朗读，并标识为 `system_tts`。0.1 不要求把每次合成结果保存为文件；已经保存的来源对白标识为 `original`。

音频目录由应用管理，数据库仅存相对定位和元数据。素材路径、来源和内容摘要具有不同用途：路径用于查找原文件，来源用于追溯，音频摘要用于重复文件识别。

准备音频前按来源片段及处理配置查找已保存且可用的资料，再核对内容；找到时直接复用，避免同一片段被反复编码产生重复副本。输入来源不同的相同音频也可按实际内容摘要复用，来源关系仍分别保留。

### 3.1 保存与中断恢复

1. 在本次操作的临时位置生成音频，核对可解码性与目标片段。
2. 将完整文件放入正式媒体目录；目标重复文件经核对后复用。
3. 在数据库事务中写入词条关系、例句、媒体引用及主动收录记录。
4. 事务提交后返回完整结果，并清理本次临时文件。

文件系统与数据库不组成一个原子事务。数据库回滚后留下的未引用文件按来源和引用情况清理；清理不能删除被其他例句引用的音频。重试使用同一操作标识查找已提交结果，恢复过程不重复计数。

存在来源音频但保存失败时，保留收录草稿供重试。若用户明确选择先收录文字，则记录无已保存原声的事实，之后补齐音频；不得静默把失败降为完整成功。

## 4 主动收录与幂等记录

`collection_actions` 记录 `operation_id`、请求摘要、词条、来源、行为类型、已提交结果和发生时间。`operation_id` 唯一，结果可用于同一操作的重试返回。

| 输入行为 | 处理规则 |
| --- | --- |
| 第一次明确确认收录 | 产生一次主动收录记录，保存或追加相关内容 |
| 同一确认操作重复提交 | 相同操作标识与请求摘要返回原结果，不增加次数 |
| 同一操作标识对应不同请求 | 返回冲突，要求新的操作标识或重新确认 |
| 用户之后再次明确收录 | 生成新操作标识；内容可能复用，但新增主动收录记录 |
| 导入解析或任务重试 | 更新来源与候选，不能冒充用户主动收录 |
| 同步拉取或重放 | 合并内容，保留既有行为来源；不能产生新的本地主动收录记录 |

影片来源出现次数从 `occurrences` 取得；划词与 OCR 的已知位置按已确认的来源和位置关联去重计算，不推断原窗口全文的词频。主动收录次数从已提交的用户行为取得。累计次数作为查询结果计算，避免把两个概念合并成一个计数字段。

采集片段再次确认时，如果原句相同则复用；用户修订原句时保留不同文字版本。当前使用位置键的 quote 后缀保存修订文字标识，出现计数归并回原位置，不因纠错虚增。系统语音是可重建缓存，不进入 original 类型的 media_assets 或原声同步关联。

## 5 学习与测验实体

| 实体 | 主要字段 | 关系与约束 |
| --- | --- | --- |
| `learning_units` 学习单元 | `id`、`entry_id`、释义范围键、能力维度 | 按词条、明确范围键和维度唯一；范围键非空，避免可空字段破坏唯一约束 |
| `review_attempts` 作答记录 | `id`、唯一提交操作标识、单元、题目快照、回答、提示、结果、判分来源、策略版本、调度前状态、时间 | 作答后保留题目与答案依据；播放次数不能自动变成正确结果 |
| `review_corrections` 判分修正 | `id`、原作答标识、前次结果版本、新结果、理由、时间 | 保留修正关系，重试同一修正不再次影响复习状态 |
| `review_states` 复习状态 | 单元标识、状态版本、算法标识与版本、算法状态、下一次时间 | 是有效测验结果的当前投影；与影响它的作答或修正一并提交 |
| `review_questions` 题目 | 单元、单元状态版本、私有答案快照、提示、音频准备、已提交作答与时间 | 出题只返回公开题面；提示与音频准备按题目关联，关闭未提交题目不形成作答 |

维度提议为词义 `meaning` 和听力 `listening`。短语用法困难可记录为专项原因及题目类型；是否单独形成调度维度属于 OPEN-03，本文不新增第三种必需复习维度。

自由浏览和预习熟悉判断不写入测验正确记录。已掌握词条再次主动收录时保留历史，并给相关学习单元设置重新复习的优先状态；具体下一次日期由复习策略决定。

判分修正后，应重新计算受影响单元的当前状态。如果后面已有新的测验，则从受影响作答前的状态边界，按有序记录及各次适用策略版本重算，不能只覆盖最后一次日期或静默改用当前参数。未改变的其他单元不受影响。

## 6 任务与同步实体

| 实体 | 主要字段 | 设计边界 |
| --- | --- | --- |
| `tasks` 任务 | `id`、启动操作标识、输入来源、类型、阶段、状态、进度、结果引用、错误、取消请求 | 业务后台执行和失败诊断持久化；preview/speech/review_audio/explanation 的正常执行与取消仅存内存回执；导入仍按素材保存阶段 |
| `sync_outbox` 待同步修改 | 变更标识、实体类型与标识、基准版本、变更内容、状态 | 与对应本地数据提交关联；字段范围必须受最终同步契约限制 |
| `sync_links` 远端映射 | 站点账号范围、远端标识、本地实体标识 | 将旧站点词键映射到本地稳定标识，避免重复拉取建立新词条 |
| `sync_state` 同步状态 | 账号范围、已确认游标、成功时间、冲突与失败概要 | 未应用的远端修改不能被当作游标已处理 |
| `sync_dirty_entries` 业务修改标记 | 词条标识、递增 epoch、修改时间 | 收录、编辑、作答、修正及已收录来源归档同事务更新；派生复习投影不产生新的业务修改 |
| `sync_documents` 账号资料基准 | 站点与账号范围、远端与本地词条、远端版本、共同资料包、已确认 epoch | 三方合并与发送确认的基准；同一实体可存在远端别名 |
| `sync_conflicts` 待确认版本 | 账号、远端/本地标识、远端版本、两份完整资料、原因与状态 | 保留文字冲突、同形词和移除选择；处理前核对展示版本 |

账号范围是已有站点认证与数据隔离所需的信息，不引入多用户协作功能。实际隔离键由站点 origin 与真实账号共同组成；协议、别名和保留完整资料的移除规则见[同步设计](synchronization.md)。`entries.archived` 只隐藏词库与复习列表，不删除原声和历史。发送队列包含账号与本地 epoch，冻结同一个 changeId 的内容，收到回执前不替换为更新后的快照。

任务执行标识与业务操作标识分别保存。同一业务操作失败后可建立新的执行尝试，但同一时刻只允许一个有效执行；已提交结果仍按业务操作标识去重，不能因重试任务换了标识而再次收录。

临时操作维持同进程操作标识的去重与取消，保留全部活跃执行及最多 64 条已结束回执；失败写入 tasks 后再返回失败终态。重启后正常临时回执无需恢复，已保存原声、释义、例句及测验记录独立保留。旧版正常临时记录仅从用户任务查询中排除，不删原库。此调整没有数据库 schema 变化，当前仍为 6。

explanation_batch 为持久化业务后台执行，聚合缺失的“目标+语境”项目，不创建逐词 tasks 行。result.preparation 保存生成/复用/中途跳过/失败数量、各来源处理量及最多 20 条失败样本；任务进度表示已处理项，不把失败数当作已获得解释。数据恢复以 explanations 是否存在为准，不依赖旧任务进度准确覆盖最后一次提交窗口。settings 的 explanation_preparation_enabled 保存用户暂停选择，默认启用；不可自动恢复错误的暂停标记与立即重试唤醒序号仅在本次运行内保存。临时请求失败在原 taskId 内等待，全部在途项目都等待时阶段为 retry_wait，不新增历史或增长已处理数；重开仍按库中缺失资料恢复，schema 保持 6。

settings 的 application JSON 包含 modelConcurrency（缺省 1）和 modelBatchSize（缺省 8），与其他偏好一起保存；请求许可、在途目标/语境集合和重试唤醒序号属于运行期状态。多个工作线程共享 explanations 的精确目标/原句身份，按现有 SQLite 规则保存；聚合任务快照只由协调线程更新，附带 concurrency/inFlight/waiting 数量，不增加逐工作线程 tasks 行，不改变 schema 6。modelBatchSize 由设置接口校验为 1～64 的整数，旧 JSON 缺省补 8；无需迁移或重写 explanations。

同句批量解释的共享 translation 按现有 explanations 目标/完整语境键与每项 meaning、notes 一起保存，不新增独立译句表，不覆盖旧资料。批量请求只保护运行期在途键；进度包含 batchesInFlight/batchSize 元数据，schema 仍为 6，确认词库与学习历史不受自动准备影响。

剧名和季集分组由 SourceSummary.title 派生，源标识、字幕/音轨版本、出处和原声关系保持原数据。分组与后台准备都复用 schema 6，没有新增季集元数据表或改变同步载荷；未收录语料的中文准备仍为本地资料。

### 6.1 本机已掌握筛选偏好

复用 settings 的独立命名空间 known_target:<kind>:<归一文本>，value_json 保存 kind、text、matchKey、markedAt。匹配与词条一致采用 NFKC、合并空白、小写；类型独立，词形和标点不猜测归并。此偏好允许尚未收录的熟词存在，不建立生词、释义、作答或测验掌握状态，不改变 schema 5。按前缀和归一文本查询管理页，候选过滤以键存在性判断，不删除 occurrences、例句或媒体。

新的有效收录与取消跳过标记在同一事务提交；缺失媒体、版本冲突等失败回滚保留偏好。已提交旧操作的幂等重试先返回回执，不撤销用户随后新建的跳过标记。该记录与本机模型/快捷键一样属于本地偏好，不进入当前站点词条资料包；词条例句、原声和测验学习记录的既有完整同步保持。

## 7 数据库实现约束

- 在数据库连接初始化时明确启用并检查外键；关系约束不能仅依靠界面校验。[SQLite 外键说明](https://www.sqlite.org/foreignkeys.html)
- 对唯一约束使用非空业务键；可空字段不能直接承担需要全局唯一的组合身份。[SQLite 建表说明](https://www.sqlite.org/lang_createtable.html)
- 按词条匹配、来源片段、到期学习单元、任务状态和待同步状态建立必要索引，先验证实际查询再扩展。
- 原声与关联写入、收录记录与次数、作答与复习状态分别采用一致的事务边界。
- 凭据与访问令牌不进入可同步的词库内容，具体本地凭据管理由同步适配设计确定。
- 数据迁移按版本执行并验证。0.1 不以新增用户可见备份导出功能替代迁移完整性要求。

### 7.1 本机听读练习（FR-13）

0.8.11 起 SQLite `settings` 分为 `practice_document` 与 `practice_progress` 两条记录。前者仅保存 PracticeDocument（标题／类型、完整章节原句、可选毫秒位置与原声相对路径）；后者保存 documentId、每章句数 chapterLengths 和 PracticeProgress（当前章句、输入草稿、速度、音频来源及声音标识）。导入时两条记录在同一事务提交；日常进度保存只读取小型进度记录，用章句数量检查位置，并只更新该记录，不读取或序列化完整正文。

旧 `practice` 合并记录在首次 practice_get 或进度保存时按同一事务拆分，两条新记录保存成功后移除旧键，保留原正文和全部进度字段；迁移只发生在听读功能内，不加入业务库启动条件。practice_get 仍向界面返回原 PracticeState 结构。当前阅读替换时保留已有业务资料，同一阅读重新导入复用来源和位置；先前页面的旧 documentId 更新不覆盖新阅读。业务 schema 保持 9，不为逐句输入创建任务或测验事件。

来源采用既有 `sources` 的 `reading` 类型，以标题、阅读类型与章节内容摘要复用；课程完整音轨复制到 `media/practice/{digest}.m4a`，只供当前本机阅读。章节和句子的位置键为 `practice:{chapter}:{sentence}`，用户收录时关联既有例句和来源。原声片段通过现有媒体保存流程独立保存，替换阅读和清理旧完整音轨不删除已收录片段。同步仅包含已确认收录的业务资料，排除完整阅读、草稿、声音与本机路径。

010_sync_growth.sql 增加以下本机元数据和查询索引，适用于 FR-12、FR-23、NFR-02／NFR-03；不改变 svl-sync-1／assessment-1 或任何已保存业务事实：

| 位置 | 字段与用途 |
| --- | --- |
| assessment_sync_dirty | 每个 session_id 的单调 epoch。迁移为现有会话建立初始标记，新会话由触发器建立；不保存或复制题目与历史 |
| assessment_sync_state | cached_epoch、cached_digest、cached_pending_references：对应完整资料的已计算摘要与引用数；remote_revision：已保存基准的远端修订，用于下载前核对 |

会话创建／更新，以及题目及交互、作答、修正、报告、收录关联的插入／更新／删除，在原事务中使会话标记变化；同步基准替换也使摘要失效。entries 别名变化会使相关收录会话及该账号含待解析引用的会话失效，以便重新核对远端引用。摘要刷新、基准回执和缓存失效分别记录，不能将一次本机缓存写入当作远端已确认。

status 只重建标记已变化的完整会话，按原 packet_digest 比较待同步状态。0.8.19 起读取完整事实后释放连接计算摘要，随后核对 epoch 并用短事务更新 cached_epoch／digest／引用数；过期结果不记为当前资料。Store 的最近一份内存完整快照按账号／会话／epoch 复用，业务变化或基准变化仍通过原触发器失效，不新增持久化完整副本。发送时已存在 pending_json 就继续使用同一冻结包，其间新事实在后续包中保留；新请求在锁外编码，提交前再次核对版本及同步状态。逐会话提交避免一次事务持有所有会话资料。旧 9 库升级初始化计数及远端修订，不删除原会话／报告；首次状态读取或同步会按需建立摘要缓存。

0.8.20 中，准备期间新算出的 assessment_current_report、assessment_report_slot 及首次同步设备标识先保存在本次准备的短期列表，与摘要在核对 epoch 后一并发布；设置值未变时不更新。真实缺少的报告仍在读取事务中插入并提交，已存在报告不因维护索引另行提交写入。首次设备标识若在锁外计算期间已由其他 Store 初始化，则重新准备，避免发布基于不同设备标识的摘要。

保存回执前，同一事务核对 pending_change_id、cached_epoch=当前 epoch、cached_digest=pending_digest；仅满足这些条件，才在保存完整 base_json、触发原基准变更计数后，将 cached_epoch 推进到新计数。pending 摘要不变，确认摘要仍来自原冻结包；其他事实或别名已经变化时不推进缓存，后续资料继续失效待重建。接收端仅在 cached_epoch=当前 epoch 且 cached_digest=acknowledged_digest 时跳过本地完整导出；应用后仍从实际业务行导出完整资料、计算摘要，并原子保存。表、触发器及 schema 10 不变。

词条 sync_outbox 的 payload_json 在 sent 或用户已处理完毕的 superseded 状态可改为 {}，保留原轻量回执字段；pending／conflict 仍保留完整请求。历史清理按账号分批执行，不删除业务历史或当前同步基准，不对数据库文件执行收缩。详细运行顺序见[同步设计 4.2](synchronization.md#42-同步增长控制0814)。

## 13 站点历史存储（0.8.17）

桌面 schema 仍为 10；此节仅定义站点 D1／R2 的内部编码，不改变完整词条／测试会话业务字段。共享字段见 [protocol/svl-history-1.json](../../protocol/svl-history-1.json)。svl_records／svl_assessment_records 与对应 changes 表的 payload_json 可保存带 history.version=1 的封装。外层保留词条 entry／deleted，或测试 protocol／sessionId，以及原列表 summary；列表筛选和分页无需还原历史。

history 保存 revision、baseRevision、depth、bundleBytes，以及 checkpoint 和／或 delta／deltaRef。首次写入、从旧格式继续写入，或达到 16 个版本的检查点周期时，保存原完整格式的 checkpoint；其他有收益的变更只保存已校验差量。depth 范围为 0～15；depth=0 必须有 checkpoint，其余版本按同账号、同实体、baseRevision 引用上一条 changes，严格核对修订与递减深度。检查点上也可保留相邻差量，以免该版本下载重新比较历史。

较大检查点沿用 R2 完整快照引用；较大差量沿用账号隔离、SHA256 寻址的 deltaRef。封装超过内联阈值时将较大部分移至 R2，避免把双份内联内容塞入一行。旧内联完整包和 packetRef 继续读取，旧行及原声对象不清理或改写。完整还原从最近检查点开始，最多应用 15 个差量；恢复流程原位应用已保存操作，不为链上每个版本再次克隆完整历史。

站点迁移 0003_sync_history 仅新增 svl_changes(user_id,entry_id,revision) 和 svl_assessment_changes(user_id,session_id,revision) 非唯一索引，避免基准查找扫描账号全部变更；不增加业务实体或删除历史。当前记录、变更封装、完整内容摘要、回执及游标仍通过原 D1 batch 条件事务提交。完整包读取可按需派生原 packetRef 供旧设备使用；这种投影及旧完整快照仍可能占用存储，本轮不执行对象垃圾回收。
