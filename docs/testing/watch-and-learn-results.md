## 1 本轮范围与环境

本轮交付用户指定的“内嵌播放 → 暂停读取已保存译文 → 完整译文绘制后 5 秒自动收录整句”。沿用 mpv 内置 OSC 和默认播放键位，不重做播放／进度／音量控件。未实施功能继续保留在计划中。

后续 0.10.0 本地文本双轨及对应中文复用另见[字幕增量记录](subtitle-import-results.md)。本文保留 0.9.0 历史执行范围，不把新证据补写成当时已实现。

- Windows 本机、Tauri／WebView2 开发程序、Vite `127.0.0.1:1420`，独立标识 `com.subtitlevocabularylist.watch.acceptance`。
- libmpv 固定构建 20261021，源码提交 `e471496c56`；DLL SHA256 `04e4d27dc385dc18ddd93fbe69c75e635b864f3c6ec53a9122df54c2f7842f4a`。动态资源位于忽略目录 `.tools/runtime/mpv`，准备脚本校验版本与摘要。
- 原生子 HWND＋OpenGL render API；全屏逻辑区域 1280×800，实际绘制缓冲 2560×1600。暂停中文为原生 ASS OSD。
- 合成绿色画面 `output/watch-and-learn-acceptance/positioned.mkv`，45 秒，H.264／AAC，带定位 ASS；首句 1–35 秒为 `I will arrive tomorrow.`，第二句 36–44 秒为 `Please wait for me.`。文件含测试音，**本轮播放器音量始终为 0**，未做真实对白听感验收。
- 隔离库为 `output/watch-and-learn-waiting/Data` 与本轮 `output/watch-and-learn-native/Data`；保留供人工检查。安装版 `D:\SubtitleVocabularyList` 的资料未修改，安装版进程未停止。

## 3 输入修正与证据边界

原问题为用户可见 OSC 但进度条／按钮无响应。宿主现以自身 client 坐标归一化，再映射 render 尺寸；按下时聚焦并捕获鼠标，抬起释放捕获，拖动结束可正常传给 mpv。宿主转发 mpv `mouse`、`keydown`／`keyup`，不实现第二套拖动逻辑。键盘释放传明确空字符串，避免固定版本 C `cmd_key` 对省略参数的空指针解引用。输入命令错误现在保留在当前播放器状态，不刷入后台任务历史。

Computer Use 已能发送真实鼠标／键盘，最终构建的输入结果由播放时钟和状态回读确认；没有用 IPC seek/play 冒充上述点击／拖动／Space。IPC 只用于隔离场景准备、静音与只读观测。调试期曾临时开启 mpv 日志及固定显示 OSC 以定位问题，最终版本已移除，恢复原生自动显示／隐藏。

本机 Computer Use 窗口捕获未包含 OpenGL 子窗口，截图中视频区域呈浅色；GL_FRONT 回读可见实际渲染的绿色画面、字幕及 OSC，用户较早已确认实际画面正常。两类证据分别记录，不把 GL 缓冲图当作本轮工具完整捕获了显示器画面。全屏还会返回两个 13×13 的附属截图，坐标操作须选择完整窗口截图；曾因误选附属截图而发生的工具越界不是播放器测试通过记录。

保留的本地诊断脚本及原始运行输出在 `output/playwright/watch-and-learn/`：`core-waiting.js`、`core-save.js`、`native-save-check.js`。`src-tauri/examples/watch_fixture.rs` 可为新的命名隔离目录建立同源索引和保存译文，不对既有测试库重复初始化。没有向公共仓库加入视频、用户数据库或模型资源。

## 5 0.11.0 后台开发增量

用户表示需要使用电脑、后续由人工操作验证后，已停止 Computer Use 输入与原生调试自动重启；没有再次打开播放器窗口或播放声音。本节为后台检查，不能冒充真实鼠标、画面、计时或听感验收。

代码接入：当前主／第二文字字幕优先、延后创建轻量来源、按当前音轨截取原声、独立 watch 查询 owner、按词／短语查询及缺句译文的流式补充，以及无文字时冻结帧 OCR、重框选和编辑核对。完整译文 ready 并实际绘制后才计时，部分输出不计时；OCR 核对前不计时，只有采集点则存文字。

### 5.1 最小后台正常结果

`watch_context_acceptance` 示例在 `output/watch-context-acceptance/Data-confirmed` 运行通过，使用静音合成视频及已知英文画面，没有打开原生窗口：

| 检查 | 实际结果 |
| --- | --- |
| 未导入视频 | 读取当前字幕上下文时来源和个人条目均为 0；收录时才绑定 video 来源；没有 corpus，预习剧集列表仍空，不冒充整片导入 |
| 精确原声 | 真实 FFmpeg 从选中流 1 截取，保存长度为 2000 ms，条目例句关联 1 项原声 |
| OCR 与核对后的收录 | 真实 Tesseract 将原文识别为 `| will arrive tomorrow.`；流程中明确更正首字母为 `I` 后保存；该例句起止均为空、无原声，保留单独采集位置标识 |
| 独立查询 | 当前 selection 会话在 watch 查询前后不变 |
| 真实本地 Qwen 流式查询 | `The train arrives at noon.`，`cacheSource=provider`，收到 4 次含文字的 running 预览，最终 ready 为 `火车中午到达。`；未使用模拟服务或预填查询结果 |
| 编译／契约 | `pnpm build`（IPC 签名／DTO、TypeScript、Vite）通过，Rust desktop 检查通过；schema 仍为 10 |

首次准备 OCR 样本时，输入侧 seek 使 ASS 滤镜时间从零开始，输出帧无字；调整为输出侧定位后，文件检查确认英文存在。随后 OCR 对首字母的正常误识别由核对步骤修正，不把文字准确率说成已校准。保留 `Data`、`Data-passing` 两个中途命名目录及最终 `Data-confirmed`，不覆盖旧验收库。

### 5.2 待人工操作

用户方便时再启动隔离开发程序，依次完成：

1. 打开未导入的 `output/subtitle-import-acceptance/bilingual.mkv`，暂停，核对当前英文；点一个词、选一个短语，确认释义及收录确认窗口。
2. 定位第二句 `Please wait for me.`，缺译文时点“翻译当前句”，确认逐步显示，完整显示后才开始 5 秒；快速继续不保存，保持暂停则保存。
3. 打开 `output/subtitle-import-acceptance/watch-hard-subtitle.mp4`，在英文出现时暂停，核对帧图，拖选重识别、纠正原文、确认再翻译；核对 OCR 只存文字，没有伪造原声。
4. 到单词本核对新词／已有词追加例句，试听真实原声；关闭、重开确认位置与其他学习会话保持。

两个素材均为短合成静音视频。此前 0.9.0 的真实 OSC、空格、显示后 5003 ms 等结果仍属原历史范围；本轮新增窗口交互、流式绘制后的实际计时、字幕延迟／速度及框选均待人工确认。音频互斥、在线字幕取得、人工音频区间编辑及发行材料仍待后续，不生成安装包。
