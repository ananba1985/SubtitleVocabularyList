## 1 背景、目标与决策状态

现有 SubtitleVocabularyList 已形成“观看／阅读素材 → 理解与收录 → 单词本 → 复习 → 服务器同步”的桌面学习流程。Android 客户端用于手机上的本地观剧、随手收录和碎片复习，并与现有服务器、Windows 客户端共享个人学习资料。

本次用户明确要求单词本、边看边播和单词本服务器同步。沿用现有命名，将“边看边播”统一表述为“边看边学”：在本应用内播放视频，暂停理解对白，并收录词语或整句。本文既定义手机收集入口，也覆盖客户端完整学习闭环。

用户随后认可本文并要求“按照这个 PRD”制定开发文档与计划，补充尽量复用桌面底层、降低维护难度。用户进一步要求按照计划完成客户端开发，本文 P0 据此作为首版实施基线，用户随后明确要求完成全部五项 P1，现按第 7 节实施。需求被认可不表示各项功能已经完成，验收以实际记录为准。

| AND-DEC-02 | 延续词条、释义、多例句、原声与学习历史的完整语义；所有入口共用相同合并规则 | 继承已确认产品规则 |
| AND-DEC-03 | 首期增加主动回忆测验、易忘词、离线查词、手动／分享取词和图片 OCR | 用户认可 PRD 后作为 P0 规划基线 |

目标是让手机独立完成已准备内容的离线学习，外出时继续桌面上的词库与复习，看到新内容时及时收录。不以运行桌面程序、开启模型服务或在线登录作为本地学习前提。

### 1.1 已确认的独立运行边界

用户进一步确认：手机与桌面各自独立运行，日常不直接连接，也不要求处于同一网络。代码复用只表示将同一业务实现编译到各自客户端；手机数据库、离线词库、OCR 引擎和识别资源均在手机本地。两端通过现有服务器同步，桌面关机不影响手机使用。手机不依赖桌面 Qwen、共享目录或电脑提供的运行服务；可选在线解释需使用手机自行配置并明确授权的服务。USB／开发服务器连接仅用于开发调试，不是正式运行依赖。

## 3 首版范围与后续边界

### 3.1 首版 P0

首版完成三条闭环：

1. 本地视频 → 暂停理解 → 收录词语／整句 → 保存原声 → 复习。
2. 其他应用分享文字／截图 → 核对查词 → 统一收录 → 服务器同步。
3. 服务器取得桌面词库与原声 → 离线浏览／测验／易忘词练习 → 学习记录回传。

第 6 节 AND-FR-01 至 AND-FR-16 及 AND-FR-22 为 P0 基线。AI 和外部查询是可选增强，服务不可用仍可使用已存内容、离线词典和人工输入。首期不要求自动生成整集翻译；本地播放、字幕读取／对齐、已存译文与按需补充必须有清楚入口。

### 3.2 建议后续 P1

第 7 节 AND-FR-17 至 AND-FR-21 为后续候选，不在首版放置无法使用的占位入口，也不先建设独立服务器、插件市场或内容生产平台。

### 3.3 当前不纳入

首期不提供在线视频平台／DRM 采集、任意应用悬浮翻译、系统级剪贴板监听、跨应用自动替换、整片离线转写、大模型随包运行、插件市场、社交协作、打卡排行榜、复杂标签统计和新的备份导出系统。远程视频串流、桌面素材自动传到手机、跨设备观看进度、完整课程同步也不属于现有词库同步范围。

## 4 用户流程与界面组织

### 4.1 边看边学

选择本地视频后直接播放，字幕来自可读内封轨或用户选定文件。暂停后显示同源当前对白与可用中文；缺中文可查词、手动补充或明确调用已配置服务，继续播放不必等待解释。字幕不可读但画面有字时，使用当前帧 OCR 并核对。

完整有效译文实际显示后开始默认 5 秒倒计时，达到时长自动收录整句；提前播放或选择“本次不收录”即取消。手动选词／短语／整句时，核对原文、释义、来源与原声后保存。收录不产生测验成绩，观看进度独立保存。

### 4.2 随手收录

在来源应用选中文字后选择本应用，或分享截图，进入可编辑查询／收录面板。允许不查询直接保存原文、稍后补义；缺上下文／链接时可补充，不猜测来源。查询本身不加入词库，确认后才持久保存并进入待同步。新输入不能覆盖未提交草稿。

### 4.3 离线复习与多端学习

用户批准连接现有账号后同步词库，查看文字与原声准备情况。离线可搜索、播放已下载原声，完成词义／听力测验与易忘词专项。作答、修正先保存手机；恢复允许网络后同步，桌面通过原流程取得手机学习记录。

### 4.4 建议导航

手机设“单词本、边看边学、复习、我的”四个主入口。查询与收录作为常用操作；易忘词放复习页，账号、同步、任务、离线资源与设置放“我的”。播放画面优先，暂停时展开学习面板；分别适配竖屏单手操作和横屏观看。P1 开启后再增加相应入口，不直接平移桌面十项侧栏。

## 5 数据归属与同步边界

### 5.1 沿用现有服务器和完整资料

服务器指现有英语练习站点及其同步服务，不另建手机专用词库。范围依据[主 PRD 的 FR-12](PRD.md#fr-12-在线单词本同步)和[同步设计](../design/synchronization.md)。接口、认证适配与能力协商进入后续设计，不能只接旧版“一个释义＋一个语境”的词库接口就宣称同步完成。

## 6 首版功能需求与验收标准（P0）

下列为首版需求基线，编号在后续设计和验收中保持稳定。现有需求映射见第 2 节，不改变 Windows 历史验收结论。

### AND-FR-01 单词本浏览、搜索与编辑

**需求**：离线浏览三种词条，按原文／已存释义搜索，查看全部语境、例句、来源、原声及学习记录，修改已有可编辑内容。

**验收标准**：三种条目重开后可搜索和查看；多义项、多例句及音频对应正确。已确认编辑持久保存并待同步，浏览不生成作答成绩。

### AND-FR-02 手动查询与确认收录

**需求**：输入／粘贴词、短语、句子，查询、编辑、朗读、复制后可明确收录。中文输入按既有规则取得英文译文，收录时核对英语目标。

**验收标准**：只查询／复制不新增词条；无模型时可保存原文及人工释义，缺项可见。确认前可核对类型、例句与来源，新分享不覆盖未提交草稿。

### AND-FR-03 统一合并与持久保存

**需求**：手动、分享、OCR、视频自动／手动收录与同步接收使用同一词库和历史规则。

**验收标准**：两个入口收录同一词的新例句后，旧例句、原声、成绩均保留；相同来源片段和同次操作不重复。主动再次收录沿用复习优先规则，同一暂停自动保存不累计主动遗忘次数。

### AND-FR-04 原声与离线英语朗读

**需求**：优先播放已保存对白，无原声时使用已准备的 Android 离线英语声音并标识来源；视频、原声、朗读与测验音频避免叠加。

**验收标准**：原视频移走后，独立原声仍离线可播；生成语音不标原声。缺英语声音时说明并提供准备入口，不阻碍文字学习；资源不可播放不计为听力答错。

### AND-FR-05 离线查词与可选服务

**需求**：优先读取已存解释与基础词库，区分词义与整句译文；新解释可由用户明确调用已配置、手机可访问的模型／查询服务，完整有效结果才可保存。

**验收标准**：离线词库命中不等待服务；缺中文可人工补义，不编造整句翻译。结果绑定原文与语境，旧响应不覆盖新输入；模型失败不自动改投外部服务。手机回环地址只指手机自身，不把桌面回环配置当作手机已可用配置。

### AND-FR-06 接收其他应用文字

**需求**：接收系统分享文本及来源应用提供的选中文字处理，只处理本次显式传入内容。

**验收标准**：从实际支持的来源应用分享后，可核对、编辑并收录；缺上下文／链接可补充，不伪造。没有选区菜单时分享／粘贴仍可用，不要求后台监听或无障碍权限。

### AND-FR-07 图片／截图离线 OCR

**需求**：选择或分享一张图片，裁剪英文区域，离线识别、编辑，再查询或收录。

**验收标准**：资源就绪后，断网可将字幕截图识别为可编辑文字并保存；可重新裁剪。取消不收录，不使用上次图片结果；图片不随词库同步，临时图像处理结束后清理。

### AND-FR-08 视频、字幕与来源管理

**需求**：通过文件选择、分享或打开方式取得本地视频；支持可读文本内封字幕与用户选择的外置中英字幕。当前来源跟随播放，必要字幕索引与对齐不阻碍播放，不以整集 AI 准备为前提。

**验收标准**：授权视频直接播放，字幕绑定当前文件；可靠中文按时间用于对应英文，不按行号硬拼。换集更新来源；素材不可访问时可重新选择，已收录内容保持。最低容器／编码／字幕支持集在设计中明确并以样本确认，不直接套用 Windows 矩阵。

### AND-FR-09 触屏播放与本机进度

**需求**：播放／暂停、停止、拖动定位、前后短跳、当前句重播、音量、倍速、音轨／字幕、英文默认、字幕偏移、横屏全屏、列表与可关闭连播均有可点击入口。

**验收标准**：播放不等待解释／同步。主动打开、选集或继续观看后恢复进度并播放，单纯启动／返回页面不自行开播。未手动选轨时优先英文，手动选轨／关闭按文件恢复；停止关闭视频、保留列表与进度。横竖切换保持资料和位置，不提交旧倒计时；切后台、锁屏或其他应用占用音频焦点时暂停，回来不自动恢复或收录。

### AND-FR-10 暂停对白、译文与帧 OCR

**需求**：主动暂停后先取当前字幕或同源可靠对白，显示已存中文／双语字幕或缺失状态，支持点词／选短语；无文字字幕时裁剪当前帧、OCR 并核对。

**验收标准**：原译文对应同一文件、字幕版本、偏移和时间；上一句需标识。缺译文可继续观看或按需补充，不自动排整集翻译。OCR 来源及时间精度明确，可纠错；跳转、换轨／文件后旧结果不回填新上下文。

### AND-FR-11 视频自动／手动收录与原声

**需求**：完整有效译文实际显示后默认 5 秒自动整句收录，可改时长、关闭／取消本次；手动词／短语／整句须确认。有可靠边界可截取原声，仅有帧位置则可人工调区间并试听或只存文字。

**验收标准**：读取、OCR、模型等待及未完整流式展示的时间不计入；满时长且仍为同一有效暂停才保存。提前播放、菜单／文件选择、手动草稿、编辑文字、离页、转后台、锁屏或换上下文取消原计时；回来不自行重启。OCR 未核对不自动保存；同源片段重开后仍去重，自动保存不冒充主动重复收录。已存原声脱离视频仍可播放。

### AND-FR-12 主动回忆与计划复习

**需求**：提供到期复习、词义回忆、听力识别、提示、判分及修正，沿用现有策略；模型是可选辅助。

**验收标准**：资源准备后断网完成两类题，作答前隐藏答案，听力题不泄露字幕。词义／听力分开保存；判分可查依据并修正，重开保持历史和安排。离线不能确定的回答列待确认，不强制等待模型；合并历史不重复记录同次作答。

### AND-FR-13 易忘词专项

**需求**：沿用现有进入／退出规则，显示原因和薄弱维度，以已有例句、原声练习。

**验收标准**：符合规则的词可见并能专项测验；作答进入正常历史并同步，看过答案不自动掌握。模型不可用仍能练习，不另造手机阈值或积分。

### AND-FR-14 双向完整同步

**需求**：交换完整词库、原声与学习历史，支持首次取得、离线改动回传、其他端更新，沿用现有增量、完整回退、去重及冲突语义。

**验收标准**：真实账号下完成“Windows→服务器→手机”和“手机收录／测验→服务器→Windows”，均能看例句、播放原声并看到历史。显示文字／媒体／待传／冲突状态及上次完成时间；手动同步可用，连接时可自主开启自动同步，开启后在回到前台或本地保存后合并触发，不依赖后台永久运行。离线先保存，恢复允许连接后继续；重试不重复计数，同字段冲突可处理。手动离线禁止同步；原声走移动网络前说明数据量并取得用户允许，或等待 Wi-Fi 且显示未完成。超限保留完整资料并说明，不能截断内容换取成功。

### AND-FR-15 真实账号与设备授权

**需求**：复用现有账号与设备批准流程，显示手机设备名和核对信息，受保护保存凭据，可断开、重新授权；离线学习无需登录。

**验收标准**：在真实账号页面批准后回到手机确认绑定，未批准不取得个人资料。令牌不进词库、分享、日志或界面；撤销／失效不丢本地内容，重新连接遵守账号归属。手机浏览器批准与回到客户端需实际证据，不以模拟令牌代替。

### AND-FR-16 任务、设置与资源状态

**需求**：必要的导入、OCR、下载、同步任务可跟踪、取消／重试；提供手动离线、同步、播放学习设置及离线资源状态。退出或系统回收后已提交资料保持，未完事项可识别。

**验收标准**：任务有对象和状态，已保存结果不因返回键／取消丢失。重开仍有已提交词条、媒体和作答，未完成不假报成功；可查看原声／词库／OCR／声音是否可用。缓存清理不误删个人原声和历史。

### AND-FR-22 同账号共享已准备剧集资料

**需求**：电脑已准备好的剧集字幕、原文／译文、时间与偏移、视频指纹及准备版本，经现有服务器供同账号手机下载复用。客户端独立工作，不要求电脑开机、同一网络或手机直连电脑。不自动传输视频文件，也不要求手机重新生成整集译文。

**验收标准**：桌面上传后退出，手机同账号取得资料并匹配手机本地同版视频，暂停显示对应原译文。资料版本与视频匹配明确，更新不破坏已收录例句、原声与作答；资料未取得时本地学习仍可用。0.25.0 正常发布／下载、离线复用和更新保持通过，见 [剧集共享验证](../testing/prepared-episode-results.md)。

### 9.2 实施顺序

先制定 Android 架构和必要适配设计，明确数据、文件访问、凭据、播放器、字幕／帧与原声处理。既有 Windows 决策不自动成为 Android 已确认选型；复用合并、复习和同步语义，Windows 窗口、语音、凭据与播放宿主需适配，不能移动界面就视为移植完成。

建议先交付“单词本＋完整同步＋原声／复习”，再交付“播放＋暂停学习＋收录”，最后接通“分享／图片 OCR”和必要设置，完成 P0。P0 收尾后用户另行授权 P1，阶段 AND-M-10 至 14 见专项计划。开发计划、工期与应用版本在设计后确定；本次文档不触发应用版本递增、打包或发布。

具体源码复用、平台接口和实施顺序已编入 [Android 架构](../design/android-architecture.md)、[开发指南](../development/android-development.md)及[开发计划](../planning/android-development-plan.md)。这些文件分别维护设计、阶段状态及实际验证结果，P1 的实现与服务验证边界、条件发布仍单列。
