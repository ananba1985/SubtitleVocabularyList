## 1 范围与查询顺序

基础词库是独立的只读参考资料，不自动加入生词本、学习记录或同步载荷。保留既有人工收录内容和已保存解释。词语查询先复用已保存解释，再依次查 Google 高频词头、Google 词形映射、ECDICT 词头、ECDICT 词形映射，均未命中才调用本地 AI。Google 的词形命中也优先于 ECDICT 的直接词头命中。有效中文释义命中后直接返回，不能为了重复生成通用释义调用模型。

后台准备在排队时排除底库命中的词语，执行时再次复用本地结果；手动解释和 Qwen 词语查询也走同一读取逻辑。完整句子译文独立准备；选区翻译替换和明确的整句翻译模式仍使用既有翻译流程。词典通用释义不标成当前对白中的特定含义。

## 2 来源与文件

中文释义优先采用 `chenny/english-word-10000` 的 `english-word-10000.md`，锁定提交 `a3bfa2903a2cbbbeb8cd3df5a3f6003578b08f8b`。按用户追加授权，后备采用 ECDICT 同一固定提交 `bc015ed2e24a7abef49fc6dbbb7fe32c1dadaf8b` 的 `ecdict.csv` 基础版全部有效中文词条，并复用 `lemma.en.txt` 和 CSV 的明确 exchange 词形。不通过模型翻译词表。

原始文件、下载 URL、提交和 SHA-256 保存在 `Data/dictionaries/sources/`。本地转换输出 Google 的 `Data/dictionaries/base.sqlite3` 和 ECDICT 的 `Data/dictionaries/ecdict.sqlite3`，与业务库 `vocabulary.sqlite3` 分离。导入工具只解析 Markdown、CSV 和词形文本，不执行第三方 SQL。第三方数据不提交公开仓库，本轮用户授权用于本机资料；公开捆绑仍需独立核对数据再分发许可。

## 3 数据与运行方式

底库 schema 1：`dictionary_entries` 保存规范化词头、中文释义、英美音标、词性、频率排名；`dictionary_aliases` 保存表层词形到词头的映射；`metadata` 保存来源信息。只收录含中文释义的词条；一个词形对应多个词头时不自行猜义，不计为词形命中。精确词头优先于别名。

Store 打开时只读加载 Google 小词表为内存索引；ECDICT 保留只读 SQLite 连接，使用词头和词形索引按需查询，不在启动时把全部大词典加载入内存。查询不产生模型请求，notes 标注命中的实际词典。没有底库时保持原流程。更换或首次准备底库后重新打开程序加载。业务 schema 保持 8，不迁移或改写用户词条。`explanation_get.meaningScope` 使用 `dictionary`，小窗结果使用 `cacheSource=dictionary` 区分模型结果。

## 4 统计与最小验证

统计只读快照中有语料文件、未归档例句所对应的 `(kind, candidate_key)`，跨集去重；Google 直接、Google 词形、ECDICT 直接补充、ECDICT 词形补充及均未命中五类互斥且合计为候选总数。未命中不直接等于实际 AI 请求量：须进一步扣除已保存词义和已掌握词语。整句译文和 HTTP 请求数不混入词语覆盖数。

最小正常验证覆盖：底库精确与词形查询、后台排队排除、手动解释与小窗返回、未命中沿用模型、原语境解释与句子译文保持。只使用合成资料及本机一次只读匹配，不启动全量模型任务、不打包。

实际覆盖数、来源校验和本地准备命令见[结果记录](../testing/base-dictionary-results.md)。
