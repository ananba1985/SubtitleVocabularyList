## 1 目标与现状

导入剧集时尽量取得同一版本的英文、中文字幕，已有中文优先用于暂停翻译，减少本地模型整句翻译负担。导入只建立学习资料，不将整集对白加入个人单词本；译文显示后 5 秒的收录规则不变。

0.10.0 在原英文导入路径外增加 `subtitles.rs`：取得全部可转换的内置文本轨及同名分语言外置字幕，保存原资产，按时间读取当前中文并补齐缺失句缓存。0.12.0 接入图片轨原资产；0.13.0 接入 `online_subtitles.rs` 的 SubDL 官方 API 适配、文件核对、人工偏移及来源记录。已有来源、例句、个人词库、学习记录及自动回执保持。证据分别见[本地字幕验证](../testing/subtitle-import-results.md)及[在线字幕数据验证](../testing/online-subtitle-results.md)；未配置真实服务，不把本地字幕包通过写成网络流程通过。

## 2 取得流程

1. 探测视频全部字幕轨及本地同名外置字幕，分别识别英语、中文、双语与未知语言；保留轨道语言、标题、格式和原文件。
2. 解析文件名中的剧名、年份、季／集（S01E02、1x02、中文季集），结合容器标题形成可编辑的检索条件。多集文件、名称冲突或季集缺失时由用户核对，不将首个搜索结果直接视为匹配。
3. 本地已具备可靠中英字幕时直接使用；缺少语言且用户已启用、配置在线字幕服务时，按文件名／剧集信息补查缺失语言。服务未配置时提供一次入口，不阻塞本地导入与观看。
4. 展示候选的语言、季集、发行版本、帧率和来源。媒体摘要、同一发行版本、时长与字幕时间共同参与匹配；名称相同不代表时间轴相同。冲突保留候选，确认后再导入。
5. 建立独立字幕资产和对齐映射，准备可复用的当前句中文资料；未匹配部分才进入原后台本地模型队列。

## 3 轨道、对齐与译文优先级

英文学习对白为规范时间轴；原始 ASS／SSA 样式和定位、PGS 图片轨独立保留供播放器显示。解析后的标准 cue 与原字幕资产关联，不用转出的纯 SRT 覆盖原字幕。

按实际时间重叠形成一对一、一对多或多对一映射，不能按行号直接拼接。内嵌双语的同一 cue 可拆分中英文，同时保留原始内容。时间偏移、不同剪辑版或帧率变换必须有明确依据；无法可靠对应的中文不作为已匹配译文。图片字幕需要识别后核对，不因存在中文轨就声称已获得可用文字。

暂停当前句的使用顺序为：用户修正内容 → 已核对对齐的中文原字幕 → 原有有效缓存译文 → 对缺项进行后台本地模型补充。不同来源保留原出处、版本和修订关系；不将下载字幕假标为模型生成，也不覆盖用户修改。暂停读取已准备资料，不默认重新请求模型。

给已导入剧集补中文字幕时保留英文来源及 cue 标识、个人例句、音频、学习历史和自动收录回执。仅更新字幕资产、对齐结果及缺失译文，避免整集重建造成重复收录。

## 4 数据与任务

| 对象 | 需要保留的信息 |
| --- | --- |
| 字幕资产 | 媒体／来源 ID、语言与双语标识、原格式、轨道号或服务文件 ID、来源 URL、文件摘要、发行版本、帧率、相对 Data 路径、取得时间 |
| 标准 cue | 资产与原 cue 标识、起止时间、原始文本、规范文本、原字幕定位引用 |
| 对齐映射 | 英文 cue ID 集合、中文 cue ID 集合、有效偏移、对齐依据／状态及版本 |
| 当前句中文 | 原句、完整中文、来源类型／引用、用户修订标记及关联版本；复用现有译文读取接口 |

本地实现保存在 `Data/subtitles/<媒体 SHA256>/`。原轨按 ASS／SRT／VTT 保存，标准 cue 与语言、来源、轨号、摘要及中文选择写入 `bundle-<来源摘要>.json`；`settings` 的 `subtitles:<sourceId>` 只保存相对路径，schema 仍为 10。原 ASS 样式与定位不改写，学习文本去除 FFmpeg 转出时保留的 ASS 控制标记。0.12.0 增加 PGS 原 SUP、DVD／DVB 原 MKS 资产复制，cue 为空且不可选为直接中文来源，明确提示需播放暂停后 OCR 核对；该图片轨导出分支尚待实际样本确认。

本轮时间匹配允许分句不同：计算中文 cue 对英文区间的覆盖并合并中文；总覆盖至少 65%，单个重叠至少为 `min(较短区间时长, max(80ms, 较短区间时长/5))`，排除容器轻微时间偏移造成的下一句边缘重叠。参数是初始实现值，未进行准确率校准，不代表所有发行版本均可靠对齐。每份资产保存 `timeOffsetMs`，正数延后中文，允许 ±1 小时，不改写原始字幕；不自动做帧率变换或把不同剪辑版强行对齐。

已选择的原字幕中文优先于旧句缓存；保存字幕只为缺失句缓存新增记录，不覆盖旧值。沿用缓存字段时以 `model_url=subtitle://<资产ID>`、`model_name=中文字幕` 明示出处，不假称模型生成。用户可在“学习设置”选中文来源或继续用旧缓存，选择持久保存，切换后旧暂停计时失效并重新确认显示。偏移更新优先资产的读取结果，不重写已有通用句缓存；这是保留既有译文的边界。CMD-72 至 CMD-74 读取资产、取得本地字幕和保存中文选择，CMD-75 至 CMD-83 见[接口契约](interfaces.md#26-本地中英字幕命令)。

在线资产增加 `provenance`：提供方、来源 URL、文件候选标识、剧名／季集、发行名称、帧率、取得时间及已核对标记。原文件复制到同一媒体目录，SHA-256 保留；下载暂存位于 `Data/cache/subtitle-download/<下载标识>`，包内路径不会直接成为落盘路径。补充本地字幕时合并已确认在线资产，保留中文选择及偏移，不重建英文例句。

检索、下载和确认导入各显示一个聚合任务，沿用任务取消和进度，不按字幕行生成历史。下载内容可离线预览／确认。搜索失败保留已取得的候选及错误摘要；本地导入不因在线失败被撤销。HTTP 状态和服务错误会显示，未实际验证认证／额度错误，不声称已覆盖所有错误分支。

## 5 在线服务边界

0.13.0 首个适配器采用 SubDL v1：`https://api.subdl.com/api/v1/subtitles`。按语言分别检索，使用名称或用户确认的 `sd_id`、年份、季集、语言、`subs_per_page=30`、`releases=1`、`unpack=1` 和官方 `client=custom_integration`；不调用云端 AI。多部同名结果须先选片再查询；候选对应官方返回的第一部影片，不静默把其他标题的字幕当作匹配。仅发送检索条件和必要服务凭据，不发送本机完整路径、视频、音频或个人词库。

“本地设置 → 在线字幕服务 · SubDL”独立配置，默认关闭；API key 沿用当前 Data 的凭据加密保存，不回传明文。启用“导入时自动检索缺失语言”即授权导入后的补查，默认也关闭；自动检索不自动下载／采用候选。英语／中文服务代码默认 EN／ZH，可调整；官方语言表链接当前未能取得，ZH 的真实服务接受情况须在配置账号后确认。

下载只接受服务缓存候选的 `https://dl.subdl.com/subtitle/...`，不接受前端任意地址；重定向仅跟随同主机 HTTPS，凭据不发给其他域名。连接超时 5 秒、总请求 30 秒，搜索响应上限 2 MiB，下载 16 MiB；ZIP 最多 128 项，仅提取 SRT／ASS／SSA／VTT，单文件 16 MiB、合计 64 MiB。多个文件不自动采用首项。确认前展示实际解析文字、时间、对应英文样例；已知季集冲突或超出视频时长提示换候选／调整偏移。只有用户确认版本及时间后才持久导入，不据时间重叠率声称版本已被自动验证。

2026-10-21 已核对的候选资料：

- [SubDL 官方 API 文档](https://subdl.com/api-doc)：本次 v1 适配依据；尚未配置账号、请求真实候选或验证 HTTP 下载。提供方当前限额、配额和语言代码须在实际服务中确认。
- [OpenSubtitles 官方 API 使用说明](https://blog.opensubtitles.com/opensubtitles/how-to-build-a-movie-subtitle-finder-cli-with-python-and-the-opensubtitles-api)：提供文件名／媒体摘要检索等能力；需按官方要求配置认证和下载权限。采用现代 `.com` API，不采用已公告终止的旧 `.org` XML-RPC 接口。

未配置服务不影响核心离线功能。在线取得失败不能改为未经授权的云端翻译，也不冒充取得成功。

## 6 最小验收与开放项

M-25 本地文本正常路径见 TC-65；M-26／27 下载后 ZIP 解析、版本预览、来源导入、偏移持久化、补充本地字幕后保留在线资产，以及旧缓存和个人词条保持，已通过一个无网络正常检查。见[增量证据及人工步骤](../testing/online-subtitle-results.md)。该检查不代替 TC-66 的真实官方搜索／下载，也不代替新增窗口及播放画面确认。

2026-10-21 用户明确接受结束本轮，真实网络、图片轨和新增窗口的未实测范围不再作为开发阻塞；已有记录保持事实，日后问题按 bug 修复。API key 是使用在线服务时的本地配置，不再要求先配置才能结束开发。字幕候选的下载采用仍由用户核对，这项产品行为不因开发结案而改变。原暂停学习闭环与播放器常规功能继续沿用 mpv。
