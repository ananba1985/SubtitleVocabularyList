## 1 样本与参考目标

Windows 11 x64 26100、AMD Ryzen 7 8845HS、8 核 16 线程，系统报告物理内存 66345938944 bytes。资源为已经实际安装的 FFmpeg/ffprobe、Whisper base.en；本地解释使用现有 127.0.0.1:8096 的 Qwen3.5-9B。仅向本机发送自编句子，没有触发外部查询、同步或界面输入。

本轮工程参考目标限定在这个硬件和素材：

| 观察项 | 参考目标 | 职责边界 |
| --- | --- | --- |
| 1000 条词库、后台导入/解释时读取 40 条词条 | P95 ≤100 ms、采样最大值 ≤500 ms | 只测正式核心返回，完整 GUI 响应另行验证 |
| 18.021 秒无字幕素材的本地处理 | 用时不超过素材时长 | 不把短片段推广为全部剧集、设备或编码的承诺 |
| 单个自编语境的本机解释 | ≤15 秒 | 已运行的模型服务，未计模型服务启动或首次权重加载 |
| 本机模型不可连接 | 明确失败；已保存词库、手动收录与基础测验继续可用 | 验证依赖失败隔离，不停用户的模型服务 |

这些数值是按已有原型样本制定的工程基准，不改变 PRD 中后台可观察、可取消和本地可用的业务需求，不声明所有设备的性能保证。GUI、完整任务取消响应和其他素材仍保留验收状态。

## 2 实际执行

原生 `core_workflow_probe` 使用正式 Application、Store 和 TaskManager：准备全新词库，然后并行执行 speech 导入和本地解释，期间每 50 ms 后再次读取词库。Python 用 Windows Toolhelp/进程计数接口观察这个进程及其子进程，并单独观察已知模型监听进程；没有读取进程内存内容或终止共享模型。

首轮无例句的 1000 条样本完成工作流并写入 UTF-8 报告，但打印中文时被系统 cp1252 编码拒绝；将控制台 JSON 改为 ASCII 转义后独立重跑通过。随后补测每条词条都有一条不同自编例句的样本，避免把无语境查询当作全部词库性能。

| 项目 | 无例句独立重跑 | 每条有例句 |
| --- | --- | --- |
| 词条数 / 读取样本 | 1000 / 110 | 1000 / 103 |
| 读取 P95 | 13.168 ms | 18.123 ms |
| 读取采样最大值 | 20.392 ms | 26.511 ms |
| 本地转写导入 | 6657 ms | 6603 ms |
| Qwen 解释 | 6253 ms | 6234 ms |
| 返回释义 | 不情愿的；勉强的 | 不情愿的；勉强的 |
| 主工作流进程组采样 working set 最大值 | 354050048 bytes | 351424512 bytes |
| 主工作流进程组采样 private bytes 最大值 | 841785344 bytes | 838971392 bytes |
| 模型服务采样 working set 最大值 | 5977444352 bytes | 5977632768 bytes |
| 模型服务采样 private bytes 最大值 | 8535453696 bytes | 8535519232 bytes |

进程观察每次采样后等待 100 ms，另有枚举/计数开销；这里只报告采样最大值。private bytes 与 working set 含义不同，不相加作为“占用内存”；没有测 GPU 内存。含词库创建、测量与收尾的总墙钟分别为 11990 ms、12103 ms。

两个样本满足上述核心参考目标。它们是小规模实测，不把采样 P95 当作长期统计 SLO，不把核心读取速度当作已测 GUI 绘制时间。

## 3 模型失败后的业务结果

在独立测试实例中将模型地址设为不可连接的 127.0.0.1:1，正式解释任务 failed、错误为 provider_unavailable。已有词库仍可读取；手动收录 manual-fallback 成功；已有学习单元的词义题独立答对，得到 correct。测试没有停止原模型服务，也没有修改用户设置或正式词库。

这补充 TC-21/41 的模型依赖不可连接场景，不声称用户服务已被实际停止；查询、同步各自的失败证据继续引用其对应模块记录。

## 5 实装 WebView 补充样本

在同一实装私有程序中，通过正式收录接口加入 1000 条各有例句的合成词条，原有两条测试词、原声和学习记录保留。1002 条词库下同时启动新的 18 秒 WebM 本地转写及新的回环 Qwen 解释，从实际 WebView 连续读取 40 条词条并采样 requestAnimationFrame。

218 次读取的 P95 为 21.9 ms、最大 34.1 ms；1079 个帧间隔的 P95 为 8.5 ms、最大 16.6 ms。转写 6492 ms、解释 7348 ms，均成功。采样时文档可见但没有键盘焦点，帧间隔不冒充用户点击到结果显示的延迟，也不作为全部机器或负载的保证。随后实际打开词库，40 条分页列表可用。

未切换正在使用的收录草稿，直到用户明确回复已试用完。原始结果为上述离线验证目录的 gui-performance-response.json。1000 条合成词经公共合并/提交路径生成，没有直接写入伪造业务数据。

该压力准备还发现旧未结束任务会被最近 30 条任务挤出的问题；已修正列表包含全部未结束任务，门控回归保留运行、取消中状态及完成后的历史上限。这同时保护退出时对未结束任务的取消。

## 6 开发启动扫描瓶颈与修复

2026-10-08，NFR-03、TC-40，交付版本 0.1.4。用户的新日志显示 setup/数据库/服务约 0.5 秒，但内容加载开始约 21.8 秒、完成约 32 秒，另有 26.5 秒代码编译。前一轮只补加载反馈，未解决实际延迟；本轮使用独立 `.local/startup-validation` 词库、真实 Tauri/WebView2、Vite 请求耗时和浏览器 Navigation/Resource Timing 定位，不使用合成 IPC。

基线开发服务没有排除原生构建和私有工具目录，进程句柄达到 66948，启动后累计 CPU 时间采样为 77.52 秒、working set 687 MiB；首页 Vite 请求处理 24719 ms，浏览器从请求到首字节约 37193 ms。主模块另等了约 10210 ms，证明 Vite ready 和原生 setup 快不能说明页面能及时返回。调整监听目录后，同工作区进程样本为 368 句柄、累计 CPU 2.13 秒、working set 83 MiB，首页处理降至 26.42 ms。

修复仅调整 Vite：前端监听排除 `src-tauri`、`.tools`、`.local`、发行/输出/缓存、用户数据/媒体/模型和 Playwright 生成目录；依赖扫描显式从 `index.html` 开始，不再默认发现整个工作区的 HTML。Rust 监听仍归 Tauri CLI。该监听边界也符合 [Tauri 的 Vite 配置说明](https://v2.tauri.app/start/frontend/vite/)，依赖扫描和请求处理依据本机安装的 Vite 6.4.4 实现；没有关闭系统安全软件或修改代理设置。

## 7 开发启动自动清理临时目录

按用户要求将清理放入 `scripts/run-dev.ps1`，所有已有开发入口共用 `Invoke-SvlDevelopmentCleanup`。只清理专用 tmp 和带有效 UUID 的启动依赖/WebView 测试缓存；不清整个 `.tools`、`.local` 或 `node_modules`，正常依赖缓存、词库与媒体保持。当前选择的数据目录与目标发生包含或相等关系时跳过，客户端仍运行也延后清理；重解析点拒绝递归处理，锁定文件清理失败不会中断启动，下次再试。

| Windows PowerShell 5.1 检查 | 实际结果 |
| --- | --- |
| CheckOnly | 可清理目录和文件保持，pnpm 调用 0 次 |
| 真实删除 | 合成工作区三个匹配目录实际删除；实际启动入口另删除一个本轮创建的临时 WebView 目录 |
| 数据与缓存 | 普通词库、自定义词库（位于匹配缓存目录内）、正常 Vite 缓存、工具资源、其他验证目录及非 UUID 名称均保留；哨兵内容不变 |
| 重解析点 | 合成 junction 被跳过，链接目标内容不变 |
| 占用与重试 | FileShare.None 锁定文件时清理延后，模拟 pnpm 仍被调用；释放锁后实际删除 |
| 启动集成 | 从带空格的其他当前目录调用真实 run-dev，清理后继续模拟 pnpm，PATH 和 SVL_DATA_DIR 恢复；未启动真实 GUI 或重编译程序 |

私有日志为 `.tools/development-cleanup-validation.log`。在测试夹具收尾时，自动审批拒绝了删除两个测试 junction 的动作，未给具体原因；含链接的夹具完整转存至 `.tools/development-cleanup-fixtures` 保留，没有删除链接。随后实际清理了空的 `.tools/tmp`，再次运行 CheckOnly 没有遗留清理警告；保留的验证夹具不进入自动清理范围。用户启动时由已接入的脚本执行正常目录清理；安全跳过的目录会给出提示。本轮为开发流程维护，保持 0.1.4，无新增安装包或原声/同步回归声明。
