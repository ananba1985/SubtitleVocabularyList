## 1 实现与环境

Windows 11、单屏 2560×1600、200% 缩放，实际 Tauri WebView2 与本地英语 Tesseract。按截图按钮或默认 `Ctrl+Alt+Shift+S`，先以 Windows GDI 保存本次桌面快照，再打开无边框选区窗口。拖选后按原始图像尺寸换算物理像素，裁剪并离线识别，成功结果进入现有收录确认窗口。

每次快照和窗口使用独立会话标识。矩形在核心再次检查，显示器配置变化时要求重新截图；取消、失败与完成均释放此次临时图像。截图准备任务完成只表示等待拖选，OCR 任务成功才表示文字识别成功，均不表示已收录。

## 2 实际结果

| 场景 | 结果与边界 |
| --- | --- |
| 200% 的窗口与快照对齐 | 最初出现窗口客户区高度多 56 个物理像素；使用原生客户区校正后，实测客户区为 2560×1600、原点 (0,0)，页面 1280×800、DPR=2 |
| WPF 英语文字拖选 | 实际拖选进入确认窗口，识别 `I was reluctant to ask for help.` 中的首字母为竖线；确认前可人工纠正 |
| 合并与语境 | 修正后收录 reluctant，合并到既有词条，形成 3 次主动收录、3 个来源例句；没有原声的截图来源不伪造音频 |
| 空白区域 | OCR 返回 empty_recognition，结果为空，不显示旧识别内容、不自动收录 |
| 无效与过小矩形 | 核心拒绝空矩形并保留当前会话；页面点击过小选区显示错误，可重新拖选或取消 |
| 重复采集 | 已有会话时返回 capture_busy，不并行替换快照 |
| 过期会话 | 返回 not_found，不取得后续会话图像、不生成新识别任务 |
| 引擎缺失 | 临时使用不存在的 Tesseract 路径，返回 provider_unavailable、结果为空；恢复后两个快捷键仍有效，词条与例句计数未改变 |
| 快捷键冲突 | 划词和截图配置为同一快捷键时拒绝，保留旧设置与注册结果 |
| 清理 | 完成与取消后未残留本轮 screen 快照；用户未确认的文字不会自动进入词库 |

WPF 测试窗口默认渲染曾造成 GDI 快照中文字空白。测试夹具明确使用软件渲染后可复现识别；这只处理夹具，不宣称所有硬件加速或受保护内容都能截图。

## 5 截图选区显示提速（0.8.8）

对应 FR-04／FR-15。用户反馈 Alt+E 识别和翻译正常，但选区窗口出现明显慢于 Pot。旧流程先用 `image::save` 对整张屏幕做默认 PNG 编码（Fast 压缩、Adaptive 逐行滤波），写入文件后才创建选区窗口；该窗口还没有像主窗口／查询窗口一样指定 Data 下的 WebView 目录。OCR 及模型查询发生在提交选区之后，不参与这段显示准备。

0.8.8 将短期全屏 PNG 改为 Uncompressed／NoFilter，原始像素与物理尺寸保持；提交选区后的裁剪 PNG 与 OCR 处理保持原流程。选区窗口明确使用相同资料库下的 `cache/webview`。临时全屏文件会较大，但只存于本次 jobs 目录并沿用提交／取消清理规则。

| 本机最小正常验证 | 实际结果与口径 |
| --- | --- |
| 旧版显示准备 | 0.8.7 的真实 `capture_ocr` 到准备完成约 3,231 ms；任务自身 createdAt 至 updatedAt 为 3,188 ms。任务完成发生在原生窗口 show／定位／聚焦之后，不代表已取得浏览器首帧时间 |
| 修改后原生显示准备 | 0.8.8 同一机器、同一隔离资料目录，任务 createdAt 至 updatedAt 为 517 ms；调用到新 WebView 出现约 489 ms |
| 修改后可操作选区 | 本次图像加载完成、工具栏出现“拖选英语文字，松开后识别”约 790 ms。实际图像 naturalWidth／naturalHeight 为 2560×1600，页面 1280×800、DPR=2，已查看工具栏截图 |
| 取消及资料保持 | 点击“取消截图”后，本次 screen 文件不存在、jobs 无 screen 残留；entryCount／sourceCount 均为 0，未操作日常资料库 |
| 编译及版本 | Windows desktop debug 编译与启动成功，真实 app_info 为 0.8.8／schema 9；统一版本及 diff 检查通过 |

测量通过实际 Tauri WebView 调用与 Alt+E 相同的 `ocr_start`，没有模拟 HTTP 或注入截图结果。旧版自动脚本最初未能从当前调试浏览器上下文发现另一个选区 WebView，不能将其等待超时当作程序弹窗耗时；旧版有效基线取自同一原生命令和真实任务完成回执。两项修改一起验证，不据此分别分配 PNG 编码和 WebView 初始化各自占用的毫秒数。

这是各一次正常路径观测，不是 Pot 对照基准、长期延迟保证或安装版性能结论。本轮未重测原已正常的 OCR／翻译内容、全部快捷键、其他缩放／多屏或故障场景，未生成安装包。原有隔离调试程序继续运行，资料目录仍为 `.local/query-stream-0.8.7/Data`；本次脚本、有效基线、验证输出及工具栏截图保留在 `.local/capture-latency-0.8.8`。
