本计划按文档、技术验证、核心闭环、能力集成和整体验收推进 0.1。阶段按依赖和完成证据排列，不承诺未经验证的日期或工时；同一人可承担需求、开发与验证工作。

## 1 当前状态

已经确定产品范围与主技术框架，已建立需求和设计文档。当前详细设计与接口是可评审提案；尚无桌面程序、数据库迁移、站点扩展或功能通过记录。

阶段顺序是实施组织方式，0.1 发布范围仍以 PRD 为准。先完成一个局部闭环不表示可以省略后续必需功能。

## 2 实施阶段

| 阶段 | 工作与交付 | 前置条件 | 完成依据 |
| --- | --- | --- | --- |
| M-01 文档与业务边界 | 核对需求、模型、流程、接口、测试；梳理未定规则 | 现有讨论与文档 | 文档无职责冲突，需求追溯完整；需原型才能关闭的事项保留状态 |
| M-02 技术原型 | 在已定框架中验证取词、截图 OCR、真实素材处理、本地解释及语音；核对第三方许可 | M-01；合法本地素材与资源 | 记录实际输出、取消和失败行为，形成支持矩阵与引擎选择依据 |
| M-03 核心收录闭环 | 建立数据迁移、核心命令、收录确认、追加去重、原声保存和浏览 | 模型与命令可实施；相关媒体路径可验证 | 新建、重复确认、新来源追加与重启后原声可用，数据边界测试通过 |
| M-04 剧集预习 | 集成导入、字幕或转写、时间核对、按词候选和本地解释 | M-02、M-03；OPEN-01 明确 | 用户可从剧集完成按词确认并收录原声 |
| M-05 Windows 日常采集 | 集成全局取词、选区与 OCR、确认窗口、系统语音及按需查询 | M-02、M-03；OPEN-02 明确 | 在支持应用与屏幕配置下，成功、取消和失败均不误收旧内容 |
| M-06 测验与专项 | 实现题目、维度、判分与修正、调度和易忘词规则 | M-03；OPEN-03 的规则明确 | 主动回忆有效，维度独立，模型不可用仍能练习，状态修正正确 |
| M-07 站点同步 | 对齐认证与字段，必要时扩展站点，完成增量、幂等和冲突 | M-03；OPEN-04 与 TECH-06 明确 | 真实账号双向同步及中断重试通过，本地功能不受服务失败影响 |
| M-08 整合与交付 | 执行整体验收，验证离线资源、安装与升级，形成使用和发布说明 | 各必需能力完成；性能目标明确 | 测试结果覆盖 PRD，交付物与说明一致，已知限制明确 |

阶段当前均未标记为开发完成。M-01 的文档已形成，文档检查及后续用户评审分别记录；其余阶段按实际工作更新进展。

## 4 决策依赖与推进方式

| 依赖 | 对实施的影响 | 可继续的独立工作 |
| --- | --- | --- |
| 取词与 OCR 支持边界未验证 | M-05 的默认实现与兼容承诺待定 | M-03 核心模型、收录与浏览可按明确契约推进 |
| 转写引擎与片段处理未验证 | M-04 的无字幕与时间校正能力待定 | 可用文本字幕流程和已保存音频管理可验证 |
| 复习与专项参数未确定 | M-06 不预设间隔和触发阈值 | 可实现题目快照、作答记录、维度与判分修正基础 |
| 站点认证与同步范围未确定 | M-07 的实际协议与验收内容待定 | 核心稳定标识、去重和契约模拟可推进 |
| 项目许可与第三方引入范围待核对 | 对 Pot 代码复制与依赖分发有影响 | 可继续文档与独立设计，避免先复制后补来源说明 |
| 性能目标缺少样本数据 | M-08 的性能判定待明确 | 先测记录，并验证后台操作和取消行为 |

已确认的框架不因原型困难自行变更。原型失败时定位适配或依赖问题，记录可用实现与成本；需要改变已确认决策时，再提出具体依据。

## 5 每个开发增量的完成要求

1. 确认增量对应的需求、设计和测试编号；需要的新规则标注来源与状态。
2. 实现最小完整业务流程，保存与返回结果一致，保留既有资料。
3. 执行与变更影响相称的规则、集成或实际桌面验证，记录证据边界。
4. 更新设计、支持矩阵、实际进展和已知限制，清理临时产物。
5. 检查差异，仅提交本增量文件并推送当前分支。

当前分支继续维护，除非用户另有要求，不额外建立分支或 PR。站点实施属于后续同步增量，不在本次文档编制中修改或部署外部项目。
