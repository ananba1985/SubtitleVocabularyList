## 1 环境与实现范围

本机为 Windows 11 IoT Enterprise LTSC，版本 10.0.26100。通过 Windows UI Automation TextPattern 取得当前选区和可取得的当前行语境；采集工作在线程中执行，读取前后核对前台窗口，成功后再显示主窗口。本实现不读取或改写剪贴板。

Windows 系统语音通过本机 SAPI 英语声音生成 WAV，再由桌面播放器播放。生成语音明确标记为系统语音，作为可重建的私有缓存，不加入原声资料表，不冒充影视对白。系统语音流程不使用大模型、FFmpeg 或外部语音服务；本轮 ffprobe 仅作为输出核对工具。

主窗口关闭行为为隐藏到托盘；托盘提供打开和退出。默认划词快捷键为 Ctrl+Alt+Shift+W，可修改或留空禁用。取词失败有明确提示；已有未提交草稿保留，新的采集结果可等原草稿关闭后确认。

## 2 实际证据

| 场景 | 动作与结果 | 覆盖边界 |
| --- | --- | --- |
| TC-07 | 用户在独立 WPF 测试窗口选中 reluctant，实际按下全局快捷键，并确认显示正确的单词和原句。后台记录成功，原句为自编英文，来源为测试窗口 | 真实跨进程取词通过；仅声明该 WPF 测试窗口和本机配置已验证，不据此宣称所有浏览器或阅读器兼容 |
| TC-11、TC-13 | 用户继续确认合并。词库保留剧集来源例句并追加划词来源，reluctant 主动收录计数变为 2，两个来源可同时浏览 | 实际统一收录与来源关联通过 |
| TC-08 | 成功取词后，在未提供可用 TextPattern 的前台应用再次调用采集；任务返回 unsupported、结果为空，没有新增收录 | 失败不复用旧结果通过；同一 WPF 控件的空选区及其他取消条件未全部实测 |
| TC-12、TC-16 | 核心测试重复收录同一采集位置，再修订原句；旧、新文本保留，主动收录计数增加，已知出现位置不因文本修订增加 | 核心规则通过；非影片采集只统计明确保存的已知位置，不推断窗口全文的词频 |
| TC-19 | 本机枚举出 Microsoft Zira Desktop 和 Microsoft David Desktop。使用 Zira 生成 115,986 字节、22,050 Hz、单声道 PCM WAV，时长 2.629025 秒；桌面按钮可实际加载，readyState=4，播放进度到达结尾，媒体错误为空 | 本机生成与播放器通过；人工听辨及物理断网条件未在本轮确认 |
| TC-19 补充 | 再次播放复用同一缓存，任务用时 10 ms，首次桌面准备 48 ms；播放中暂停，位置停在 0.161648 秒，后续观察未继续前进 | 缓存复用与实际播放器暂停通过；样本数仅本次输入 |
| TC-39 | 长文本系统语音任务接受取消并返回 cancelled，结果为空。另在独立 Windows 原生探针中，等待音频已开始生成后取消，SAPI 处理返回取消 | 排队与生成中取消均有实际证据；临时部分输出清理 |
| 资源失败 | 选择一个不存在的声音，语音任务返回 resource_missing、无播放路径；随后恢复原设置，词条与收录次数未变化 | 配置失效不产生虚假音频或学习结果 |
| 快捷键配置 | 本机 Ctrl+Alt+W 注册失败并显示占用；改为 Ctrl+Alt+Shift+W 后成功。错误格式更新返回 invalid_input，原配置与有效快捷键保留 | 实际占用和格式失败通过；不抢占其他应用快捷键 |

WPF 素材由 `scripts/probe-selection.ps1` 创建，仅含自编英文；它不打开用户文档。手动前台操作由用户完成，因为当前会话没有可用的 Windows 窗口控制工具。截图、音频、测试数据库与临时输出位于本机忽略目录，不进入公开仓库。

## 4 当前限制与后续验收

当前只采用 UI Automation，不提供剪贴板模拟复制回退。无法提供 TextPattern、权限不匹配或前台变化时返回失败，允许手动收录；后续增量已提供主动截图 OCR 入口，实际结果与支持边界见[OCR 记录](ocr-results.md)。具体浏览器、阅读器和不同权限窗口尚未形成已验证支持清单。

系统语音需要已安装 Windows 英语声音；配置失效可改选默认或已有声音。生成缓存与原声的类型和关联保持独立。语音不可用不会变成测验错误；复习模块仍待实施。

截图 OCR 的完整兼容矩阵、按需联网查询、托盘交互的完整验收、离线冷启动与安装升级，以及后续复习和真实站点同步仍未完成。本文不据部分 M-05 能力关闭完整 0.1。

## 6 Pot 替代范围与快捷键（0.4.4）

2026-10-11，FR-03、FR-04、FR-05、FR-08、NFR-03。用户确认软件将替代本机 Pot，要求沿用快捷键。本轮只读本机 Pot 配置的热键字段，实际为划词 Alt+C、截图翻译 Alt+E、输入翻译 Alt+D，截图纯识别键为空；这是该安装的配置，不宣称 Pot 所有安装都使用相同默认值。功能对照参考 [Pot 使用指南](https://pot-app.com/docs/) 和 [快捷键说明](https://pot-app.com/docs/config/hotkey.html)，同时核对当前源码。

| 基本能力 | 当前实现及替代边界 |
| --- | --- |
| 划词 | UI Automation 读取当前选区和可用原句，再进入统一确认；支持范围取决于原应用，不提供模拟复制回退 |
| 截图 OCR | 本地拖选、识别、纠错和确认，按 Alt+E 触发；没有另设纯 OCR 快捷键，因为本机 Pot 未启用该键 |
| 截图翻译 | 识别后可手动调用本地解释；尚不是截图后自动翻译的小窗流程 |
| 输入翻译／收录 | 新增 Alt+D，复用手动输入窗口，按需解释、朗读或保存；没有 Pot 的独立输入翻译窗和回车翻译习惯 |
| 语音 | Windows 英语 TTS 和剧集原声可用；没有 Pot 多个在线语音服务／插件兼容 |
| 查询与收藏 | 本地 Qwen 解释、持久化已生成资料、手动词典／翻译查询以及词条、例句、原声合并可用；没有完整离线词典或多服务并排查询 |
| 托盘 | 左键恢复、右键常用菜单和常驻／完全退出可用，0.4.2 用户确认结果见上节 |
| 剪贴板监听、增量翻译、外部调用／插件 | 未实现，仍是替代缺口；该核对不表示已经纳入本轮实现承诺 |

本轮三组快捷键均可自定义、禁用和保存，设置页提供“使用 Pot 快捷键”配置按钮。旧配置没有输入键时，旧工厂划词／截图值升级，其他自定义保持。输入键沿用托盘 collect 导航，不自动查询或收录；查询结果只有在用户确认保存后成为词条。

最小验证：pot_style_shortcuts_upgrade_and_survive_restart 为 1 passed、91 filtered，证明合成词库的旧默认值升级为三组新值、保存和重开保持。Windows 桌面 cargo check 和 pnpm exec tsc --noEmit 均通过。Pot 在本次检查时仍运行，未停止它，也未实测相同键的注册／触发；切换前应退出 Pot 释放快捷键。未额外运行冲突故障、兼容矩阵或完整回归，未生成安装包。

## 7 浏览器首次划词就绪修复（0.8.4）

对应 FR-03、TC-07。用户确认问题出现在 Chrome／Edge 网页。原取词实现只请求一次 UI Automation；浏览器按需启用辅助功能后，渲染器尚未发布 TextPattern 就被判为不支持。参见 [Chromium 官方说明](https://chromium.googlesource.com/chromium/src/+/main/docs/accessibility/overview.md#command-line-options) 及其关于跨进程树缓存可能稍迟于渲染器的说明。

本机 Chrome 155.0.8059.41，独立新配置目录、无强制辅助功能参数。自编 HTML 在加载后选中 reluctant；探针等待该测试页位于前台，再调用与快捷键相同的生产 `selected_text`，没有先用辅助工具读取页面树。证据保留于 `.local/selection-first-use-0.8.4`，不含用户网页或个人词库。

| 检查 | 实际结果 |
| --- | --- |
| 原实现复现 | 0.8.2 原生核心：首次返回与用户截图相同的 unsupported，约 63 ms；同一选区第二次成功，返回 reluctant 和完整自编原句，约 13 ms |
| 修复后最小正常流程 | 另启全新配置的 Chrome，只调用一次：成功返回相同单词、原句及 chrome.exe 来源，约 149 ms；不要求第二次调用 |
| 编译 | `cargo build --manifest-path src-tauri/Cargo.toml --example windows_probe --features desktop` 通过，实际验证链接该 Windows desktop 核心 |
| 版本与提交检查 | 统一版本检查与 `git diff --check` 通过，产品版本 0.8.4，schema 不变 |

修复仅在 chrome.exe／msedge.exe／chromium.exe 返回暂时缺少 TextPattern 或空选区时，在同一 COM 客户端内以 60 ms 间隔重新取得焦点元素与选区，就绪窗口 1,500 ms；已有前台窗口、元素归属、密码和长度检查保留。最终读取完成后才由原流程打开查询窗，不为中间尝试发布错误。

本轮是实际浏览器原生取词正常流程；Edge 使用相同处理分支，但没有扩大到多浏览器兼容矩阵、故障注入、压力或全量回归，也没有新增全局快捷键至查询窗口的人工验收。没有读写个人数据库或剪贴板，没有重启、替换正在运行的 0.8.2 安装版；本次交付源码，不生成新安装包。各次耗时只说明本次调用，不作为性能保证。
